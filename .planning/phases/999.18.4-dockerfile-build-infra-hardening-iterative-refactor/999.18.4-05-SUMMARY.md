# Plan 05 Summary — k8s declarative `grpc:` probe migration

**Status:** Complete

**Branch:** `gsd/phase-999.18.4-dockerfile-build-infra-hardening-iterative-refactor`

## What Was Done

Migrated 8 k8s probe blocks across 4 base manifests (`auth`, `sender`, `parser`, `audience`) from `exec.command:[/usr/local/bin/grpc_health_probe, -addr=:NNNN]` to k8s 1.27+ native declarative `grpc:{port:NNNN}`. Tuning fields (`initialDelaySeconds`, `periodSeconds`, `timeoutSeconds`) preserved verbatim per the pure-migration contract — no probe re-tuning. The in-image binary at `/usr/local/bin/grpc_health_probe` is RETAINED unchanged: docker-compose `healthcheck.test:` for the 5 gRPC services in `infra/docker-compose.yml` still invokes it (Plan 02/03/04 contract).

After this Plan, kubelet calls `grpc.health.v1.Health/Check` directly against PodIP:NNNN (no in-image binary invocation), while compose-side healthchecks continue to invoke the in-image binary. The two probe transports converge on the same server-side endpoint (`HealthImplementation` registers the `''` overall-server entry to SERVING in `packages/foundation/src/external/grpc/grpc-server.factory.ts`).

## Notable Deviations

### Tooling deviation (Rule 3 — auto-fix, documented)

Plan's Task 1 Probe (d) requested `kubectl --dry-run=client apply -k deploy/k8s/overlays/dev/`. In this environment, kubectl 1.35.4 hard-couples client-side dry-run to live API-server discovery (object-recognition step). The active kubeconfig context points at a stale minikube cluster (`https://192.168.49.2:8443`) unreachable from the dev workstation, so the command times out at the OpenAPI download step. `--validate=false` does NOT bypass this; `KUBECONFIG=/dev/null` falls back to `localhost:8080` also unreachable.

**Substitute applied:** `kubectl kustomize deploy/k8s/overlays/{dev,prod}/` — pure local kustomize render, no API contact, byte-equivalent to `kustomize build`. Output is the exact YAML stream `kubectl apply -k` would POST. All structural validation (kustomize parser + reassembler) preserved. The k8s-API field-name validation that `--dry-run=client` adds on top falls into Decision 3 (deferred end-to-end gate at first real `kubectl apply` on a live cluster).

This deviation does NOT relax any must_have — it just substitutes a strictly-equivalent local-render gate for the planning-time-documented form. Documented in DISCOVERY.md §Probe (d) and surfaced in checkpoint.
