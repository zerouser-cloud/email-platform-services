# Plan 02 Summary — gateway healthcheck busybox-as-wget

**Status:** Complete (commit `c5644b1`)
**Date:** 2026-05-05

## What Was Done

Closed the silent compose-unhealthy state for gateway by COPY'ing a statically-linked
`busybox:1.37.0-musl` binary into Stage 2 runner of `infra/docker/app.Dockerfile` and
renaming it to `/usr/local/bin/wget`. busybox is multi-call: under the name `wget` it
dispatches the wget applet via argv[0]. The gateway compose healthcheck stays
byte-identical (`test: ['CMD', 'wget', '-qO-', 'http://localhost:3000/health/ready']`)
— the fix makes wget WORK rather than rewriting the test.

## Empirical Verification

Before writing the plan: `docker build` test that copied `/bin/busybox` from
`busybox:1.37.0-musl` into a debian:12-slim test stage and invoked it as `wget`:

```
BusyBox v1.37.0 (2024-09-26) multi-call binary.
wget GET works
```

Glibc variant (`busybox:1.37.0-glibc`) was tried first and failed with
`/lib/x86_64-linux-gnu/libc.so.6: version 'GLIBC_2.38' not found` — debian-12
(the distroless runner base) ships an older glibc. Switched to musl (statically
linked, libc-independent). Documented in plan body and in Note seed.

After plan execution (in-container probe):

- `docker exec gateway wget -qO- http://localhost:3000/health/ready` →
  `{"status":"ok",...}` — empirical proof busybox-as-wget executes inside the
  running container, not just builds.
- `docker exec gateway ls /` → `ls: not found` — distroless preserved (we did
  NOT regress to a full Unix userland; only the `wget` argv[0] dispatch is
  reachable).
