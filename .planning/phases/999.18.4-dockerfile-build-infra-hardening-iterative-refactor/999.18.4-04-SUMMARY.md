# Plan 04 Summary — Digest pin grpc-health-probe + busybox

**Status:** Complete
**Date:** 2026-05-05
**Branch:** `gsd/phase-999.18.4-dockerfile-build-infra-hardening-iterative-refactor`

## What Was Done

Three deliverables in a single atomic commit:

1. **Two FROM directives in `infra/docker/app.Dockerfile` rewritten from `:tag` form to `@sha256:digest` form.**
   - Stage 1.0 health-probe: `FROM ghcr.io/grpc-ecosystem/grpc-health-probe:${GRPC_HEALTH_PROBE_VERSION} AS health-probe` → `FROM ghcr.io/grpc-ecosystem/grpc-health-probe@sha256:b615f8b80a6796490b91bfe0f7f4d59cf73767d4921968495cb8b4024090e151 AS health-probe`
   - Stage 1.0.5 busybox: `FROM busybox:1.37.0-musl AS busybox` → `FROM busybox@sha256:19b646668802469d968a05342a601e78da4322a414a7c09b1c9ee25165042138 AS busybox`
2. **`infra/docker/PINS.md` created** — audit-trail registry sibling to `infra/docker/daemon.json.example`. Records (image, tag-equivalent, digest, harvested-date, verified-by, mediaType, platforms) per pin. Documents harvest procedure and rotation policy.
3. **ARG cleanup applied per option (a) — `ARG GRPC_HEALTH_PROBE_VERSION=v0.4.48` line REMOVED** (Plan 03 set this; once the FROM uses `@sha256:` it's dead code). The tag-equivalent `v0.4.48` is preserved in PINS.md for human-readable cross-reference.

Closes the supply-chain attack vector that Plans 01 + 03 explicitly accepted via tag mutability. With `@sha256:<digest>` the registry-side bytes are content-addressable: any substitution would yield a different digest, and BuildKit would error with a manifest-mismatch error rather than building.
