<objective>
Replace fragile `apk add wget + GitHub-release download + sed-based arch mapping` delivery of `grpc_health_probe` in `infra/docker/app.Dockerfile` with a multi-arch-native `COPY --from=ghcr.io/grpc-ecosystem/grpc-health-probe:${GRPC_HEALTH_PROBE_VERSION}` directive sourced from a new dedicated stage and copied directly into Stage 2 runner.

Purpose: Eliminate transient build-time dependencies (`wget` install, GitHub release CDN reachability, arch-string normalization via `sed`) and align with project's stated multi-arch CI strategy (BuildKit auto-resolves the right arch via `$TARGETPLATFORM` against the upstream multi-arch manifest covering linux/amd64, linux/arm/v7, linux/arm64/v8, linux/ppc64le, linux/s390x). Server-side `grpc.health.v1.Health` registration (via `grpc-health-check` npm package, see `packages/foundation/src/external/grpc/grpc-server.factory.ts`) is unaffected — this is purely a binary-delivery transport change.

Output:

- `infra/docker/app.Dockerfile` rewritten with a new `health-probe` stage and a direct runner-stage copy.
- `.planning/ROADMAP.md` Phase 999.18.4 entry finalized (Goal + 3-plan list).

Scope discipline: Tag pin stays at `v0.4.24` (current value). Bump to `v0.4.48` is Plan 02. Digest pin is Plan 03. This Plan delivers ONLY the transport switch — minimal change-set, atomic commit.
</objective>
