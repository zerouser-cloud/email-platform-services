<objective>
Restore a working gateway compose healthcheck by adding a real `wget` binary to the distroless Stage 2 runner image. The current `infra/docker-compose.yml` gateway healthcheck reads `test: ['CMD', 'wget', '-qO-', 'http://localhost:3000/health/ready']`, but the Phase 999.18.3 distroless migration removed all userland binaries — `gcr.io/distroless/nodejs22-debian12:nonroot` ships no shell, no curl, and no wget — so this healthcheck has been silently failing and Docker engine marks the gateway container `unhealthy` after `retries: 5` even though the application itself is fully functional. This Plan adds ONE new dedicated stage that pulls `busybox:1.37.0-musl` and ONE COPY line in Stage 2 runner that extracts `/bin/busybox` as `/usr/local/bin/wget`. Busybox is a multi-call binary: when invoked under the name `wget`, it dispatches the wget applet via `argv[0]`. The compose healthcheck `test:` line is preserved VERBATIM — the fix makes wget WORK rather than rewriting the test contract.

Purpose: Close the silent compose-unhealthy state surfaced during Plan 01 smoke. Restore an empirically-verifiable healthy gateway contract for the local isolated-mode stack so subsequent plans (version bump in Plan 03, digest pin in Plan 04, k8s declarative probes in Plan 05, base-stage extraction in Plan 06) start from a clean smoke baseline. The fix is minimal and architecturally explicit: a deliberate, scoped, audited point compromise on distroless minimalism. Busybox is a single statically-linked ~1MB binary with no shell, no package manager, no setuid bits — adding it as a renamed `wget` restores expected `wget` behaviour with no shell surface and no extra layer beyond the COPY.

Output:

- `infra/docker/app.Dockerfile` — one new stage block (`FROM busybox:1.37.0-musl AS busybox` plus an explanatory comment block) and one new COPY line in Stage 2 runner. All Plan 01 artifacts (Stage 1.0 health-probe, Stage 2 grpc_health_probe COPY) preserved verbatim. All other stages (pruner, prod-deps, builder, runner ENTRYPOINT/USER/CMD) preserved verbatim.

Scope discipline: ONLY `infra/docker/app.Dockerfile` is modified by this Plan. The compose file is NOT touched (`infra/docker-compose.yml` gateway `test:` line preserved verbatim — this Plan makes the existing wget call work, not rewrites it). The 5 gRPC services keep their `grpc_health_probe` healthchecks (correct after Plan 01). The infra services (postgres/redis/rabbitmq/garage in `docker-compose.infra.yml`) are untouched. `apps/*` and `packages/*` source untouched. `deploy/k8s/base/*.yaml` untouched (k8s probes are independent — Plan 05 will replace them with declarative `grpc:`). - Image `busybox:1.37.0-musl` (Docker Hub Official Image, statically-linked musl variant) ships `/bin/busybox` as the multi-call binary. Tested: docker build with `FROM busybox:1.37.0-musl AS bb` + `COPY --from=bb /bin/busybox /usr/local/bin/wget` into a debian:12-slim test stage; invocation of `/usr/local/bin/wget` produced "BusyBox v1.37.0 multi-call binary" preamble and applet selection by argv[0]; invocation `/usr/local/bin/wget -qO- http://example.com` exited 0 with the example.com HTML body.
- The glibc variant `busybox:1.37.0-glibc` requires `GLIBC_2.38`, which is newer than the glibc shipped by the debian-12 base of `gcr.io/distroless/nodejs22-debian12:nonroot`. Attempting to use the glibc variant would produce a runtime linker error inside the distroless runner. The musl variant is statically linked and runs anywhere.
- Distroless image `gcr.io/distroless/nodejs22-debian12:nonroot` writes USER=65532:65532; busybox-as-wget at `/usr/local/bin/wget` is owned by root:root with mode 0755 by default after COPY — readable+executable by USER 65532, no setuid bits, no privilege escalation surface.
- Docker engine healthcheck `test: ['CMD', 'wget', ...]` resolves `wget` against the container's PATH (which on distroless includes `/usr/local/bin`); the file at `/usr/local/bin/wget` is exec'd directly via spawn, not via shell. busybox sees argv[0]=`/usr/local/bin/wget` (or `wget` depending on resolution), and dispatches the wget applet.
- Compose file `infra/docker-compose.yml` (lines 27-32) currently reads:

Host-side port mappings:

- Isolated mode: `'4000:3000'` — host-side curl uses `:4000`.

Why busybox (and not the previously-rejected `node -e fetch(...)` alternative): user explicitly preferred a real `wget` binary delivered via a deliberate COPY over a multi-line JavaScript expression embedded as a YAML inline string in the compose file. Busybox is a single ~1MB statically-linked binary, audited and well-known; the COPY is one line in the Dockerfile, the wget invocation in compose stays a textbook `wget -qO- URL` call. No magic JavaScript-in-YAML.

Why busybox (and not a rebase of the runner away from distroless): undoing distroless would expand the runtime attack surface across all 6 services for the sake of one tool. The point compromise — adding ONE binary — is much smaller than the full base-image swap.

Why pin `1.37.0-musl` (and not `latest` or unversioned `:musl`): mutable tags are reproducibility hazards. `1.37.0` is the current upstream release. The `-musl` suffix selects the statically-linked variant. Plan 04 will generalize digest pinning across all base images at which point this pin can be tightened to `busybox@sha256:…` alongside the grpc-health-probe digest pin.
