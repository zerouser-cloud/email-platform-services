## What Was Done

Extracted a new `base` stage from `infra/docker/app.Dockerfile` that consolidates the four directives previously duplicated across the `prod-deps` (lines 56-59 at HEAD) and `builder` (lines 70-73 at HEAD) stages: `WORKDIR /app`, `ENV PNPM_HOME="/pnpm"`, `ENV PATH="$PNPM_HOME:$PATH"`, `RUN corepack enable`. After the refactor:

```
FROM node:${NODE_VERSION} AS base
WORKDIR /app
ENV PNPM_HOME="/pnpm"
ENV PATH="$PNPM_HOME:$PATH"
RUN corepack enable

FROM base AS prod-deps
COPY --from=pruner /app/out/json/ ./
RUN --mount=type=cache,id=pnpm-store,target=/pnpm/store \
    pnpm install --prod --frozen-lockfile

FROM base AS builder
COPY --from=pruner /app/out/json/ ./
...
```

The 8 inlined directive instances (4 directives × 2 stages) at HEAD become 4 directive instances in `base` plus 0 in prod-deps + 0 in builder = 4 instances. Net diff: +15/-8 (15 added, 8 removed; new base stage with header + 4 directives + 7 comment lines minus the 8 removed directive lines plus 2 new "Inherits …" comments). Pruner stage byte-identical. Runner stage byte-identical. Plan 04 digest pins for both health-probe and busybox preserved verbatim. Stage 2 COPY directives (Plans 01/02 invariants) byte-identical.

**Layer-equivalence PROVEN:** post-refactor `prod-deps`, `builder`, AND `runner` final-stage layer SHA256s are bytewise-identical to pre-refactor baselines. BuildKit's content-addressable cache produces the same SHA256 because the directive sequence executed inside each downstream stage is identical to before — only its origin differs (now inherited from `base` instead of inlined). Pure DRY rewrite, zero behavioral drift, zero observable change at the image-layer level.
