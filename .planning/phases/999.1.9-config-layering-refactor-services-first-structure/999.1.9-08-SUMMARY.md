# Phase 999.1.9 Plan 08: Notifier Service Migration (final per-service wave — D-21 fan-out complete + last Pitfall 2 escape hatch removed) — Summary

**Status:** COMPLETE. Task 1 committed (`74919fc`). **Final per-service migration** in the Phase 999.1.9 strangler-fig rollout. Closes the SIXTH and LAST `createConfigModule<...>()` generic form callsite, completes the D-21 external-APIs fan-out (3/3), and demonstrates pattern universality across all six services. W9 cleanup is now unblocked.

## Goal

Migrate the `notifier` service end-to-end to the Phase 999.1.9 per-app config structure. Final of six per-service waves. W8 specifically validates:

1. **0-peer + external-apis + no-DB shape** — notifier is a terminal event consumer (inbound RMQ + gRPC server); no upstream gRPC clients → no peer topologies; no database → no PERSISTENCE_CONFIG_PORT. Infra blocks: Rabbit + Storage + Logging + Grpc + per-svc Telegram.
2. **W6-seeded topology stub verification** — `NotifierTopologyShape` was seeded in W6 (for parser's peer-spread need) already in the full 3-key target form. W8 verifies and proceeds without overwrite (mirror of W6 verifying the W3-seeded `ParserTopologyShape` stub).
3. **D-21 third and final application** — `TelegramSchema` relocated to `apps/notifier/external-apis.schema.ts`; pruning the Telegram re-export from `./schemas/index.ts` root barrel completes the D-21 fan-out. Legacy shared file `packages/config/src/schemas/external-apis.ts` now has ZERO root-barrel consumers and is safe to remove in W9.
4. **Last Pitfall 2 escape hatch closure** — `notifier-config.module.ts` switches from legacy 2-generic `createConfigModule<typeof NotifierEnvSchema, NotifierEnv>({...})` to target single-generic `createConfigModule({...})` form. **After W8, the default-valued `TEnv` generic on `createConfigModule` is unused everywhere** — safe to remove entirely in W9.
5. **D-12 invariant 6/6** — all six `apps/*/src/main.ts` now use the `app.get<XxxEnv>(XXX_CONFIG)` DI retrieval pattern. Uniform bootstrap shape across the whole platform.
6. **Telegram consumer type swap** — external consumer `telegram.module.ts` imports `NotifierEnv` from `@email-platform/config`, not the local bootstrap re-export. Third and final application of Pattern 14.

Reduces the set of legacy 2-generic `createConfigModule` call sites from 1 → 0. Closes the Phase 999.1.9 W3-W8 per-service rollout.
