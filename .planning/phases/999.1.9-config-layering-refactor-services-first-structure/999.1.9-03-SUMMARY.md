### New files (`packages/config/src/`)

- **`service.ts`** — canonical Identity layer. Exports `defineService` (new, simplified: no `.port`/`.displayName`/`.envKeys` per D-17), `GrpcServiceIdentity`, `ServiceIdentity`. 2 overloads — grpc input → GrpcServiceIdentity return; no grpc → ServiceIdentity.
- **`apps/audience/identity.config.ts`** — `AUDIENCE = defineService({ id: 'audience', grpc: { serviceName: 'AudienceService' } })`. Imports `defineService` via deep relative path to sidestep legacy re-export collision.
- **`apps/audience/topology.schema.ts`** — `AudienceTopologyShape = { AUDIENCE_PORT, AUDIENCE_GRPC_PORT, AUDIENCE_GRPC_URL }` (terminal leaf per RESEARCH §Pitfall 1).
- **`apps/audience/env.schema.ts`** — native `z.object({ ...AudienceTopologyShape, ...ParserTopologyShape, ...DatabaseSchema.shape, ...RabbitSchema.shape, ...LoggingSchema.shape, ...GrpcSchema.shape })`. `type AudienceEnv = z.infer<typeof AudienceEnvSchema>` (D-08: no intersection alias).
- **`apps/parser/topology.schema.ts`** — minimal stub (audience's peer spread dep). Final shape; W6 parser plan adopts it verbatim.

### Foundation factories

- **`create-config-module.ts` (D-10)** — primary call pattern is single-generic `createConfigModule<typeof XxxEnvSchema>({...})`. A default-valued second generic `TEnv = z.infer<TSchema>` is retained as a Pitfall 2 escape hatch for Zod 4 on `composeSchemas`-produced `ZodObject<MergeShapes<T>>` — see Deviations below.
- **`grpc-server.factory.ts` (D-16)** — new 3-arg signature `createGrpcServerOptions(service: GrpcServiceIdentity, grpcPort: number, protoDir: string)`. No longer reads `service.grpc.port` (unblocks D-17 dead-field removal in W9).
- **`define-grpc-client.ts` (D-17 envKeys removal)** — 3 surgical edits: (1) `GrpcServiceDeclaration` → `GrpcServiceIdentity` import, (2) same on `readonly service` field, (3) env-var lookup derived literally from `${opts.service.id.toUpperCase()}_GRPC_URL` (replaces `opts.service.envKeys.GRPC_URL`). Runtime-identical — same string keys, same URL resolution.

### Apps

- **`apps/audience/src/main.ts`** (full D-12 migration):
  ```ts
  const app = await NestFactory.create(AudienceModule, { bufferLogs: true });
  const config = app.get<AudienceEnv>(AUDIENCE_CONFIG);
  // ...
  app.connectMicroservice(
    createGrpcServerOptions(SERVICE.audience, config.AUDIENCE_GRPC_PORT, config.PROTO_DIR),
  );
  await app.listen(config.AUDIENCE_PORT, SERVER.DEFAULT_HOST);
  ```
- **`apps/audience/.../audience-env.schema.ts` DELETED.** Schema now in `@email-platform/config/apps/audience/env.schema`.
- **`apps/audience/.../audience-config.module.ts`** — imports `AudienceEnvSchema` from `@email-platform/config`; uses target single-generic form `createConfigModule({ ... })` (no generic args). Proves D-10 works for native z.object target state.
- **4 legacy `main.ts` (auth/sender/parser/notifier)** — surgical 3-arg update: `createGrpcServerOptions(SERVICE.{svc}, SERVICE.{svc}.grpc.port, config.PROTO_DIR)`. Envs untouched (env schemas remain in apps/ until respective W4-W8 plans).
- **5 legacy config modules** — retain legacy 2-generic form `<typeof XEnvSchema, XEnv>` as Pitfall 2 escape hatch (explicitly documented in each module). Each is scheduled for single-generic migration in the service's W4-W8 plan.

## Deviations from Plan

### [Rule 3 — blocking issue] Retain default `TEnv = z.infer<TSchema>` generic in `createConfigModule`

- **Found during:** Task 1 build — 5/5 legacy config modules (`auth/sender/parser/gateway/notifier`) fail TypeScript check after dropping the second generic. Zod 4's `z.ZodType<...>` output-only wide type interacts poorly with `composeSchemas`-produced `ZodObject<MergeShapes<T>>` across the generic boundary: `z.infer<TSchema>` resolves to `unknown` inside the interface, making all `slice: (c) => ({...})` callbacks receive `c: unknown`.
- **Fix:** reverted interface + function signature to carry a default-valued `TEnv = z.infer<TSchema>` parameter. Primary call pattern documented as single-generic `createConfigModule<typeof XSchema>({...})` (audience uses this successfully — proves D-10 works for the native z.object target state). 5 legacy modules retain the explicit 2-generic call site (`<typeof XSchema, XEnv>`) documented as Pitfall 2 escape hatch in each module. Scheduled for removal in W9 cleanup once all 5 migrate to native z.object spread in W4-W8.
- **Files modified:** `packages/foundation/src/external/config/create-config-module.ts` (interface + function), `apps/{auth,sender,parser,gateway,notifier}/src/infrastructure/bootstrap/config/*-config.module.ts` (5 legacy modules keep 2-generic form; documented inline).
- **Risk:** None runtime (TS-only surface). The 5 legacy modules behave identically. The plan's target state (single-generic for native z.object schemas) is already achieved for audience. Pattern for W4-W8 proven.
- **Commit:** `65128e1`.

### [Rule 3 — follow-up observation] `promisify-grpc-client.ts` reformatting

- A 3-line Prettier formatting change on `promisify-grpc-client.ts` existed in the worktree at start (pre-existing uncommitted state). Included in the commit since it's part of the foundation touch surface for this plan; benign, no functional impact.
