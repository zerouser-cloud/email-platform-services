# Phase 999.1.9 Plan 07: Gateway Service Migration (HTTP-only + 5-peer explosion + refine preservation) — Summary

**Status:** COMPLETE. Task 1 committed (`147db59`). Extends the W3 / W4 / W5 / W6 pattern to gateway's shape — the **HTTP-only REST facade** with the **maximum peer fan-out (5)** and a **cross-field `.refine()` security rule** that must be preserved verbatim. Fifth proof point and the most exotic variant, demonstrating the pattern generalizes to all shape flavors in the 6-service platform.

## Goal

Migrate the `gateway` service end-to-end to the Phase 999.1.9 per-app config structure. W7 specifically validates:

1. **HTTP-only bootstrap** — `defineService({ id: 'gateway' })` without `grpc` input (returns plain `ServiceIdentity`); main.ts has NO `createGrpcServerOptions` / `connectMicroservice` / `startAllMicroservices` calls (gateway never exposes a gRPC server).
2. **Maximum peer fan-out (5)** — gateway env.schema must spread ALL 5 peer topologies: Auth, Sender, Parser, Audience, Notifier (RESEARCH §Pitfall 4 peer-explosion checklist).
3. **`.refine()` preservation** — the legacy cross-field validation `CORS_STRICT + CORS_ORIGINS='*'` rejection MUST survive the spread-composition rewrite (RESEARCH Assumption A8, T-999.1.9-17 mitigation).
4. **Target single-generic factory form** — `createConfigModule({...})` collapses cleanly through a `.refine(...)`-wrapped schema via `z.infer`, removing the fifth legacy Pitfall 2 escape hatch.
5. **Throttle consumer type swap** — external consumer `throttle.module.ts` imports `GatewayEnv` from `@email-platform/config`, not the local bootstrap re-export.

Reduces the set of legacy 2-generic `createConfigModule` call sites from 2 → 1 (only notifier remains on the Pitfall 2 escape hatch, to be closed in W8).
