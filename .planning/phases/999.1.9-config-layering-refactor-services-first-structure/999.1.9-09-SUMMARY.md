## Decisions Made

1. **SERVICE aggregator in service.ts (not a separate layer).** Plan 09 authorized adding `SERVICE` to `packages/config/src/service.ts` directly rather than a new `aggregator.ts` or `catalog.ts` file. This keeps identity concerns colocated with `defineService` and identity interfaces, matching W1 file layout. Rationale: the aggregator is mechanical (6 imports + object literal) and doesn't warrant its own file.

2. **Docstring cleanup in foundation (Rule 2 — correctness hygiene).** Found 3 foundation source files with docstrings referencing now-deleted symbols (`composeSchemas`, legacy `SERVICE.{svc}.envKeys.GRPC_URL`, "W3 coexistence"). Plan 09 did not explicitly call these out, but leaving them creates future confusion (readers would grep for non-existent symbols). Updated inline as part of same task commit. Files touched: `load-config.ts`, `grpc-server.factory.ts`, `grpc-client.interfaces.ts`. No semantic changes, documentation only.

3. **Turbo cache artifact-replay quirk handled via direct package-level builds.** `turbo run build --force` restores `dist/**` outputs from cache even when `--force` bypasses cache for execution decisions. This produced stale `dist/infrastructure/config/*-env.schema.d.ts` artifacts referencing deleted types after the first `pnpm build`. Resolved by running `pnpm --filter @email-platform/<svc> build` directly for each package (bypassing turbo), which cleanly regenerates `dist/` from current source. Post-direct-build, all 10 decision-level grep invariants return 0. No production impact (dist is in `.gitignore`, ephemeral).
