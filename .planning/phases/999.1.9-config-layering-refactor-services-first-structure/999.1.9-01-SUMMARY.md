## Decisions Made

- **Root barrel НЕ экспортирует `./infra` в W1** — в плане Task 2 `<action>` анализ зафиксировал: и `./schemas/index.ts`, и `./infra/index.ts` экспортируют `DatabaseSchema` (identical binding, разные source files). TS даст ошибку `Module has already exported a member`. Решение — отложить `export * from './infra'` до W9 cleanup (когда `./schemas` удаляется). До W9 per-service `env.schema.ts` будут импортить из `../../infra/{name}.schema` через **relative paths** (root barrel не участвует).
- **external-apis НЕ в infra/index.ts** — per D-21 это per-app split: TelegramSchema→notifier, AppStoreSpySchema→parser, CloudFnSchema→sender. В W5/W6/W8 эти схемы будут жить в `apps/{name}/external-apis.schema.ts`.
- **Byte-identical copy, не git mv** — D-23 migration strategy требует coexistence старых schemas/ файлов до W9. `git mv` удалил бы оригинал. Копия через Write сохраняет оба.
- **`export {}` в stub barrels** — TS валидный empty module pattern. Без него TS warning «file is not a module».
