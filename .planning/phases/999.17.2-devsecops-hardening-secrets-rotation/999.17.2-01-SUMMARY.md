## Decisions Made

- **D-06 `regexTarget = "secret"` (deviation from PLAN spec `"match"`)** — empirical verification on gitleaks v8.30.1 showed Match field contains the entire capture including surrounding `"<key>": "..."` prefix, so anchored regex `^[a-f0-9]{64}$` against Match never satisfies (regex requires exact 64-hex run from start to end of string). Targeting Secret (the extracted bare hex group) makes the anchored regex match correctly. RESEARCH.md §A5 explicitly authorized this fallback: "if hashes still fire, swap to secret". In-file `description` field documents the choice. (Rule 1 auto-fix — see Deviations.)
- **OQ-5 fingerprints kept BOTH commits despite empirical 1-fire reality** — gitleaks v8.30.1 deduplicates by introducing-commit, so only `c638e69` actually fires (the "set real Telegram bot token" commit). `382fc1f` is the preceding placeholder-introduction commit. Both fingerprints retained per PLAN `must_haves.truths` "TWO new FULL-form fingerprint entries" — second is defensive future-proofing, harmless if it never fires.
- **OQ-5 line number `:52` empirically confirmed** — JSON report (`docker run gitleaks ... --report-format json`) reports `StartLine: 52` for `c638e69` finding. Same value used defensively for `382fc1f` fingerprint (would only matter if scan logic re-detect heuristics ever change).
- **CLAUDE.md insertion inside GSD wrapper** — preserves GSD-managed regeneration semantics. Section placed between `## Module Design` and `## Architecture Constraints` as PLAN spec dictated, ordered correctly per `grep -n "^## " CLAUDE.md` (lines 235 / 250 / 260).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] D-06 `regexTarget` value swapped from `"match"` to `"secret"`**

- **Found during:** Task 2 (post-edit verification — manifest findings still fired despite allowlist applied).
- **Issue:** PLAN spec mandated `regexTarget = "match"` per RESEARCH.md draft. Empirical scan after applying showed manifest's 2 findings (`generic-api-key` line 30, `discord-api-token` line 157) STILL fired. JSON report inspection revealed gitleaks v8.30.1 builds `Match` field with surrounding key-name and quote prefix (`"secrets.cjs": "201d72d9...02"`), so anchored `^[a-f0-9]{64}$` against `Match` never satisfies. The `Secret` field, by contrast, contains only the bare 64-char hex.
- **Fix:** Changed `regexTarget = "match"` → `regexTarget = "secret"` in D-06 [[allowlists]] block. Re-ran scan: findings dropped 23 → 21 (manifest's 2 entries now correctly suppressed). Updated D-06 `description` field with verification note and citation to RESEARCH.md A5 fallback authorization.
- **Files modified:** `.gitleaks.toml` (single key change in D-06 block).
- **Verification:** `pnpm security:secrets-full` post-fix shows 0 findings under `.claude/gsd-file-manifest.json`; `python3` JSON-report inspection confirms manifest entries no longer present.
- **Committed in:** `5ad5d8c` (Task 2 commit — fix landed in same atomic commit as the original D-06 implementation, since the verification step caught the issue before the commit was authored).

**2. [Rule 1 — Bug] OQ-5 second fingerprint (`382fc1f`) does not empirically fire on current scan**

- **Found during:** Task 4 (empirical line lookup STEP 1).
- **Issue:** PLAN spec STEP 1 expected grep output to return 2 lines (one per commit `c638e69` / `382fc1f`). Empirical execution returned ONLY 1 line (commit `c638e69`). Investigation: gitleaks deduplicates findings by introducing-commit, so the first commit where the secret appears is the only one reported. Inspection of `git show 382fc1f -- .env.docker` revealed `382fc1f` is the preceding placeholder commit (`TELEGRAM_BOT_TOKEN=replace-me-telegram-bot-token`) — placeholder, not a real leak; gitleaks correctly does not flag it.
- **Fix:** Both fingerprints retained per PLAN `must_haves.truths` "TWO new FULL-form fingerprint entries" (PLAN considers both authoritatively required regardless of empirical fire status). Defensive: if scan logic / re-detect heuristics ever change, the second fingerprint provides forward coverage; harmless if it never fires. Comment block annotated to acknowledge the empirical reality without contradicting the spec.
- **Files modified:** `.gitleaksignore` (both fingerprints + clarifying comment block).
- **Verification:** `grep -E '^c638e69e... | ^382fc1f...'` both return 1 line each (PASS). Negative grep `[0-9]{8,}:[A-Za-z0-9_-]{30,}` returns 0 (no real Telegram-format literal in suppression file).
