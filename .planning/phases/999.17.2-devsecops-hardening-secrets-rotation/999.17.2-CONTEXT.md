## Implementation Decisions

### Принцип защиты (foundational)

- **D-01:** **Один стандарт для всего что в git.** Никаких path-allowlist для user-content. Если AI agent пишет real-looking secret в любой путь (`.planning/research/`, `apps/*/src/`, `infra/`, comments) — gate должен это ловить. Path-based exception ломает defense-in-depth (pre-commit → pre-push → CI каждый layer полагается на uniform coverage).
- **D-02:** **Защита через формат, не через путь.** Examples секретов в planning/research/SUMMARY/comments должны быть в redacted/synthetic format который default rules не matches. Если scanner ловит example — это сигнал что example в real-looking format → fix the content, не the rule.
- **D-13:** **Custom rules не нужны.** Default gitleaks rules ловят all real findings (telegram-bot-api-token, generic-api-key, aws-access-token, private-key и т.д.). Real-format postgres connection strings в production code мы не имеем; если AI напишет — он напишет в redacted format per D-02. Если когда-то real-format URL проскочит default rules — отдельный follow-up phase, не сейчас.

### AM-01 — `.gitleaksignore` syntax fix

- **D-03:** Удалить line 33 `scripts/security/fixtures/**` из `.gitleaksignore` (invalid syntax — `.gitleaksignore` принимает ТОЛЬКО fingerprints `commitSHA:path:rule:line`, не glob path patterns; gitleaks emits `WRN Invalid .gitleaksignore entry` каждый run). Path-allowlist для fixtures переезжает в D-05.

### AM-02 — `secrets-full.sh` `dir` → `git`

- **D-04:** Изменить `scripts/security/secrets-full.sh` line 17: `gitleaks dir /repo --no-banner` → `gitleaks git /repo --no-banner`. Pre-push должен verify что push'ится (= tracked content via git protocol), не сканировать filesystem (untracked `.pnpm-store/`, `.claude/worktrees/` = 111 false-positives). Inline комментарий с обоснованием в скрипте.

### Path-allowlists (только два, обоснованные)

- **D-05:** **Test infrastructure exception.** В `.gitleaks.toml [[allowlists]]`:
  ```toml
  [[allowlists]]
  description = "Test fixtures (security gate self-tests) — synthetic triggering-format secrets used to prove scanner detection. Industry-standard exception for security tooling test infrastructure (cf. semgrep test framework, trivy testdata, gitleaks own tests/)."
  paths = ['''^scripts/security/fixtures/''']
  ```
  Anchored regex (`^`). Carries-over rationale из 999.17.1 D-07 (where pattern was attempted via wrong file). Single well-known path, no other path-allowlists.

- **D-06:** **`gsd-file-manifest.json` shape-based allowlist** (не path carve-out, per research). В `.gitleaks.toml [[allowlists]]`:
  ```toml
  [[allowlists]]
  description = "GSD framework integrity manifest (~280 SHA-256 file hashes). Suppresses ONLY findings where match shape is bare 64-char lowercase hex inside this exact file. Real AWS key, JWT, or PEM block in same file still fires (default rules unaffected)."
  condition = "AND"
  paths = ['''^\.claude/gsd-file-manifest\.json$''']
  regexes = ['''^[a-f0-9]{64}$''']
  regexTarget = "match"
  ```
  Idiomatic gitleaks v8 pattern (canonical example in gitleaks README для `package-lock.json`). Discriminates по форме _что найдено_, не _где_. Соответствует principle D-01.

### Content cleanup standard (D-07/D-08)

- **D-07:** **Redacted-format standard для examples** (используется в `.planning/**`, code comments, SUMMARY files). Формат **не должен matchить default rules**:
  - Connection strings: `postgres://user:<redacted>@host:5432/db`, `redis://default:<redacted>@host:6379/0`, `mongodb://user:<redacted>@host:27017/db`, `amqp://<redacted>@host:5672`
  - Cloud keys: `<aws-access-key-redacted>` или `AKIA<redacted-suffix>` (избегать `AKIA[A-Z0-9]{16}` real-format match)
  - Tokens: `<api-token-redacted>`, `<github-token-redacted>`, `<slack-token-redacted>`, `<digits>:<redacted-bot-token>` (телеграм-формат `\d+:[A-Za-z0-9_-]+` не должен matchить)
  - Generic: `<rpc-secret-redacted>`, `<32-byte-hex-redacted>`, `<password-redacted>`
  - Private keys: всегда `<private-key-redacted>`; никогда не вставлять `-----BEGIN ... PRIVATE KEY-----` блоки даже как examples

  - `.planning/phases/999.10.1-hexagonal-naming-convention-refactor/999.10.1-03-SUMMARY.md` (2)

### CLAUDE.md update — AI rule (D-09)

- **D-09:** **Project rule for AI agents** в `CLAUDE.md` (новая section "Examples & Secrets Hygiene" под "Conventions" или "Code Style"):
  > **Examples содержащие секреты должны быть в redacted format.** При writing example credentials/tokens/keys в code comments, planning docs, research notes, SUMMARY files — использовать non-triggering format per D-07 standard. Real-looking format = automatic gate fail (pre-commit / pre-push / CI). ### `infra/docker/garage.toml` — 12-Factor envsubst template (D-10)

- **D-10:** **NO `.gitignore` для config-файлов с secrets — pattern через envsubst, не tracked-template-+-.gitignored-real.** Принцип: real secret должен жить только в env vars (k8s Secret, `.env.docker`). `.gitignore` для config-файла = anti-pattern (скрывает дыру; real value всё ещё на хосте, просто не tracked в git — false sense of security, и secret оседает в Docker layer cache / docker-compose ephemeral state). 12-Factor: separation of config from code, config через env vars.

  Действия:
  1. `git mv infra/docker/garage.toml infra/docker/garage.toml.template`
  2. В `.template` заменить real `rpc_secret` на envsubst placeholder: `rpc_secret = "${GARAGE_RPC_SECRET}"` (Garage не имеет native env-var override, требует preprocessing — verify в plan-phase research)
  3. **NO `.gitignore` entry** для `infra/docker/garage.toml` — оригинальный файл не должен создаваться на хосте вообще
  4. Container startup mechanism: `entrypoint.sh` (либо в `infra/docker/storage-bootstrap.sh`, либо новый script, либо docker-compose `command:`) делает `envsubst < /etc/garage.toml.template > /etc/garage.toml && exec garage server -c /etc/garage.toml`. Substituted file = ephemeral в container, не на host.
  5. Real `GARAGE_RPC_SECRET` value поступает через:
     - **Local dev:** `.env.docker` (already в `.gitignore` — это env-injection mechanism, OK по D-01 carve-out)
     - **Production:** k8s Secret mounted as env var (DevOps configures)
  6. Missing env var → envsubst → empty string → Garage fails to parse config → container fails fast (12-Factor compliant fail-closed; opposite of silent fall-back)
  7. Plan-phase research: (a) поддерживает ли Garage native env override (вероятно нет, но проверить), (b) есть ли existing envsubst pattern в `infra/docker/` other services (reuse если есть), (c) docker-compose mechanism для substitution.
  Plan-phase finalize exact ordering + verify substitution работает (boot Garage, check rpc_secret applied).

## Specific Ideas

- **«AI может писать в свои файлы реальные ключи»** — central threat model from user. Drives D-01/D-02/D-07/D-08/D-09 architecture: защита через формат, не через путь. Path-allowlist ломает это (AI agent видит "safe" path, может не задумываясь скопировать real value).
- **«Делать как можно проще»** — explicit user direction. Drives D-13 (custom rules rejected — default rules достаточно), AM-04 split-out из 999.17.2 (quality concern, не security).
- **«Защищать всё что в git»** — explicit principle. Drives D-01 uniform protection. Только два exemption обоснованы independently:
  - D-05 fixtures = test infrastructure category (industry-standard exception, paralleling semgrep `tests/` / trivy `testdata/` / gitleaks own `tests/`)
  - D-06 manifest = shape-and-scope allowlist (не path carve-out — discriminate по форме what was found, не where it lives)
- **«Кубер + GitLab CI вместо Coolify»** (2026-04-30) — drives DEVOPS-HANDOFF CI-platform-portable. NO GitHub Actions YAML, NO Coolify env vars, NO Kubernetes admission controller manifests. Только spec того что должно прогоняться + exit code semantics.
- **«Никаких .gitignore для config-файлов с secrets»** (2026-04-30 user directive) — drives D-10 12-Factor envsubst pattern instead of tracked-template-+-.gitignored-real. Принцип: scrubbing secrets из git tracking — это false security (value всё равно на хосте + в Docker layers + в process state). Real fix = secrets не в config files вообще, секреты только в env vars, config files имеют только placeholders. `.env*` в `.gitignore` = different category (canonical env-injection mechanism для local dev), не violates this principle.
- **«Мы слишком растянули эту простую задачу»** — drives final scope narrowing. 7 atomic items only, single plan-phase target. No discuss creep.
- **Manifest shape allowlist research-backed** — gitleaks v8 README сам документирует этот pattern для `package-lock.json` (canonical example). pnpm-lock.yaml (sha512 integrity hashes) — community precedent. Это idiomatic gitleaks v8, не invention. Soutce: `[[allowlists]] condition = "AND" + paths + regexes + regexTarget = "match"` — правильный mechanism для combined path+shape matching.
- **Default gitleaks rules — industrial standard** — никаких custom не нужно для project'а на этом этапе. Default ловит: aws-access-token, github-pat, slack-bot-token, telegram-bot-api-token, stripe-access-token, discord-api-token, generic-api-key (entropy), private-key (PEM blocks), rsa/dsa keys, jwt, и десятки других. Real findings которые мы обнаружили (telegram token в `.env.docker` history, garage rpc_secret) — все catched default rules.
- **Two scanner config bugs surfaced through Plan 04 empirical UAT** (999.17.1) — это и есть value of fixture-and-prove pattern. Без empirical run baga оставались бы скрытыми.
