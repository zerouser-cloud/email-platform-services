## 6. GitLab migration — coordination notes

> Active migration plan per memory `project_gitlab_migration.md`. Two scenarios for `.gitleaksignore` post-cutover; this section disambiguates.

### 6.1 `.gitleaksignore` handling at migration cutover

The OQ-5 fingerprint suppressions (and the §4.1 D-08 follow-up entries) in `.gitleaksignore` reference commit SHAs from the current GitHub origin. At GitLab migration cutover, behaviour depends on migration mode:

- **Scenario (a) — Full-history migration** (`git push --mirror` from GitHub origin to GitLab origin): commit SHAs are preserved. The OQ-5 + D-08 fingerprint entries continue to apply on the new GitLab origin without modification. The comment block above the entries continues to apply (re-evaluation trigger not yet hit). No developer-side action.
- **Scenario (b) — Fresh-repo migration** (squash-and-import or `git --orphan` reset, no full history): the historical commits cease to exist on the new GitLab origin. The OQ-5 + D-08 fingerprint entries become MOOT — DELETE them from `.gitleaksignore` at migration cutover, and verify `pnpm security:secrets-full` exits 0 without them. The acceptance signature loses meaning because there is nothing to suppress.

DevOps documents the chosen migration mode (a or b) in the GitLab migration runbook. The 999.17.2 PR's OQ-5 + D-08 suppressions are written to support both scenarios — no developer-side change required at cutover except option (b)'s DELETE.

### 6.2 Active GitHub repo post-migration

If the GitHub repo remains active (mirror, archive, or fallback) after GitLab becomes primary:

- The historical Telegram token in commits `c638e69`, `382fc1f` is still POST-ROTATION worthless — no exfiltration value.
- The Garage rpc_secret in commit `1427558`+ is post-rotation worthless similarly.
- The OQ-5 + D-08 fingerprint suppressions on the GitHub repo continue to silence informational findings; no action.
- Residual exposure analysis: same as §4 — historical leaked values are post-rotation worthless; the GitHub origin's continued existence does not increase risk. If the GitHub repo is fully archived (read-only) or deleted post-migration, residual exposure drops to zero.

DevOps decides the GitHub repo's post-migration role (archive / mirror / delete) as part of the migration runbook.
