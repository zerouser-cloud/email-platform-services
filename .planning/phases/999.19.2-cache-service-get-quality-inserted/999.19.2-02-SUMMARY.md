## Findings Closed

### BL-01 — TRANSIENT scope bleed-through (BLOCKER closed)

**REVIEW.md cross-ref:** `999.19.2-REVIEW.md` § BL-01 (file `cache.providers.ts:28-33`).

**Root cause:** `PinoLogger@nestjs-pino@4.6.1` is decorated `@Injectable({ scope: Scope.TRANSIENT })`. NestJS DI scope hierarchy: factory provider depending on TRANSIENT provider becomes TRANSIENT itself. Plan 01's `inject: [REDIS_CLIENT, PinoLogger]` silently demoted `CACHE_SERVICE` to TRANSIENT — singleton invariant broken, L1 Cache no longer matched L2 Drizzle / L3 S3 / L4 gRPC clients singleton tier-1 surface.

**Closure:** D-11.A factory revert + lazy-getter pattern in service. Singleton invariant verified by absence of TRANSIENT-scoped injects in the new `inject: [REDIS_CLIENT]` array. Empirical smoke confirms `cacheServiceProvider` factory now resolves once per service module — no per-resolution allocation overhead, no log-context race in concurrent requests.

### WR-01 — prefixKey 4× hot-path duplication (closed)

**REVIEW.md cross-ref:** `999.19.2-REVIEW.md` § WR-01 (file `cache.service.ts:21,31,45,48`).

**Closure:** `const prefixed = this.prefixKey(key)` once at top of `get<T>()`; 3 subsequent calls replaced. `await this.del(key)` keeps BARE `key` because `del()` itself prefixes (verified in `cache.service.ts:77` — `await this.redis.del(this.prefixKey(key))`).

### WR-04 — stale comment / missing JSDoc on CacheGetResult (closed)

**REVIEW.md cross-ref:** `999.19.2-REVIEW.md` § WR-04 (file `cache.interfaces.ts:23-26`).

**Closure:** dedicated JSDoc block above `CacheGetResult<T>` explaining Tier-1 contract role + D-07 (verbatim shape lock) + D-08 (caller-side branching) references. Existing `Canonical Config Access Contract` comment kept in place attached to `CacheConfig` re-export — its narrow scope was correct, just visually disambiguated by the new JSDoc above.

### IN-02 — D-06 invariant violation in self-heal del() (closed)

**REVIEW.md cross-ref:** `999.19.2-REVIEW.md` § IN-02 (file `cache.service.ts:34,48`).

**Closure:** both corrupt branches wrap `await this.del(key)` in `try { ... } catch (delErr) { this.logger.error({ key: prefixed, delErr }, 'cache: self-heal del() failed; corrupt entry persists'); }`. D-06 invariant restored — raw `delErr` (Redis network failure or similar) stays foundation-internal; the public `CacheGetResult` contract always returns `{ status: 'corrupt', reason: ... }` regardless of self-heal outcome. ### 1. [Rule 3 — Blocking] Constructor-eager `child()` assignment failed at boot — applied lazy-getter rollback shape

- **Found during:** Task 5 (Step 3 — Runtime smoke `pnpm start:native`).

Empirical boot of all 6 services produced `TypeError: Cannot read properties of undefined (reading 'child')` from `[ExceptionHandler]` — `PinoLogger.root` is `undefined` at the time `cacheServiceProvider.useFactory` constructs `RedisCacheService`. - **Fix:** Applied the plan's own `<rollback_strategy>` (lines 924-938) — replaced eager assignment with a lazy private getter:
  ```typescript
  private _logger?: PinoBaseLogger;
  private get logger(): PinoBaseLogger {
    if (!this._logger) {
      this._logger = PinoLogger.root.child({ context: RedisCacheService.name });
    }
    return this._logger;
  }
  ```
  TEMP marker comment moved from the constructor body to directly above the getter — content byte-identical (4 lines verbatim per D-11.B), grep-able once. The TEMP marker text mentions `PinoLogger.root.child(...)` in a backtick reference and the actual `child()` invocation lives in the getter — `grep -c "PinoLogger.root.child(" cache.service.ts` returns 2, but the architecturally-significant TEMP-anchor (the `TEMP: foundation logger DI pattern under design` line) appears exactly once.

## Lessons Learned

- **`PinoLogger.root` is bootstrap-late.** When `useFactory` of a feature-level provider depends on `PinoLogger.root`, that static is `undefined` at module-instantiation time. Lazy access (getter or constructor-late call) is the safe pattern. Constructor-eager `PinoLogger.root.child(...)` only works when the class is instantiated AFTER `app.listen()` (e.g., per-request adapter via `@Injectable({ scope: Scope.REQUEST })`) — but that re-introduces the BL-01 TRANSIENT-class problem. Lazy getter on a singleton is the clean compromise.
- **Plan 02's `<rollback_strategy>` block was load-bearing.** The planner correctly anticipated the bootstrap-order risk and pre-locked the lazy-getter shape as the fallback. Having the rollback shape in the plan itself made the deviation a single-step recovery rather than an architectural redesign.
- **`del()` self-heal is a real D-06 surface.** Wrapping `await del()` in try/catch may look paranoid (corrupt entry persisting one extra TTL is not a disaster), but the strict reading of D-06 — "raw error stays foundation-internal" — required it: a Redis-down condition during corrupt entry handling must not leak `IORedisError` through the `CacheGetResult` contract. The cost is two extra try/catch blocks; the benefit is contract honesty under transient Redis instability.
- **TEMP markers as architectural anchors are a valid pattern.** The 4-line verbatim TEMP marker (D-11.B) defers a real architectural question (LoggerPort Tier-1 abstraction) without quietly committing the codebase to one shape. Future Phase 999.20 will grep this marker as the start of its audit. Forward-reference via grep-anchor + `project_logger_port_tbd` memory + Phase 999.20 placeholder on ROADMAP creates a 3-way-cross-referenced TBD that won't get lost.
