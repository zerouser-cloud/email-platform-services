### Mirror diff (cache vs http adapter)

```
http adapter (39-48)                       │ cache service (24-28, 30-32)
───────────────────────────────────────────┼──────────────────────────────────────────────
private ensureInit(): void {               │ private ensureInit(): void {
  if (!this.logger) {                      │   if (!this.logger) {
    this.logger = PinoLogger.root.child(   │     this.logger = PinoLogger.root.child(
      { context: this.logContext });       │       { context: RedisCacheService.name });
  }                                        │   }
}                                          │ }
                                           │
onModuleInit(): void {                     │ onModuleInit(): void {
  this.ensureInit();                       │   this.ensureInit();
}                                          │ }
```

Единственная семантическая разница — источник `context` (instance-field `this.logContext` в HTTP-адаптере vs class-name literal `RedisCacheService.name` в кэше). Это ожидаемо: HTTP adapter параметризуется per-instance log-context (multi-vendor HTTP clients), кэш-сервис singleton с фиксированным контекстом. Шаблон унификации (Phase 999.20 grep-target) сохранён — оба сайта дают `private ensureInit() { if (!this.logger) ... }` block.
