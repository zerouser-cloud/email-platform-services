### NEW: `packages/foundation/src/external/config/load-config.ts` (utility, verbatim relocation)

**Analog (primary, exact):** `packages/config/src/config-loader.ts` (entire 20-LOC file).

**Full file to copy verbatim** (`packages/config/src/config-loader.ts` L1-20):

```typescript
import { z } from 'zod';

const cache = new Map<z.ZodType, unknown>();

/**
 * Validates process.env against the provided Zod schema.
 * Results are cached by schema reference for idempotency.
 * Works because each service passes the same module-level const schema reference.
 *
 * @param schema - A ZodObject or ZodEffects (refined ZodObject) to validate against
 * @returns Parsed and validated config object
 */
export function loadConfig<T extends z.ZodType>(schema: T): z.infer<T> {
  const cached = cache.get(schema);
  if (cached) return cached as z.infer<T>;

  const result = schema.parse(process.env);
  cache.set(schema, result);
  return result as z.infer<T>;
}
```

**Deviations from analog:** zero. Cache-by-schema-reference semantics are load-bearing (D-08 in 999.11.1 uses it so `useValue: loadConfig(...)` is safe to call eagerly at module-definition time without double-parsing). Any wording change risks behavioral drift.

**Data flow:** imports `zod`; exports `loadConfig` to barrel; this is the ONE legal `process.env` read-site per invariant I-0.1 (after Plan 01 rewrite).

```typescript
// packages/foundation/src/external/config/create-config-module.ts
import { Global, Module, type DynamicModule, type Provider } from '@nestjs/common';
import type { z } from 'zod';
import { loadConfig } from './load-config';

export interface CreateConfigModuleOptions<TEnv> {
  readonly schema: z.ZodType<TEnv>;
  readonly token: symbol;
  readonly narrowPorts?: ReadonlyArray<{
    readonly port: symbol;
    readonly slice: (env: TEnv) => unknown;
  }>;
}

@Global()
@Module({})
class ConfigModuleHolder {}

export function createConfigModule<TEnv>(
  opts: CreateConfigModuleOptions<TEnv>,
): DynamicModule {
  const configProvider: Provider = {
    provide: opts.token,
    useValue: loadConfig(opts.schema),
  };

  const narrowPortProviders: Provider[] = (opts.narrowPorts ?? []).map(
    ({ port, slice }) => ({
      provide: port,
      inject: [opts.token],
      useFactory: (env: TEnv) => slice(env),
    }),
  );

  const exportedTokens: symbol[] = [
    opts.token,
    ...(opts.narrowPorts ?? []).map((p) => p.port),
  ];

  return {
    module: ConfigModuleHolder,
    global: true,
    providers: [configProvider, ...narrowPortProviders],
    exports: exportedTokens,
  };
}
```

**Deviations from gRPC analog:**
- Returns `DynamicModule` directly (config has ONE instance per app), gRPC returns a recipe (gRPC has MANY instances per app — one per upstream).
- Uses `global: true` on return object (config MUST be global per 999.11.1 Plan 10 Rule 3). gRPC ClientsModule.registerAsync is inherently root-level so no `global: true` needed.
- No `Symbol.for` derivation (config token is app-local, passed in via opts).
- No `healthProvider` (config has no runtime liveness state).

**Inline-vs-separate-interface decision:** inline in the same file, re-export from `index.ts` — matches `define-grpc-client.ts` L18-29 precedent (tight coupling, one consumer, no decoupling benefit from a separate file).

**Data flow:** imports types from `@nestjs/common`, type-only from `zod`, runtime from `./load-config`; exports `createConfigModule`, type `CreateConfigModuleOptions<TEnv>`; consumed by 6× apps `{svc}-config.module.ts` (Plan 06).
