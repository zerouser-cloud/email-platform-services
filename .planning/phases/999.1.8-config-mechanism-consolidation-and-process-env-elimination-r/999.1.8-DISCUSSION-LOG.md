## Area 3: createConfigModule API shape

| Option | Description | Selected |
|--------|-------------|----------|
| Factory function → DynamicModule (Recommended) | `export const AudienceConfigModule = createConfigModule({ schema, token, narrowPorts })` — factory возвращает DynamicModule сразу. Declarative, нет boilerplate. Minimum lines per service (~15 vs current ~60). | ✓ |
| Class with forRoot() static | `createConfigModule()` возвращает класс с `forRoot()` методом. Mirrors current pattern — apps пишут `SvcConfigModule.forRoot()` как сейчас. Consistency с historical precedent but больше LOC. | |
| Class-based API | `class AudienceConfigModule extends createConfigModule({...})` — inheritance-based. More object-oriented. Менее идиоматично для NestJS, ожидается больше issues. | |

**User's choice:** Factory function → DynamicModule
**Notes:** Breaking change vs current pattern — `apps/*/src/{svc}.module.ts` imports constant directly, no `.forRoot()` call. Plan 06 updates all 6× root modules mechanically. Factory internally preserves @Global() scope per 999.11.1 Plan 10 Rule 3.

## Area 4: Narrow port slices — declaration location

| Option | Description | Selected |
|--------|-------------|----------|
| Inline в apps (Recommended) | Apps пишут `narrowPorts: [{ port: PERSISTENCE_CONFIG_PORT, slice: (c) => ({ DATABASE_URL: c.DATABASE_URL }) }, ...]`. Per-service flexibility сохраняется — каждый сервис берёт только нужные поля. Current pattern preserved. | ✓ |
| Pre-declared standard slices в foundation | Foundation экспортирует `persistenceSlice`, `loggingSlice`, `grpcClientSlice` — apps просто подсоединяют `narrowPorts: [persistenceSlice, loggingSlice]`. DRY но жертвует per-service variance (e.g., sender имеет extra grpcUrls). | |
| Hybrid — foundation defaults + app override | Foundation даёт standard slices; apps могут override отдельные поля. Более complex, но flexibility + DRY. Ожидается over-engineering для 6 сервисов. | |

**User's choice:** Inline в apps
**Notes:** Per-service variance preserved (gateway: 5 grpcUrls; sender/parser/audience: 1 each; notifier+auth: no grpc consumers). Shared helpers deferred per D-14 — only если post-Plan 06 duplication становится реальной проблемой.
