## Decisions Made

- **Verbatim `loadConfig` relocation** — zero deviations from source file. Any wording/signature drift would risk behavioural drift on cache-by-schema-reference semantics, which D-08 of Phase 999.11.1 relies on for eager `useValue: loadConfig(...)` evaluation at module-definition time.
- **Factory returns DynamicModule directly (not a class with static `forRoot()`)** — per CONTEXT D-08/D-11. Consumer import pattern becomes `AudienceConfigModule` (constant) instead of `AudienceConfigModule.forRoot()`. This is intentional breaking change per user's "делать сразу правильно" stance — all 6 `{svc}.module.ts` imports will be updated in Plan 06.
- **Belt-and-suspenders `@Global()` on anchor class + `global: true` on return** — both markers present to guarantee narrow-port providers are visible to nested `forRootAsync({inject: [*_CONFIG_PORT]})` dynamic modules (LoggingModule, gRPC ClientsModule, TerminusModule) that cannot walk up to root providers otherwise. This preserves the 999.11.1 Plan 10 Rule 3 fix.
- **zod imported as `import type`** — factory itself has no runtime dependency on zod; only `loadConfig` (imported from sibling) does. Makes the semantic dependency graph explicit.
- **Inline interface declaration** — `CreateConfigModuleOptions<TEnv>` lives in the same file as `createConfigModule` (not a separate `.interfaces.ts`), matching `define-grpc-client.ts` L18-29 precedent: tight coupling, one consumer, no decoupling benefit.
