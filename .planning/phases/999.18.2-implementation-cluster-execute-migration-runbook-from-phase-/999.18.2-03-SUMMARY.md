### USER-APPROVED Architectural Amendment (Rule 4)

**1. [Rule 1 - Bug + Rule 4 - Architectural Decision] Pulled Wave 3 task #3 (healthcheck swap к grpc_health_probe) forward into Wave 2 atomic commit**

- **Found during:** Task 7 implementation (compose `expose:` cleanup) — recognized cross-coupling между Wave 2 surgery и Wave 3 healthcheck recipe
- **Issue (Rule 1 — plan verify-gate overshoot):** Plan 03 verify-gate `grep -cE ":300[1-5]" infra/docker-compose.yml = 0` (must return 0 после Task 7 sub-task A) overshoots ADR intent. Pre-existing healthchecks `["CMD", "wget", "-qO/dev/null", "http://127.0.0.1:300x/health/live"]` reference HTTP ports 3001-3005 КОТОРЫЕ САМИ становятся unreachable после Task 5 (`app.listen()` dropped). Without inline healthcheck swap: `docker-compose.yml` is structurally broken (healthcheck pings non-existent endpoints) BETWEEN Wave 2 anchor commit AND Wave 3 task #3 commit. `pnpm start:isolated` between waves would show services как perpetually unhealthy → cascading `depends_on: condition: service_healthy` breaks gateway boot.
- **Architectural decision (Rule 4):** Two options presented к user during checkpoint:
  - **Option A (CHOSEN by user):** Pull Wave 3 task #3 healthcheck swap inline в Wave 2 — atomic commit covers ALL related changes; structurally consistent at every commit boundary. Plan 04 task #3 becomes verify-only (assert grpc_health_probe already в place).
  - **Option B (rejected):** Keep Wave 2 + Wave 3 separate per original plan; accept transient broken state между two commits. Was rejected because rollback drill protocol requires byte-for-byte recoverable + smoke-runnable state at each anchor.
- **Fix applied:** В infra/docker-compose.yml — 5 backend healthchecks (auth/sender/parser/audience/notifier) swapped к `["CMD", "grpc_health_probe", "-addr=:5005x"]` exec-form (distroless без shell, no CMD-SHELL wrapper) с `start_period: 30s` (was 10s); gateway healthcheck preserved as wget HTTP per ADR (c.1).
