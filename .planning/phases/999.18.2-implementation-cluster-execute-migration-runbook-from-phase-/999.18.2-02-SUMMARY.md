## Decisions Made

- **`$TURBO_ROOT$/` microsyntax (Rule 1 auto-fix).** Plan instructed bare `"pnpm-lock.yaml"` in `tasks.generate.inputs`. Empirical differential test exposed cache HIT despite lockfile mutation — bare-path inputs are interpreted package-relative in turbo 2.x, и `pnpm-lock.yaml` does not exist inside `packages/contracts/`. Consulted turbo 2.5+ docs (Context7 → `/vercel/turborepo` library) — canonical syntax is `$TURBO_ROOT$/<path>`. Re-ran differential test with corrected syntax — cache MISS confirmed. Plan-time syntax error fixed without re-deciding F-24 V1 strategy (semantic intent unchanged: ts-proto patch bump → lockfile change → cache invalidation).
- **Lockfile regeneration as part of Wave 1 surface (Rule 2 auto-add).** Plan ожидал 2-file Wave 1 surface (`pnpm-workspace.yaml` + `turbo.json`). После удаления `injectWorkspacePackages: true` из `pnpm-workspace.yaml`, `pnpm install --frozen-lockfile` падает с `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` — lockfile содержит embedded `settings.injectWorkspacePackages: true` snapshot. Без обновления lockfile вся Wave 1 цель (F-15 archaeology root-cause closure: «`pnpm install --frozen-lockfile` exits 0 без `--force`») недостижима. Lockfile refresh — это не deviation от M3, это структурный артефакт самого M3. Surface expanded to 3 files; rationale documented inline в commit body.
- **Native smoke gate workaround для worktree mode.** `.env` + `.env.docker` файлы gitignored, не копируются в worktree. Native smoke gate требует их наличия для `docker compose --env-file .env.docker`. Скопировал из main checkout в worktree (локально, не в commits) для smoke verification, удалил после успешной проверки. Это recurring worktree-mode quirk — ortho к Wave 1 changes.
- **No umbrella `verify:all` script added.** Wave 0 анкер уже включает 4 `verify:*` скрипта. Wave 4 task #2 invokes их explicitly en bloc per RUNBOOK; umbrella был бы scope creep — за рамки Wave 1.
