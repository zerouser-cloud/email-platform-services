# Phase 999.18.3 — Forensic Regression Full Audit

## 1. Executive verdict

Регрессия найдена и эмпирически локализована. Один rewrite-коммит **a647f51 (999.18.2-W2)** перевёл Dockerfile с явного `COPY tsconfig.base.json ./` (строка 28 pre-rewrite) на pipeline `pnpm dlx turbo prune --docker → installer → builder`, но **не заменил потерянный workspace-root config**. Pruner output `/app/out/full/` empirically NOT contains `tsconfig.base.json` (probe-pruner /app/out/full/ inspection). Каждая из 9 package-tsconfig'ов делает `extends "../../tsconfig.base.json"` → `tsc -p tsconfig.json` падает с **TS5083**, fallback на default-options без `esModuleInterop` → cascade 52× **TS1259** в zod 4.4.2. До Wave 3 эта ошибка была скрыта более ранним падением installer (`ERR_PNPM_NO_OFFLINE_TARBALL`). Wave 3 D-08 fix корректен и должен остаться. **Полный фикс — один canonical паттерн на выбор: (a) explicit `COPY tsconfig.base.json` в builder stage; (b) turbo `globalDependencies + futureFlags.pruneIncludesGlobalFiles=true`. Оба эмпирически проверены, оба canonical Vercel/Turborepo.** Distinct issues: **1**. Severity per `feedback_phase_completeness`: **малый дрейф** (одна строка/один config-flag).

## 5. Vercel/Turborepo canonical reference

Два независимых canonical паттерна documented in turborepo.dev:

**Pattern A — explicit COPY в builder stage (legacy/manual).** Vercel `examples/with-docker/apps/web/Dockerfile` использует только `COPY --from=prepare /app/out/json/` и `COPY --from=prepare /app/out/full/` — **не копирует workspace-root configs**. Это работает для examples потому что у них нет shared `tsconfig.base.json` (per-app self-contained). Для проектов с extends — explicit COPY дополнительной строкой это документированный workaround (старый pre-2.5 turbo). [Vercel example Dockerfile](https://github.com/vercel/turborepo/blob/main/examples/with-docker/apps/web/Dockerfile)

**Pattern B — `globalDependencies + futureFlags.pruneIncludesGlobalFiles` (canonical, current).** Из turborepo.dev/docs/reference/configuration: «Copy files matching `globalDependencies` globs into the `turbo prune` output directory». Конфигурация:

```jsonc
{
  "globalDependencies": ["tsconfig.base.json"],
  "futureFlags": { "pruneIncludesGlobalFiles": true },
  "tasks": { ... }
}
```

Эффект: `tsconfig.base.json` копируется и в `out/full/`, и в `out/json/`. Empirically validated probe-pruner-globaldeps (turbo 2.9.8): `find /app/out -name "tsconfig*"` → **6 файлов, включая `/app/out/full/tsconfig.base.json` И `/app/out/json/tsconfig.base.json`**. Status: **future flag, experimental, не stable** (per turborepo.dev). Issue [vercel/turborepo#6675](https://github.com/vercel/turborepo/issues/6675) подтверждает что без флага root-files не попадают.

**Какой выбрать.** Pattern B — каноничнее (single source of truth = turbo.json, future-proof когда флаг станет default), но experimental. Pattern A — battle-tested (используется в Vercel's own examples), zero-risk, but introduces «two sources of truth» (turbo.json declares `globalDependencies` but Dockerfile must mirror via COPY). **Сравнение с pre-999.18 working state: старый Dockerfile использовал Pattern A (explicit COPY).** Recommendation для MAANG canonical match: **Pattern A основной + Pattern B заявить как roadmap upgrade когда флаг станет stable.** Оба emplеренные.
