### Q5 — что делать с husky?

Husky нужен **только на host** (git hooks). В Docker context это noise. Альтернативы:

- Использовать `prepare` script с conditional check (`test -d .git && husky || true`)
- Использовать другой git hooks manager (lefthook, simple-git-hooks)
- Просто игнорировать в Docker (`--ignore-scripts` patch path)

**Researcher MUST evaluate**: какой подход у production-grade monorepo'ов с husky?

## Lessons (general, не tied к specific fixes)

1. **Empirical probe BEFORE locking ADR.** 999.18.1 предположил cache-mount target = `/pnpm/store` без verification. Probe должен предшествовать locking decision.

2. **Diff against last working baseline при rewrite infra files.** 999.18.2 W2 rewrite Dockerfile под turbo prune НЕ сделал diff с pre-rewrite working version → потерял `COPY tsconfig.base.json`. Procedure: `git show <last-working-commit>:<file>` + diff review = mandatory step before rewrite.

3. **Cross-check audit recommendations против user meta-principles.** Audit recommended Pattern A (COPY bypass) — costyl per user's framing. Application of meta-principle 9 raised the bar к Pattern E.

4. **Третий workaround в одной phase = systemic gap signal.** 4 layers of failure в 999.18.3 = systemic. Не продолжать patching.

5. **Layer separation > clever optimizations.** Mixing host-dev concerns (husky, lifecycle) с build context (Docker) создаёт hidden coupling. Чистый layer split (host / build / runtime) устраняет class of issues.

6. **Pattern thrashing is symptom of insufficient global pass.** Если предлагаешь Pattern A → B → E последовательно — значит первый pass был недостаточно глубоким. Один thorough survey + один proposal лучше трёх iterations.

7. **«Это canonical» — claim, требующая proof.** Не заявлять canonicity без source code reference / documented citation / empirical probe. Иначе — `[unverified]`.
