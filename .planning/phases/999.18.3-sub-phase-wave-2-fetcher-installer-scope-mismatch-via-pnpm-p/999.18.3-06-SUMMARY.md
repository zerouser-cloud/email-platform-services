**NEW failure surface — root cause analysis:**

1. **Root `package.json` line `"prepare": "husky"`.** Husky 9.x `prepare` lifecycle script registers git hooks via the `husky` CLI binary present in node_modules.
2. **`husky` is in root devDependencies** (`"husky": "^9.1.7"`), not regular dependencies.
3. **Post-`pnpm install --frozen-lockfile`** at installer stage: husky binary present → `prepare` runs OK (note in installer log: `. prepare$ husky` → `. prepare: Done`).
4. **At builder stage Stage 1.3 `pnpm prune --prod`**: pnpm strips devDeps (husky among them) AND re-runs the `prepare` lifecycle script as part of standard pnpm prune behaviour. Result: `sh: husky: not found` → exit 1 → ELIFECYCLE → `RUN ... pnpm prune --prod` fails → docker buildx fails the builder stage.
5. **This surface was masked** by the prior `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` failure (D-10 target). Once D-10 ENV CI=true eliminated the TTY abort, pnpm prune progresses further and exposes the husky lifecycle issue.

**Forward-fix candidates** (for user decision — not auto-applied per CONTEXT D-06 + memory `feedback_infra_changes`):

- **Option A:** Append `--ignore-scripts` to `pnpm prune --prod` in Stage 1.3 builder. Canonical pnpm flag for skipping lifecycle scripts. Pure additive 1-flag change.
- **Option B:** Conditional root `prepare` — change `"prepare": "husky"` to `"prepare": "husky || true"` (silent skip when binary absent). User-side script change.
- **Option C:** Move `prepare` script to a non-Docker path — e.g., conditionally check for `.git` presence before running husky. Self-aware lifecycle script.
- **Option D:** Drop husky entirely from root devDeps and replace with manual git hook setup. Architectural removal.

Each option has tradeoffs around developer ergonomics, CI/CD purity, and forward-compatibility. Selection is a Rule 4 architectural decision — user-owned per memory `feedback_infra_changes` + skill `infrastructure-guard`.
