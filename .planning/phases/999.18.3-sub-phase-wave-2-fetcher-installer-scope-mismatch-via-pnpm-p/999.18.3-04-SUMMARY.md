Possible root causes (tier 4 architectural — D-09 follow-up scope):

1. **turbo prune omits non-package-scope root files by design** — `tsconfig.base.json` lives at workspace root, not inside any package; pruner's dep-graph is package-level → root-level configs не traverse.
2. **Wave 3 amendment unmasking pre-existing latent bug** — pre-Wave-3, builder either (a) failed earlier (на ERR_PNPM_NO_OFFLINE_TARBALL — covered Stage 1.3 by failing Stage 1.2), (b) or built differently due to legacy fetcher contributions to filesystem.
3. **zod@4.4.2 strict TS1259 emergence** — recent zod version requires `esModuleInterop: true` в `tsconfig.json`; if `tsconfig.base.json` missing, packages cannot inherit setting → 52 TS1259 cascade.

Forward-fix candidates (D-09 future scope):

- **Option A:** Add `COPY --from=pruner /app/tsconfig.base.json ./tsconfig.base.json` (or wider `COPY --from=pruner /app/tsconfig*.json ./`) к Stage 1.3 builder — supplements pruner artifact gap.
- **Option B:** Workspace-level pruner discipline — instruct turbo prune to include root configs (e.g. via `.turbo` config или explicit prune flag).
- **Option C:** Move shared TSC config к package level (each package owns its own base config) — more invasive, kills DRY.
