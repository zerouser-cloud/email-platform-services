## Decisions Made

- **Shared TransitionCampaignStatusUseCase (D-03 realised).** Plan's recommendation honored: one atomic use case serving both `pauseCampaign` (pass `'paused'`) and `resumeCampaign` (pass `'active'`) RPCs. Demonstrates cross-service use case reuse within the same bounded context — a concrete proof-of-pattern complementing auth's `IssueTokenPairUseCase` (shared by Login + RefreshToken).
- **Runner/Message/Macros use cases stubbed without outbound ports.** Per RESEARCH.md §Q2/Q3 and PROJECT.md "без бизнес-логики" constraint — structural phase permits use cases that `throw new Error` without persistence adapters. Symmetric outbound ports (RunnerRepositoryPort, MessageRepositoryPort, MacrosRepositoryPort) are additive for the future business-logic phase.
- **PauseCampaignService/ResumeCampaignService return minimal projection.** Current `Campaign` domain entity carries only `{id, name, status}`. Services pass through those three fields and stub the remaining proto fields (`messageId`, `runnerId`, `groupId`, `userId`, `sentCount`, `failedCount`, `createdAt`, `updatedAt`) with empty strings / zeros. Will be populated when the entity gains those fields in the business-logic phase.
- **CloudFnSmokeController unchanged.** D-13 test-boundary exception honored — smoke controller stays in `controllers[]` array at the same position, no refactoring applied. `test/cloudfn-smoke.controller.ts` path untouched.
