## Decisions Made
- **D-18 realised mechanically.** What was "convention" through Plans 02-05 (discipline checked by grep) is now "provably enforced" at every `pnpm lint` invocation. Override 9's message for `@email-platform/contracts` names the exact responsible owner: "Controllers (infrastructure/controllers/grpc/) own the proto↔domain mapping" — so a future developer who types `import { LoginRequest } from '@email-platform/contracts'` in `application/services/login.service.ts` knows both the rule (bad) AND the fix location (controller layer) from the error message alone.
- **Override 9 uses two separate pattern entries** (contracts + microservices) rather than one merged group. Separation keeps each message targeted — proto imports get the Proto Visibility explanation, `@nestjs/microservices` imports get the transport-adapter explanation. Matches how Overrides 1-3 differentiate message content per forbidden group.
- **@nestjs/common INTENTIONALLY permitted in application/.** Application layer uses `@Injectable()`, `@Inject()` for DI — these are NestJS common-module decorators required for service and use-case classes to register. Transport-specific (`@nestjs/microservices`) stays out. This matches the three-layer stack doc in `.agents/skills/nestjs-hexagonal-mapping/`.
