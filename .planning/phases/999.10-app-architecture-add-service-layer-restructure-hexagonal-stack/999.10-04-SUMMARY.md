# Phase 999.10 Plan 04: Parser Sweep — Option A Canonicalise Storage Smoke Summary

Parser service migrated to canonical Controller → Service → UseCase 3-layer stack for all 8 proto RPCs; Pitfall 3 (duplicate gRPC registration of runStorageSmoke + cleanupStorageSmoke between parser.grpc-server.ts stubs and test/storage-smoke.controller.ts) resolved per user decision via Option A canonicalisation — smoke test logic migrated into 2 inbound ports + 2 services + 3 atomic use cases; StorageSmokeController deleted; ParserController now holds all 8 RPCs with @ParserServiceControllerMethods() bulk decorator preserving uniformity with auth/sender pilots.

## What Shipped

**Renames (3 — via git mv preserving history):**
- `apps/parser/src/infrastructure/grpc/parser.grpc-server.ts` → `infrastructure/controllers/grpc/parser.controller.ts` (class renamed `ParserGrpcServer` → `ParserController`; body fully rewritten for N-port wiring — git diff reports as delete+add due to >50% change)
- `apps/parser/src/health/health.controller.ts` → `infrastructure/controllers/rest/health.controller.ts` (Pitfall 9 resolved: relative-import depth re-anchored 1 → 3)
- `apps/parser/src/infrastructure/persistence/parser-task.mapper.ts` → `infrastructure/persistence/mappers/parser-task.mapper.ts`

**Commands (7):** `CreateTaskCommand`, `ListTasksCommand`, `GetTaskCommand`, `GetSettingsCommand`, `UpdateSettingsCommand`, `RunStorageSmokeCommand`, `CleanupStorageSmokeCommand`.

**Inbound Ports (7):** `CreateTaskPort`, `ListTasksPort`, `GetTaskPort`, `GetSettingsPort`, `UpdateSettingsPort`, `RunStorageSmokePort`, `CleanupStorageSmokePort`. Each port owns its result type (e.g., `CreateTaskResult`, `SmokeBucketResult`). healthCheck intentionally has no port — stubbed inline in controller (D-14 — gRPC health is grpc-health-check protocol registered in main.ts; the RPC stub returns `{status: SERVING}`).

**Services (7):** 5 pure-delegation services for the non-smoke RPCs (each injects 1 use case, forwards the command). 2 smoke services: `RunStorageSmokeService` composes `RunPrivateSmokeCycleUseCase + RunPublicSmokeCycleUseCase` via `Promise.all` (preserves existing parallel-cycle semantics); `CleanupStorageSmokeService` delegates to `CleanupSmokeObjectUseCase`.

**Use Cases (8):**
- 5 non-smoke stubs: `CreateParserTaskUseCase` (replaces StartParsingUseCase per D-23), `ListParserTasksUseCase`, `GetParserTaskUseCase`, `GetParserSettingsUseCase`, `UpdateParserSettingsUseCase`. Pattern: `throw new Error('XxxUseCase not yet implemented')` — behavior identical to pre-refactor.
- 3 real-I/O smoke cycles: `RunPrivateSmokeCycleUseCase` (injects `PARSER_STORAGE: PrivateStoragePort`, runs upload→exists→download on private bucket), `RunPublicSmokeCycleUseCase` (injects `SHARED_REPORTS: NamespacedStoragePort`, runs upload→exists→public-fetch on public bucket, embeds `makeSmokePdf` helper), `CleanupSmokeObjectUseCase` (injects BOTH ports, dispatches by bucket name via `Record<string, (key)=>Promise<void>>`).

**Controller rewrite:** `ParserController` implements full `ParserServiceController` (all 8 methods), decorated with `@ParserServiceControllerMethods()` bulk decorator, injects 7 inbound ports via Symbol tokens. Proto DTO shapes mapped field-by-field to Command DTOs and back to proto response types.

**Module rewrite:** `ParserModule` providers[] in 3-zone format (Zone 1: outbound port → PgParserTaskRepository; Zone 2: 7 inbound ports → 7 services; Zone 3: 8 use cases as plain @Injectable providers without tokens). controllers[] holds `ParserController`, `HealthController`, `AppStoreSpySmokeController` (StorageSmokeController removed).

**Deletions (4):**
- `apps/parser/src/application/ports/inbound/start-parsing.port.ts` (D-23 rename)
- `apps/parser/src/application/use-cases/start-parsing.use-case.ts` (D-23 rename)
- `apps/parser/src/infrastructure/grpc/parser.grpc-server.ts` (full rewrite in new location)
- `apps/parser/src/test/storage-smoke.controller.ts` (Option A canonicalisation — 154 lines removed; logic distributed across 2 services + 3 use cases)

## Decisions Made

1. **Pitfall 3 resolution: Option A (Canonicalise)** — user-approved at Task 0 decision checkpoint. Smoke logic migrated into canonical 3-layer stack; `StorageSmokeController` deleted. Rationale: all 4 services follow identical pattern (D-01 uniformity); SKILL.md canonical pattern holds without exception; ParserController declares full `implements ParserServiceController` — TypeScript type safety at the proto boundary; +8 files accepted as a fair cost for zero test-tier exception.

2. **D-23 rename applied** — `start-parsing.{port,use-case}.ts` replaced by `createParserTaskUseCase` + `CreateTaskPort` matching proto RPC name `createTask`. No runtime behavior change.

3. **Smoke use cases contain REAL I/O logic (not stubs)** — intentional per Option A canonicalisation. Gateway `/test/parser/storage-service` endpoint gates phase smoke; only architectural layers migrated, bizlogic boundary unchanged since smoke was already operational pre-refactor. Documented in summary metadata and parser code comments.

4. **Record dispatch for bucket cleanup** — CleanupSmokeObjectUseCase uses `Record<bucket, deleteFn>` with fallback returning `{success:false, detail:'Unknown bucket'}`. Complies with CLAUDE.md no-switch/case rule and matches semantic behavior of previous `StorageSmokeController` L76-84 (if/if/fallback chain).

5. **0 proto-shape auto-deviations** — Plan 02/03 lesson applied proactively by reading `packages/contracts/src/generated/parser.ts` before writing any ports/services/controller code. All 8 RPC shapes verified against the generated `ParserServiceController` interface before implementation.
