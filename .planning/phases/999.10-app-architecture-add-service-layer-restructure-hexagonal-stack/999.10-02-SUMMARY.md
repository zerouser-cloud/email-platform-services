## Accomplishments

- **Canonical 3-layer stack realised in auth** — Controller (infrastructure) implements proto, Service (application) implements our inbound port, UseCase (application) is atomic. Reference pattern for Plans 03/04/05.

- **Per-feature Service granularity** (6 services, one per non-health RPC) — `LoginService` / `RefreshTokenService` / `ValidateTokenService` / `RevokeTokenService` / `CreateUserService` / `ListUsersService`.
- **Use case decomposition per D-23** — monolithic `LoginUseCase` replaced by 8 atomic use cases (VerifyCredentialsUseCase, IssueTokenPairUseCase — shared with refreshToken, PersistUserUseCase, HashPasswordUseCase, ValidateRefreshTokenUseCase, VerifyAccessTokenUseCase, RevokeRefreshTokenUseCase, ListUsersUseCase).
- **Hexagonal file layout cleanup** — `src/health/` removed; `infrastructure/grpc/` removed; new paths under `infrastructure/controllers/{grpc,rest}/` + `infrastructure/persistence/mappers/`.
- **Domain + application layer isolation verified** — 0 `@email-platform/contracts` imports in `application/`, 0 framework imports in `domain/`.
- **Native runtime smoke PASSED** — `/health/ready` returns HTTP 200 with all 5 upstreams `up` (auth/sender/parser/audience/notifier) after `pnpm start:native`.
