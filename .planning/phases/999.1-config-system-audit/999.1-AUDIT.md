### F-10 (major, L5): `packages/foundation/src/external/build-info.ts` silently falls back to `LOCAL_BUILD_INFO` when file absent — no-fallbacks skill violation

- **ID:** F-10
- **Layer:** L5 Missing Configs
- **Severity:** major
- **Title:** `getBuildInfo()` in `build-info.ts` swallows file-read + JSON-parse errors via `try/catch` and substitutes in-code `LOCAL_BUILD_INFO` constant — soft application of env-schema "no fallbacks" rule (and no Zod parse on the loaded JSON)
- **Evidence:**

```bash

...
const LOCAL_BUILD_INFO: BuildInfo = { commit: 'local', branch: 'local', built: 'local' } as const;

let cached: BuildInfo | null = null;

export function getBuildInfo(): BuildInfo {
  if (cached) return cached;
  try {
    const raw = readFileSync(BUILD_INFO_PATH, 'utf8');

    return cached;

    cached = LOCAL_BUILD_INFO;                  # ← silent fallback
    return cached;
  }
}
```

- **Violated contract:** DESIGN.md I-6.3 (env-schema — build-time artefacts that code parses structurally MUST have a Zod schema applied at parse time; no `JSON.parse(raw) as BuildInfo` cast) + I-1.2 corollary (env-schema — no fallbacks in consumer code; `LOCAL_BUILD_INFO` on file-absent is a fallback pattern in a non-env context)

Phase 999.11.1 removed `@nestjs/config` to eliminate exactly this pattern of "silent validation bypass via cast"; `build-info.ts` is the remaining instance.
