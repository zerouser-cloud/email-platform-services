## Что было пропущено

### F-15 (blocker — L3 Violations): CLI direct `process.env` reads

**Проблема:** 4× `apps/{auth,audience,parser,sender}/drizzle.config.ts` делают `DatabaseSchema.parse(process.env)` напрямую. DESIGN.md I-0.1 объявил их «legal read-sites exception», но у нас уже есть `loadConfig<T>()` в `packages/config/config-loader.ts` — framework-free generic wrapper, ничего не требует от DI. CLI должен его использовать.

**Canonical:**
```typescript
// apps/audience/drizzle.config.ts
import { loadConfig, DatabaseSchema, SERVICE } from '@email-platform/config';
import { defineConfig } from 'drizzle-kit';

const env = loadConfig(DatabaseSchema);  // ← вместо DatabaseSchema.parse(process.env)

export default defineConfig({
  dialect: 'postgresql',
  schema: './src/infrastructure/persistence/schema/index.ts',
  out: './drizzle',
  dbCredentials: { url: env.DATABASE_URL },
  schemaFilter: [SERVICE.audience.id],  // ← вместо hardcoded 'audience'
});
```

Результат: ровно 1 `process.env` read-site во всём репо (`config-loader.ts:18`), CLI exception удаляется.

### F-16 (major — L4 Propagation + architectural drift): Identity/Mechanism/Assembly split нарушен для config

**Проблема:** `packages/config/` смешивает Identity (Zod schemas, SERVICE catalog) с Mechanism (`loadConfig`, `composeSchemas`). У нас `infrastructure-client-layering` SKILL.md требует Three-Layer Rule (Identity / Mechanism / Assembly). Для gRPC применён корректно: contracts (proto) → foundation (`defineGrpcClient`, `GrpcCaller`, `Promisified<T>`) → apps assemble. Для config — сломан: mechanisms в том же пакете что и contracts; нет foundation-level factory; каждый app руками пишет `@Global() {Svc}ConfigModule.forRoot()` boilerplate.

**Canonical (симметрично gRPC):**

```
packages/config/         — Identity only: Zod schemas + SERVICE catalog + composeSchemas (pure data)
packages/foundation/config/ — Mechanism (НОВОЕ):
  ├─ load-config.ts          — loadConfig<T>() переехал сюда
  └─ create-config-module.ts — factory createConfigModule({ schema, token, narrowPorts })
apps/*/bootstrap/config/ — Assembly: импортируют identity + mechanism, декларативно собирают
```

**Как будет выглядеть app-side:**
```typescript
// apps/audience/src/infrastructure/bootstrap/config/audience-config.module.ts
import { createConfigModule } from '@email-platform/foundation';
import { PERSISTENCE_CONFIG_PORT, CACHE_CONFIG_PORT } from '@email-platform/foundation';
import { AudienceEnvSchema } from './audience-env.schema';
import { AUDIENCE_CONFIG } from './audience-config.constants';

export const AudienceConfigModule = createConfigModule({
  schema: AudienceEnvSchema,
  token: AUDIENCE_CONFIG,
  narrowPorts: [
    { port: PERSISTENCE_CONFIG_PORT, slice: (c) => ({ DATABASE_URL: c.DATABASE_URL }) },
    { port: CACHE_CONFIG_PORT,        slice: (c) => ({ REDIS_URL: c.REDIS_URL }) },
  ],
});
```

Cascade: F-15 сливается с F-16 в одну sub-phase — они трогают те же файлы (packages/config/, packages/foundation/, 4× drizzle.config.ts, 6× {svc}-config.module.ts).
