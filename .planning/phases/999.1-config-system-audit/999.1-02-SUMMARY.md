## Decisions Made

- **Classified F-02 as major (not blocker).** The 3 × `deps.env[KEY] as string` casts operate on already-Zod-validated output — runtime correctness holds; only type-safety transparency fails. A blocker would require a real correctness bug (e.g., vendor code that could misinterpret an unvalidated value). Keeping at major signals "drift from design" without overstating the production risk.
- **Surfaced F-04 + F-06 as I-7.2 interpretation findings rather than omitting.** I-7.2 as written ("No env-key name appears in infra/** that is NOT also in a Zod sub-schema") is literally violated by `NODE_VERSION`, `APP_NAME`, `BUILD_COMMIT`, `BUILD_BRANCH`, `IMAGE_TAG`, `POSTGRES_USER/PASSWORD/DB`, `GARAGE_ADMIN_TOKEN`. These are genuine design-review points for SOLUTIONS — either the invariant needs a "build-tools exception" clause or these keys need Zod schema coverage. Classified both as major because the choice materially affects future schema design.
- **Classified F-05 at major (not blocker) per RESEARCH §1.8 preview.** Dockerfile `ENV PROTO_DIR=/app/proto` duplicates `.env.docker:46` and `.env.docker.example:54`. Current values match → no runtime drift today → not a blocker. Flagged major because "duplicate source of truth" is a canonical DESIGN violation that will drift the moment one side changes without the other.
- **Classified F-12 (.env missing GARAGE_ADMIN_TOKEN) as blocker.** This is the 2026-04-17 UAT env-drift incident that prompted the pre-existing todo — currently breaks native-mode dev whenever someone touches storage features. Real-runtime-impact → blocker per D-01.
- **Split F-12 / F-13 / F-14 as separate L5 findings.** F-12 is the actual drift (key missing); F-13 is the template-governance gap (no mechanism ensures `.env` tracks `.env.example`); F-14 is the tool-coverage gap (`check-env-parity.sh` doesn't compare against `.env.example`). Three distinct root causes — merging would have muddled the SOLUTIONS variants per D-05 (2-4 per finding).
