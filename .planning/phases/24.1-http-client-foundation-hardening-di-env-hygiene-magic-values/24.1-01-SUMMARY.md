## Decisions Made

All decisions in this plan originate from the locked `24.1-CONTEXT.md` (D-01..D-37). No new decisions were introduced during execution. The one amendment surfaced during planning iteration (W-3) was already baked into the plan's acceptance criteria:

- **W-3 (Plan Task 2, amended):** `PinoHttpClientLoggerAdapter` ships with a private `ensureInit(): void` lazy guard from the start. Rationale: the adapter is constructed manually inside `httpClientProvider`'s `useFactory` (Plan 02), so `onModuleInit()` alone would never fire — the lazy guard is required for the manual-construction path.

- **W-2 (Plan Task 1, signature locked):** `CircuitBreakerPort` generic signature matches the refined form `CircuitBreakerPort<TArgs extends unknown[] = unknown[], TReturn = unknown>` (default permissive); `HttpClientDeps.breaker` narrows to `CircuitBreakerPort<[() => Promise<Response>], Response>` — the retry loop is passed as the first `fire()` arg in Plan 02.

- **Verification:** `tsc --noEmit -p packages/foundation/tsconfig.json` exit 0; `tsc -p …` (emit) exit 0; `eslint` on all new files exit 0.
- **Committed in:** `bd448cb`.

**2. [Rule 1 - Bug] OpossumCircuitBreakerAdapter: per-event `on()` calls instead of a loop.**
- **Found during:** Task 2 typecheck.
- **Issue:** The initial draft called `this.breaker.on(ev, fn)` inside a loop where `ev: Transition = 'open' | 'halfOpen' | 'close'`. Opossum's `on()` has narrowly-typed per-event overloads (including `'failure'` with a different listener signature), so TS resolved the union-typed `ev` to the wrong overload (`TS2769: No overload matches this call. Type '"close"' is not assignable to type '"failure"'`).
- **Fix:** Bind each transition explicitly with a literal string event name (`this.breaker.on('open', openFn)`, `'halfOpen'`, `'close'`). Pushed the pairs to `this.listeners` for `dispose()` to clean up later. Behaviour is identical to the looped form.
- **Files modified:** `packages/foundation/src/external/http/circuit-breaker/opossum-circuit-breaker.adapter.ts`.
- **Verification:** typecheck passes.
- **Committed in:** `bd448cb` (same Task 1+2 commit).

**3. [Rule 1 - Bug] `dispose()` uses runtime cast to call `off()`.**
- **Found during:** Task 2 typecheck (follow-on from #2).
- **Issue:** `this.breaker.off(ev, fn)` fails the same overload-selection issue (EventEmitter's `.off` inherits without opossum-level overrides; TS picks the `'failure'` overload). Plain `removeListener` suffers the same problem.
- **Fix:** Runtime cast `(this.breaker as unknown as { off: (ev: string, fn: () => void) => void }).off(ev, fn)` — documented with an inline comment explaining the overload mismatch. Runtime behaviour is standard EventEmitter listener removal. No `any` used (strict type discipline preserved).
- **Files modified:** `packages/foundation/src/external/http/circuit-breaker/opossum-circuit-breaker.adapter.ts` (dispose method).
- **Verification:** typecheck passes; dispose semantics match opossum `.off()` contract.
- **Committed in:** `bd448cb`.

**4. [Rule 3 - Environment] node_modules symlinked from main repo.**
- **Found during:** Before Task 1 commit.
- **Issue:** Worktree (`.claude/worktrees/agent-a340559f/`) has no `node_modules` — `tsc` and `eslint` unavailable for verification. The worktree was created fresh from the feature branch; dependencies were never installed here.
- **Fix:** `ln -s /home/mr/Hellkitchen/workspace/projects/tba-tech/api/email-platform_claude/node_modules ./node_modules` (and same at `packages/foundation/node_modules`). This is filesystem scaffolding, NOT a code change — symlinks are never committed.
