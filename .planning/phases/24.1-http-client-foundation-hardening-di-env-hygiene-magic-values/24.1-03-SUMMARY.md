# Phase 24.1 Plan 03: Vendor Adapter Migration + HttpSmokeClient Split + Foundation Barrel Closure Summary

**Migrated 3 per-vendor HTTP clients (Telegram, AppStoreSpy, CloudFn) to the Phase 24.1 param-bag + httpClientProvider shape, split HttpSmokeClient into a production-reachable client (infrastructure/) and a test-only controller+module (test/ with TODO(remove-before-release) markers), extracted HTTP_SMOKE_DEFAULTS magic values + introduced a status(code) path builder, standardised HttpSmokeController return types on the exported CircuitState, and finalised the foundation barrel by removing the Plan 02 HTTP_CLIENT_DEFAULTS compat bridge. 4 non-null assertions eliminated; workspace typecheck + build + lint green; `scripts/check-no-bang.sh` reports PASS across all 5 HTTP-adjacent paths.**

## Accomplishments

- All 4 per-vendor HTTP adapter modules (telegram / appstorespy / cloudfn / http-smoke) now route through `httpClientProvider({...}, (deps) => new Client(deps, ...))` — no hand-written `useFactory: (config, cls) => new Client(cls, baseUrl, timeout, cbOpts, logCtx, secret)` boilerplate remaining anywhere in the workspace.
- Zero `config.get<T>(KEY)!` non-null assertions across the 5 HTTP surface paths (`scripts/check-no-bang.sh` exits 0). The 4 previously-assertive calls now go through native `ConfigService.getOrThrow<string>(KEY)` — either inside `httpClientProvider` (for `BASE_URL` values, via `baseUrlEnvKey`) or inside the per-vendor `build` callback (for vendor secrets like `TELEGRAM_BOT_TOKEN`, `APPSTORESPY_API_KEY`, `CLOUDFN_API_KEY`).
- Per-vendor modules shrunk from ~40 lines with hand-written `clientProvider: Provider` blocks to 24–30 lines with a single `httpClientProvider(...)` call. Constructor signatures reduced from 6 args (`cls`, `baseUrl`, `defaultTimeoutMs`, `cbOptions`, `logContext`, `vendorSecret`) to 2 (`deps`, `vendorSecret`).
- `HttpSmokeClient` is now a production-reachable artifact at `apps/gateway/src/infrastructure/clients/http-smoke/http-smoke.client.ts` — the test-only HttpSmokeController+HttpSmokeModule that currently drive it live at `apps/gateway/src/test/http-smoke/` under a `TODO(remove-before-release)` fence. When the `test/` subtree is deleted, the client itself survives for a future phase (admin diagnostic / health probe / baseline) to consume.
- `HTTP_SMOKE_PATH.status` is now a function builder (`(code) => `/status/${code}``) — the `STATUS: '/status'` prefix-hack plus caller-side concatenation (`` `${HTTP_SMOKE_PATH.STATUS}/${code}` ``) is gone. `HTTP_SMOKE_DEFAULTS` gained `ERROR_PREVIEW_CHARS: 200` and `DEFAULT_PROBE_STATUS: '500'` to absorb the 3 `String(err).slice(0, 200)` occurrences and 1 `@Query('code') code = '500'` default in the controller.
- `HttpSmokeController.state()`, `.probe()`, and `.burstFail()` return types now reference the exported `CircuitState` type instead of the 4x-duplicated inline `{ cb: 'closed' | 'halfOpen' | 'opened'; consecutiveFailures: number }` literal.
- `packages/foundation/src/external/http/index.ts` is final D-16/D-17 shape — the `TEMPORARY COMPAT BRIDGE — REMOVE AT END OF PLAN 03` block and its two private imports (`_RETRY`, `_CB`) are deleted. No code anywhere in the workspace (`apps/`, `packages/`, excluding dist/ output) references `HTTP_CLIENT_DEFAULTS`.
