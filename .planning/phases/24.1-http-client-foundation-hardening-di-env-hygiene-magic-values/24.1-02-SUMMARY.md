## Accomplishments

- AbstractHttpClient reduced from 240 lines (God class) to 112 lines (thin orchestrator). The `request()` method is five lines of delegation: `breaker.fire(() => retry.run(() => executor.execute()))`.
- Param-bag `HttpClientDeps` constructor replaces the 5-arg positional constructor of Phase 24 — all collaborators in a single typed object.
- Zero lifecycle hooks in AbstractHttpClient. `PinoLogger.root.child(...)` (Pitfall 6) lives inside the logger adapter's `ensureInit()` lazy guard (Plan 01 Task 2), so manually-constructed adapters inside `httpClientProvider.useFactory` stay safe.
- `httpClientProvider(opts, build)` factory wires fresh per-vendor collaborators (logger, normaliser, executor, retry, breaker) — preserves per-vendor CB isolation from Phase 24 (D-08).
- Both env-driven `baseUrlEnvKey` (via native `ConfigService.getOrThrow<string>()`) and literal `baseUrlLiteral` (for smoke-test clients) supported — Plan 03 will exercise both paths.
- Barrel exposes only the D-16 consumer-facing API: `AbstractHttpClient`, `HttpClientDeps`, `httpClientProvider` + opts, port types, `CircuitState`, `HTTP_CLIENT_HEADERS`, `RETRY_DEFAULTS`, `CB_DEFAULTS`, all 5 error classes + `HttpClientError` base + `HttpClientErrorKind`, `HTTP_CLIENT_LOG`.
- Internal symbols kept file-local per D-17: DI tokens, adapter classes (HttpRequestExecutor, DefaultRetryExecutor, OpossumCircuitBreakerAdapter, PinoHttpClientLoggerAdapter), HttpErrorNormalizer, concrete mappers, and 4 internal constants (TIMEOUT_ERR_NAMES, IDEMPOTENT_METHODS, RETRYABLE_STATUS_MIN, CB_BREAKER_OPEN_MESSAGE_SUBSTRING).
- Temporary `HTTP_CLIENT_DEFAULTS` compat bridge composed from `RETRY_DEFAULTS + CB_DEFAULTS + { TIMEOUT_MS: 5000 }` keeps per-vendor modules green during the Plan 02 → Plan 03 window. Clearly marked `// REMOVE AT END OF PLAN 03`.
- All 6 pre-24.1 root-level files deleted via `git rm`. Only `di-tokens.ts` and `index.ts` remain at the `external/http/` root.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] RETRY_DEFAULTS name collision in external/index.ts**
- **Found during:** Task 3 (barrel rewrite) — foundation build failed with `TS2308: Module './http' has already exported a member named 'RETRY_DEFAULTS'`.
- **Issue:** The new HTTP barrel re-exports `RETRY_DEFAULTS` (from `retry/constants.ts`) per D-16 contract. A pre-existing export of the same name lives at `resilience/retry-connect.ts:7` (an unrelated legacy connect-retry helper). Both flow through `external/index.ts` via `export *`, causing ambiguity at compile time.
- **Fix:** Disambiguated at `external/index.ts` — the legacy `resilience/retry-connect` constant is now re-exported as `CONNECT_RETRY_DEFAULTS` while the HTTP one keeps the plain name (which is what the D-16 contract specifies). The legacy constant is only used internally by `retryConnect()` itself, so no app code breaks.
- **Files modified:** `packages/foundation/src/external/index.ts` (replaced `export * from './resilience/retry-connect'` with an explicit named re-export list that renames `RETRY_DEFAULTS` to `CONNECT_RETRY_DEFAULTS`).
- **Verification:** `pnpm --filter @email-platform/foundation build` exit 0; `pnpm typecheck` exit 0 across all 12 workspace packages.
- **Committed in:** `d9630b9` (Task 3 commit).

**2. [Rule 3 - Environment] node_modules symlinked from main repo**
- **Found during:** Before Task 1 build attempt — worktree has no `node_modules` (fresh worktree, never installed).
- **Fix:** Symlinked each workspace package's `node_modules` from the main repo:
  - `./node_modules` → main repo root
  - `packages/foundation/node_modules` → main repo's foundation local node_modules (preserves `.bin/tsc`)
  - `packages/config/node_modules`, `packages/contracts/node_modules` → main repo equivalents
  - `apps/{gateway,auth,audience,notifier,parser,sender}/node_modules` → main repo equivalents
- **Files modified:** None (symlinks are not committed; they are environment scaffolding).
- **Verification:** `pnpm --filter @email-platform/foundation build` and `pnpm typecheck` now run successfully against the same dependency graph as the main repo. Initial attempt with `./node_modules` pointing at the root worked for most packages, but `packages/foundation/node_modules` had to point at the main repo's foundation-local node_modules directly (where tsc's `.bin` link lives).
- **Committed in:** N/A — not code, not committed.
