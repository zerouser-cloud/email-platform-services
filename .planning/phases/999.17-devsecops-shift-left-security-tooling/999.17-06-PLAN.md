<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer staged diff ↔ gitleaks scanner (Docker container) | Staged file content piped to gitleaks via git pre-commit protocol; container has read-write access to repo via `-v $(pwd):/repo` mount |
| Docker daemon ↔ gitleaks container | Container runs with default Docker isolation; no `--privileged`, no socket mount, no host network |
| package.json `security:*` scripts ↔ Docker registry (docker.io/zricethezav/gitleaks) | Image fetched at first run; subsequent runs from local cache. Image integrity via Docker registry signing |
| .husky/pre-commit ↔ git core.hooksPath | husky 9 sets `core.hooksPath = .husky/_`; the `_` directory contains the wrapper that invokes our hook file |
| developer machine git operations ↔ pre-commit hook | Hook can be bypassed via `git commit --no-verify` — accepted by D-04 (Layer A is UX, CI is enforcement) |
