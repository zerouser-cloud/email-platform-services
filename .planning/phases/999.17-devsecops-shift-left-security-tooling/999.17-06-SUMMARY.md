## Decisions Made

- **Tag pin level — patch, not major.minor.** Plan called for `v8.30` major.minor pin per D-14 + D-16. Docker Hub registry only publishes full SemVer tags; `v8.30` does not resolve. Closest valid pin within the same minor is `v8.30.1` (the latest patch in v8.30 — confirmed by `curl https://registry.hub.docker.com/v2/repositories/zricethezav/gitleaks/tags`). v8.30.0 is older. v8.30.1 honors the spirit of D-14 + D-16 (reproducible builds, no surprise upstream changes) — patch updates within a minor are CVE/feed updates, which is what the relaxed "minor pin" wanted to allow. This DOES tighten the pin (no patch updates without explicit code review), but tightening pin direction is fail-safe for security tooling. Tag bumps now require a 1-character edit + code review — same operational cadence the plan envisioned.
- **No `--redact` flag added** (per plan §HARD CONSTRAINTS Task 1): un-redacted stderr is acceptable for local debugging; CONTEXT.md mandates rotation on any local leak. Plan 09 (DEVOPS-HANDOFF.md) will recommend `--redact` for CI tier where logs may be aggregated.
- **Insertion point = between `docker:down` and `prepare`**: groups `security:*` entries together below transport scripts, keeps `prepare: husky` as the last entry (npm `prepare` lifecycle convention).

## Issues Encountered

- **Behavioral smoke (fake-AWS-key fixture commit) inconclusive in git-worktree mode.** Inside a git worktree, `.git` is a `gitdir:` pointer file (not a directory). The gitleaks Docker container, bind-mounting only `$(pwd)`, cannot follow that pointer to the actual repo metadata at `<root>/.git/worktrees/agent-*`. Outcome: gitleaks reports `0 commits scanned`, `no leaks found`, exit 0 — with a stderr `fatal: not a git repository` log. This is a worktree-mount edge case, NOT a hook defect. In a normal (non-worktree) checkout, `.git/` is a real directory inside the bind mount and gitleaks operates correctly.
- **Mitigation:** Behavioral smoke was best-effort per plan acceptance criteria. All deterministic acceptance criteria for Task 1 + Task 2 passed. The hook will function correctly when developers commit on the merged main branch (non-worktree). The same edge case is documented for Plan 09 (DEVOPS-HANDOFF.md) — CI runners use full clones, not worktrees, so CI tier is unaffected.
- **First-run Docker pull duration:** ~5–8 seconds for the v8.30.1 image (4 layers, 50.3 MB total) on a warm-network developer machine. Image fully cached after first run. This anchors the latency table for Plan 09 DEVOPS-HANDOFF.md: cold = ~5–8 s on this hardware (developer M-class, fiber link); warm cache = sub-second startup; well within the <5 s D-01 budget.
