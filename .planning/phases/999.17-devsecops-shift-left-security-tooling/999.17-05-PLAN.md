<objective>
Create `.trivyignore` (suppression baseline — empty body + RULES header) at repo root.

Purpose: foundation for Plan 07 (pre-push `trivy config` static Dockerfile/compose scan). The suppression baseline establishes audit-trail discipline (per-entry comment with reason/ticket/expiration date) preventing D-09's abuse failure mode. Trivy auto-loads `.trivyignore` from the working directory at scan time — no config file or CLI flag is needed.

**Why no `.trivy.yaml`:** per D-06 + RESEARCH §Trivy, this phase scopes Trivy to `config` mode only (static Dockerfile/compose linting; no CVE feed). A `.trivy.yaml` file would be redundant for the in-scope mode and risks scope creep into `fs`/`image` modes (D-06 OUT-OF-SCOPE).
