## Decisions Made

1. **`config:recommended` over `config:base`** — RESEARCH §Pitfall 7 documented Renovate v36+ rename; `config:base` triggers deprecation warnings on the dashboard. D-08 originally said `config:base` but RESEARCH corrected this; plan explicitly directed `config:recommended`.
2. **`automerge: false`** — D-08 explicit conservative posture. Every security PR is reviewed by a human on first activation. Tuning (selective automerge for trusted patch updates) deferred per CONTEXT §Deferred Ideas; re-evaluate after first DevOps activation cycle.
3. **`osvVulnerabilityAlerts: true` despite RESEARCH §A11 GA-status uncertainty** — even if Renovate runtime warns "experimental", the worst case is a noisy log line; the upside is OSV.dev malicious-package detection (T-99917-08-01 primary mitigation). Threat-model net-positive.
4. **`minimumReleaseAge: "14 days"`** — RESEARCH §Pattern 6 supply-chain best practice. Two weeks is the empirically-observed window in which the npm/registry community typically identifies and flags malicious packages.
5. **`postUpdateOptions: ["pnpmDedupe"]`** — project uses pnpm 11 (Plan 01); ensures Renovate updates don't accumulate duplicate transitive dependencies in `pnpm-lock.yaml`.
6. **Monorepo grouping for `apps/**` + `packages/**`** — matches actual structure (`apps/{gateway,auth,sender,parser,audience,notifier}` + `packages/{config,foundation,contracts}`). Single `"monorepo internal"` group prevents 9-way PR fan-out.
7. **No environment branching, no defaults outside the config** — Renovate field names + preset IDs are tool-specific values dictated by the Renovate library; per `no-magic-values` skill they live in `renovate.json` as the canonical, version-controlled source. Schedule strings (`"before 3am on Monday"`) are tool-domain literals, not application magic values.
8. **Bot DORMANT per D-08** — explicit non-activation in this phase. No `.github/workflows/renovate.yml`, no `.gitlab-ci.yml` Renovate stage. Activation requires DevOps to install GitHub App OR run self-hosted GitLab Renovate runner; same `renovate.json` works on both (CI-platform-portable, project requirement per GitLab migration plan).
