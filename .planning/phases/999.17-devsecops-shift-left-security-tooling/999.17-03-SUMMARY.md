### `.gitleaksignore` (full body)

```
# Phase 999.17 — gitleaks suppression baseline. Body intentionally empty.
# See .planning/phases/999.17-devsecops-shift-left-security-tooling/.
#
# .gitleaksignore — fingerprints of secret findings to ignore.
#
# FORMAT:  <commit-sha>:<file-path>:<rule-id>:<line-number>
# EXAMPLE: cd5226711335c68be1e720b318b7bc3135a30eb2:apps/auth/test/fixture.ts:generic-api-key:42
#
# RULES:
# 1. Every entry MUST have a comment line above it explaining WHY it is ignored.
# 2. Comment must include: (a) reason it's a false positive OR (b) ticket
#    link if it's an accepted risk, AND (c) re-evaluate-by date if accepted.
# 3. Secrets are ALWAYS preferred to be rotated, not ignored. Add an entry
#    here only after rotation is impossible AND the value is verified to be
#    a fixture / test data / non-production.
# 4. Empty file = clean state. Do not add entries proactively.
```

## Decisions Made

- **Default rules over custom regexes** (T-99917-03-02 mitigation): gitleaks ships ~150 community-audited patterns. RESEARCH §Don't Hand-Roll mandates zero custom rules at this stage. Rationale: maintenance burden + false-negative risk of self-built regexes outweighs any marginal coverage gain.
- **Allowlist scope constrained to file-extension regex** (T-99917-03-03 accepted): `(jpg|gif|doc|pdf|bin|svg|socket)` covers binary fixtures only. Documented in `description` field. Future additions require comment-justified entries (file format conventions in PATTERNS §SP-4).
- **Suppression baseline empty by design** (D-09): Adding example entries upfront would normalize the abuse mode the file is meant to prevent. Header-only enforces the "comment-above + rotate-not-suppress" discipline before any real entry exists.
