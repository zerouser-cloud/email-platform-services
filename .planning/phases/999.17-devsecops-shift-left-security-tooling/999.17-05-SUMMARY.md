## Decisions Made

- **D-09 applied:** Empty `.trivyignore` body with FORMAT / RULES / EXAMPLE header. Every future entry requires a comment with (a) reason, (b) ticket / issue link, (c) re-evaluate-by date. Code review enforces; baseline starts clean.
- **D-06 applied:** Explicit non-creation of `.trivy.yaml`. The in-scope `config` mode is fully driven by CLI flags (`--severity HIGH,CRITICAL --exit-code 1 .`) which live in Plan 07's `security:trivy-config-if-changed` npm-script. A `.trivy.yaml` would risk accidental enablement of the OUT-OF-SCOPE `fs` / `image` modes (which require ~1 GB CVE feed and would break the sub-30s pre-push budget).
- **Trivy auto-discovery contract:** Per Trivy docs, `.trivyignore` is auto-loaded from the directory where `trivy` is invoked when the file name is exactly `.trivyignore`. Plan 07 invokes `trivy config ... .` from repo root, so no `--ignorefile` flag is needed.
