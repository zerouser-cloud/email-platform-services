## Decisions Made

1. **Option B (delete) over Option A (anchored regex).** Plan-prescribed; rationale carried verbatim from `<objective>`:
   - Minimal surface area (no regex to mis-write).
   - Honors `.gitleaks.toml` preamble's own design intent (only add rules unique to this codebase).
   - `useDefault = true` already covers binary paths via gitleaks community-audited defaults.
   - Safer fail-mode (auto-inherits future default-config updates).
   - No real binary files at risk in this repo right now.
   - Option A documented in `<interfaces>` as the alternative if a future binary-file false-positive surfaces.

2. **Plan-defect substitution: fake AWS key `<aws-access-key-redacted>` (AWS-docs canonical) → `<aws-access-key-redacted>` (executor-recommended).** During Step B, all four fixtures using the planner's chosen literal returned exit 0 (`no leaks found`). Diagnostic showed gitleaks v8.30.1 default ruleset hard-codes the AWS-docs canonical literal as a known docs-canonical placeholder (it lives in gitleaks' built-in `aws-access-token` rule's allowlist). Substituting the executor-recommended literal (different middle letters, NOT in built-in allowlist) produced exit 1 with `aws-access-token` finding on all four paths. Documented as Deviation #1 below.

3. **Step D adaptation: `git worktree add` → `git clone --local --no-hardlinks`.** The plan's Step D used `git worktree add` to create an isolated test environment. At execution time, 11 active GSD parallel worktrees were registered against the shared `.git/`; an additional worktree-add risked branch-name conflicts and would have polluted the shared worktree state. A local clone (`git clone --local --no-hardlinks`) provides equivalent isolation without touching shared git state. Documented as Deviation #2 below.
