<decisions>
## Implementation Decisions

### Layer 1 — Source (workspace + host-dev lifecycle)

- **FR-01: Drop husky entirely.** Удалить `husky` из `devDependencies` в root `package.json`. Удалить директорию `.husky/`. Удалить `prepare` script из root `package.json`.
- **FR-02: `.githooks/` как канонический host-dev механизм.** Создать `.githooks/pre-commit` + `.githooks/pre-push` с содержимым existing husky hooks (security:pre-commit + security:pre-push из Phase 999.17).
- **FR-03: `pnpm setup-hooks` — explicit ergonomic step.** Script `setup-hooks` = `git config core.hooksPath .githooks`. Документировать в `README.md` / `CONTRIBUTING.md` как "After clone: `pnpm install && pnpm setup-hooks`".
- **FR-04: Pattern E preserved.** `packages/tsconfig-base/` workspace tsconfig pattern (D-09 из 999.18.3 iter 5) сохраняется verbatim.

### Layer 2 — Orchestration

- **FR-05: Turborepo retain.** Pragmatic-accept на N=6 services horizon. Никакого orchestrator swap (не Bazel, не Buck2, не Nx). RE-EVAL триггеры (T-ORCH-01..T-ORCH-04) активны для будущего пересмотра.

### Layer 3 — Packaging (Dockerfile)

- **FR-06: Two-install Vercel canonical pattern.** Dockerfile = 4 стадии:
  - **Stage 1.1 pruner:** `pnpm dlx turbo prune --docker --scope=@email-platform/${APP_NAME}` → produces `/app/out/json` (manifests-only) + `/app/out/full` (source).
  - **Stage 1.2 prod-deps:** `COPY --from=pruner /app/out/json ./` + `pnpm install --prod --frozen-lockfile` (только prod deps; БЕЗ dev → БЕЗ husky leak).
  - **Stage 1.3 builder:** `COPY --from=pruner /app/out/full ./` + `pnpm install --frozen-lockfile` (full) + `pnpm exec turbo run build --filter=@email-platform/${APP_NAME}`.
  - **Stage 2 runner:** `gcr.io/distroless/nodejs22-debian12:nonroot` (user 65532) + `COPY --from=prod-deps /app/node_modules ./node_modules` + `COPY --from=builder /app/apps/${APP_NAME}/dist ./dist` + `CMD ["dist/main.js"]` (exec-form).
- **FR-07: Distroless runner.** Default = `gcr.io/distroless/nodejs22-debian12:nonroot`. Chainguard/Wolfi — defer alternative оценка к 999.18.4 если нужна.
- **FR-08: `ENV PNPM_HOME=/pnpm` preserved.** D-08 из iter 5 сохраняется в обеих install stages (1.2 prod-deps + 1.3 builder) для cache-mount alignment с pnpm 11 default store.
- **FR-09: Zero kostyls в Dockerfile.** Запрещены:
  - `pnpm prune --prod` post-build (causes husky lifecycle re-run per pnpm bug #7068)
  - `ENV CI=true` (L3 layer leak)
  - `ENV HUSKY=0` (escape hatch — но нет husky → нет fence нужен)
  - `pnpm deploy --legacy --prod` (escape hatch к deprecated path)
  - `--ignore-scripts` (blanket disable, не targeted)
  - `injectWorkspacePackages: true` (per ADR (b) M3 architectural-eliminate)
  - orphan fetcher stage (BuildKit DAG-prunes)
  - `rm -rf node_modules` patterns
- **FR-10: `ENV PROTO_DIR=...` removed from Dockerfile.** PROTO_DIR живёт ТОЛЬКО в `.env.docker` (single source of truth) per F-05 closure из 999.18.1.
- **FR-11: Non-root user в runner.** Distroless `:nonroot` тэг (user 65532). USER directive ordering per DOCKERFILE-REFERENCE I-S2.1/I-S2.2.

### Layer 4 — Pipeline (CI/CD)

- **FR-12: GitLab CI = canonical CI.** Source of truth = `.gitlab-ci.yml` (новый файл, draft в Plan 08). Per `project_gitlab_migration` + `project_hosting_infra` memory.
- **FR-13: 3-stage layout.** `build → push → deploy`. K8s deploy mechanism (Helm vs Kustomize vs ArgoCD) — design step внутри Plan 08, через plan-phase researcher.
- **FR-14: security:\* scripts = required pipeline jobs.** Все 8 npm-scripts из Phase 999.17 (`security:pre-commit`, `security:pre-push`, `security:secrets-staged`, `security:typecheck`, `security:env-parity`, `security:semgrep-diff`, `security:audit-if-lock-changed`, `security:trivy-config-if-changed`) запускаются как required jobs.
- **FR-15: Branch protection.** `main` requires MR + passing pipeline. Server-side enforcement = canonical security layer (per React/Astro empirical pattern).
- **FR-16: Substitutability rule.** Pipeline invokes ТОЛЬКО `pnpm <script>` + `docker buildx`. НЕ embeds build logic в `.gitlab-ci.yml` per `feedback_use_package_scripts`.
- **FR-17: Multi-arch.** `docker buildx` + `setup-qemu-action` runner-agnostic per `project_multiarch_runner_agnostic`. Survives GitHub Actions → GitLab CI migration.

### Layer 5 — Verification

- **FR-18: `scripts/verify-*` = canonical L5 entry.** `pnpm verify:image-determinism` + `pnpm verify:injection-extinct` + `pnpm verify:multiarch` + `pnpm verify:per-service-smoke` (Wave 0 999.18.1 outputs) reused as-is.
- **FR-19: Dual-mode runtime smoke = phase gate.** `pnpm start:native` :3000/health/ready + `pnpm start:isolated` :4000/health/ready — обе зелёные = phase gate per `runtime-smoke-verification` skill.
- **FR-20: Post-deploy K8s gates.** `kubectl rollout status` + readiness probe gates после Plan 08 wiring. Concrete mechanism finalize в Plan 08 design step.
