## What was empirically verified during Iteration 7 (this session)

1. **husky 9.1.7 source code** read locally (`node_modules/husky/index.js` line 8): `if (!f.existsSync('.git')) return ".git can't be found"` — husky has internal `.git` safeguard but only fires AFTER binary execution. Doesn't help when binary itself is missing (Stage 1.2 prod-deps case).

2. **pnpm bug #7068** (https://github.com/pnpm/pnpm/issues/7068): pnpm STILL runs `prepare` script on `--prod` install. Open, no fix planned. **Confirms** that two-install pattern + husky `prepare` script = broken.

3. **MAANG public repos** (verified via raw.githubusercontent.com WebFetch):
   - **React (Meta) package.json** — NO husky, NO prepare script, NO local hooks. Relies on CI.
   - **Astro package.json** — NO husky, NO prepare, NO local hooks. Relies on CI.
   - **Microsoft VS Code** — has husky (^0.13.1, stale) but NO prepare script.
   - **Vercel Turborepo + Next.js** — have husky + standard `"prepare": "husky"` (the broken pattern we're escaping).
   - **Conclusion:** drop-husky-entirely IS the empirically-canonical MAANG-aligned pattern (React/Astro confirmed).

4. **Atlassian/GitHub Engineering canonical pattern** (verified via WebFetch + WebSearch): server-side enforcement (CI required pipelines + branch protection) is the actual security layer. Local hooks = convenience.
