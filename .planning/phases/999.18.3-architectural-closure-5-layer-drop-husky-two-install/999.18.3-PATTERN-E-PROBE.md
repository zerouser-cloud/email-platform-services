## 4. Latent Issues Catalogue

1. **`pnpm prune --prod` TTY failure (UNRELATED to Pattern E).** Builder hit `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` at line 95-96 production Dockerfile — pre-existing pnpm 11 Docker quirk (reproduces и без Pattern E). **Не блокирует** — TS build уже PASS до этого шага. Mitigation: `ENV CI=true` или `confirmModulesPurge=false` перед `pnpm prune --prod`. Track как separate item.

2. **`moduleResolution: "node16"` + bare-specifier `extends` works.** TS 5.0+ resolves через Node.js package resolution; `package.json` без `exports` map → fallback на direct file path lookup. `files: ["tsconfig.json"]` exposed. Verified в 4/4 Docker builds + host typecheck.

3. **pnpm symlink mode (default, без `node-linker=isolated` в `.npmrc`).** `apps/auth/node_modules/@email-platform/tsconfig-base/` resolves через symlink. TS follows symlinks для `extends`. Worked в host + Docker `pnpm install --frozen-lockfile`.

4. **`generate.sh` independent.** Proto codegen reads `pnpm bin` для `protoc-gen-ts_proto`; никаких ссылок на tsconfig.base. Turbo `generate` task depends on `proto/**/*.proto` + lockfile only.

5. **`apps/*/tsconfig.build.json` unchanged.** Extends `./tsconfig.json` (relative), не корневой base — Pattern E их не трогает. `nest build` отрабатывает.

6. **No self-reference cycle.** `packages/tsconfig-base/package.json` не extends ничего, не имеет deps на себя.
