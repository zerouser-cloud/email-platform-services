**Note re kustomize binary:** `bitnami/kubectl:1.30` does NOT bundle the standalone `kustomize` CLI. Two options:
  - Option A (chosen above): one-shot install via curl in `before_script` (idempotent — `command -v` guard).
  - Option B: switch to `bitnami/kubectl:1.30-debian-12-r0` + sidecar tool image — overkill.
  - Option C: use `kubectl kustomize` (built-in since 1.14) — but `kustomize edit set image` (substitution) is a `kustomize`-binary-only feature, not exposed through `kubectl kustomize`. Therefore curl-install is the minimum path.

Substitutability rule (FR-16) preserved: pipeline invokes ONLY pinned vendor CLIs (`kubectl`, `kustomize`, `bash`, `apt-get`, `curl`). No embedded shell-build-logic. The for-loop is canonical Kustomize substitution per <https://kubectl.docs.kubernetes.io/references/kustomize/cmd/edit/setimage/>.

### Target shape для `deploy/k8s/overlays/dev/kustomization.yaml`:

The image references in `images:` MUST stay as `registry.example.com/email-platform-{svc}` placeholders **so that `kustomize edit set image` from the pipeline can rebind them**. Do NOT change to `$CI_REGISTRY_IMAGE` — Kustomize does NOT resolve env vars in `kustomization.yaml`. The CI step substitutes them.

**However:** the `newTag: latest` per-image stanza is the actual concern — it doesn't matter if `kustomize edit set image` overrides it, but having `latest` as fallback creates ambiguity. Replace `newTag: latest` with explicit comments.

Decided pattern (per CR-01 fix):

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: email-platform-dev

resources:
  - ../../base

# Image references: placeholder names matching base/*.yaml `image:` fields.
# CI overrides via `kustomize edit set image registry.example.com/email-platform-{svc}=${CI_REGISTRY_IMAGE}/email-platform-{svc}:${CI_COMMIT_SHORT_SHA}`
# (see .gitlab-ci.yml deploy-dev for substitution loop).
# Manual local apply requires running the same command before `kubectl apply -k`.
images:
  - name: registry.example.com/email-platform-gateway
    newName: registry.example.com/email-platform-gateway
    newTag: dev-placeholder
  - name: registry.example.com/email-platform-auth
    newName: registry.example.com/email-platform-auth
    newTag: dev-placeholder
  - name: registry.example.com/email-platform-sender
    newName: registry.example.com/email-platform-sender
    newTag: dev-placeholder
  - name: registry.example.com/email-platform-parser
    newName: registry.example.com/email-platform-parser
    newTag: dev-placeholder
  - name: registry.example.com/email-platform-audience
    newName: registry.example.com/email-platform-audience
    newTag: dev-placeholder
  - name: registry.example.com/email-platform-notifier
    newName: registry.example.com/email-platform-notifier
    newTag: dev-placeholder
```

`dev-placeholder` (вместо `latest`) делает grep `'newTag: latest'` zero, что является fail-loud canary: «эти image references обязаны быть substituted CI-ем перед apply».
