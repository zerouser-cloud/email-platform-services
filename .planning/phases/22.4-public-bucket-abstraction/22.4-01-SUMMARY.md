# Phase 22.4 Plan 01: Foundation contracts for public bucket abstraction — Summary

## One-liner

Foundation теперь экспортирует `NamespacedStoragePort` + `SharedNamespaceModule.forNamespace(...)` поверх единого `public` bucket'а с multipart-upload через `@aws-sdk/lib-storage` и inline size-counter, плюс два новых env var (`STORAGE_PUBLIC_URL`, `STORAGE_MAX_UPLOAD_BYTES`) — всё без presigner.

## What Was Built

### Task 1 — Deps swap + rename (commit `4429a90`)

1. **Dependency rotation** в `packages/foundation/package.json`:
   - Удалён `@aws-sdk/s3-request-presigner`
   - Добавлен `@aws-sdk/lib-storage@^3.1030.0`
   - `@aws-sdk/client-s3` поднят до `^3.1030.0` (lockstep с lib-storage)

2. **Type rename**: `interface StoragePort` → `interface PrivateStoragePort`, метод `getSignedUrl(key, expiresInMs)` удалён из интерфейса и реализации.

3. **Module rename**: `BucketStorageModule` → `PrivateStorageModule` (файл `private-storage.module.ts`); `forBucket(opts)` API сохранён 1:1.

4. **Transient update**: `public-storage.module.ts` (22.5 facade) переключён на `PrivateStorageModule` (BucketStorageModule больше не существует). Сам facade остаётся на диске до Plan 02 (barrel уже не реэкспортит — см. Task 2).

### Task 2 — SharedNamespaceModule + env schema (commit `9a66fe9`)

Создано шесть новых файлов под `packages/foundation/src/external/storage/public/`:

- `namespaced-storage.interface.ts` — `NamespacedStoragePort` + `NamespaceOptions` types.
- `shared-namespace.module.ts` — `SharedNamespaceModule.forNamespace({namespace, contentType, token})` фабрика. Импортирует `ConfigModule` + `S3CoreModule`. Provider собирается через `useFactory` с `S3_CLIENT` + `ConfigService`.
- `namespaced-storage.service.ts` — реализация: key `{ns}/{uuid}/{sanitizedFilename}`, body прокачивается через `SizeCountingTransform` в `new Upload({...}).done()`; URL собирается `buildPublicUrl` (D-14 amended).
- `size-counting.transform.ts` — pass-through `Transform`, cumulative byte count > `max` → `cb(StorageUploadTooLargeError)` → Upload auto-abort.
- `upload-too-large.error.ts` — ошибка с `seen`/`max` readonly полями.
- `public-url.builder.ts` — `buildPublicUrl(base, _bucket, key)` (bucket в hostname per D-28/D-29, поэтому в URL не участвует) + `sanitizeFilename`.

Расширена `packages/foundation/src/external/storage/public/public.constants.ts`:
- `SHARED_REPORTS = Symbol('SHARED_REPORTS')`
- `PUBLIC_URL`, `UPLOAD_DEFAULTS`, `CONTENT_TYPE`, `FILENAME_SANITIZE` как `as const` объекты.
- Существующие `PUBLIC_STORAGE`, `PUBLIC_STORAGE_HEALTH`, `PUBLIC_BUCKET`, `PUBLIC_HEALTH_KEY` сохранены (Plan 02 решит их судьбу).

Обновлён barrel `packages/foundation/src/external/storage/public/index.ts` — убран реэкспорт `./public-storage.module`, добавлены новые. Файл `public-storage.module.ts` физически остаётся на диске (удаляется в Plan 02 Task 1).

В `packages/config/src/schemas/storage.ts` добавлены:
```ts
STORAGE_PUBLIC_URL: z.string().url(),
STORAGE_MAX_UPLOAD_BYTES: z.coerce.number().int().positive(),
```
Без `.default()`, без `.optional()`, без `?? fallback` — per env-schema skill.
