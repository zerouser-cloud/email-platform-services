# Phase 22.4: public-bucket-abstraction — Research

**Researched:** 2026-04-14
**Domain:** S3-compatible storage abstraction — public/private bucket split, multipart streaming upload, anonymous read policies on MinIO vs Garage
**Confidence:** HIGH on AWS SDK / MinIO. **MEDIUM–LOW on Garage URL shape** — one locked decision (D-14 path-style `/public/${key}`) is **architecturally inconsistent with Garage's actual capabilities**; flagged explicitly in Open Questions.

## Summary

All 27 decisions in CONTEXT.md are sound individually and align with the established per-service composition pattern from Phase 22.1. The stack is narrow and canonical: `@aws-sdk/lib-storage.Upload` for multipart streaming, `node:crypto.randomUUID()` for v4 keys, a `Transform` stream for size-limit enforcement, `mc anonymous set download` on MinIO, and `garage bucket website --allow` on Garage.

**One critical gap found by research:** D-14 specifies public URL format `${STORAGE_PUBLIC_URL}/public/${key}` (path-style via a single hostname). MinIO serves this trivially on its S3 API port after `mc anonymous set download`. **Garage does not support anonymous GET on its S3 API endpoint at all** `[CITED: garagehq.deuxfleurs.fr issue #263]` — the only mechanism for anonymous access is the separate web endpoint (port 3902), which serves **virtual-hosted-style only** (`https://public.{web-root-domain}/{key}`). Two different URL shapes per backend. The locked format works for MinIO but cannot be produced by Garage without an external reverse-proxy rewrite. This is surfaced as an Open Question — not challenged as a decision, but flagged because the planner must decide between (a) path rewriting at reverse proxy, (b) accepting per-env difference in `STORAGE_PUBLIC_URL` values (Garage gets `https://public.files.email-platform.pp.ua` without `/public` suffix), or (c) revisiting D-14 with the user.

**Primary recommendation:** Proceed with the locked architecture. Use `@aws-sdk/lib-storage.Upload` with a `PassThrough`-based size counter. Enforce content-type at PutObject time only (no ACL knobs available on either backend). For URL format, plan tasks should **treat `STORAGE_PUBLIC_URL` as the full-base-URL-including-bucket-path-or-subdomain** — the env var absorbs the backend difference, keeping code 12-factor clean. Final call on per-env env values goes to operator via the runbook.

### Pattern 1 — Factory DynamicModule (mirrors `BucketStorageModule.forBucket`)

**What:** Public factory takes options object, returns `DynamicModule` with Symbol-keyed providers.

**When:** Every time a service binds a `public` namespace. One call per namespace+contentType pairing.

**Example:**

```ts
// packages/foundation/src/external/storage/public/shared-namespace.module.ts
// Source: mirrors existing packages/foundation/src/internal/storage/bucket-storage.module.ts
import { Module, type DynamicModule } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import type { S3Client } from '@aws-sdk/client-s3';
import { S3_CLIENT, S3CoreModule } from '../../../internal/storage';
import { PUBLIC_BUCKET } from './public.constants';
import { NamespacedStorageService } from './namespaced-storage.service';
import type { NamespaceOptions } from './namespaced-storage.interface';

@Module({})
export class SharedNamespaceModule {
  static forNamespace(opts: NamespaceOptions): DynamicModule {
    return {
      module: SharedNamespaceModule,
      imports: [ConfigModule, S3CoreModule],
      providers: [
        {
          provide: opts.token,
          inject: [S3_CLIENT, ConfigService],
          useFactory: (client: S3Client, config: ConfigService) =>
            new NamespacedStorageService(
              client,
              PUBLIC_BUCKET,
              opts.namespace,
              opts.contentType,
              config.get<string>('STORAGE_PUBLIC_URL')!,
              config.get<number>('STORAGE_MAX_UPLOAD_BYTES')!,
            ),
        },
      ],
      exports: [opts.token],
    };
  }
}
```

### Pattern 2 — `Upload` + Size-Limited PassThrough

**What:** The caller's `Readable` pipes through a counter `Transform` that destroys itself with `StorageUploadTooLargeError` on overflow. `Upload.done()` sees the stream error and auto-aborts multipart parts via `AbortMultipartUpload`.

**When:** Inside `NamespacedStorageService.upload`.

### Pattern 3 — Compile-time separation of private vs public

Each service's composition module imports **both** modules independently:

```ts
// apps/parser/src/infrastructure/storage/storage.module.ts (per D-10/D-11)
@Module({
  imports: [
    ParserStorageModule, // private bucket 'parser' (PrivateStoragePort)
    SharedNamespaceModule.forNamespace({
      namespace: 'reports',
      contentType: 'application/pdf',
      token: SHARED_REPORTS,
    }),
  ],
  exports: [ParserStorageModule, SharedNamespaceModule],
})
export class StorageModule {}
```

A caller injecting `PARSER_STORAGE` gets `PrivateStoragePort` (no `getPublicUrl`, no `url` in upload return). A caller injecting `SHARED_REPORTS` gets `NamespacedStoragePort`. **TypeScript rejects any attempt to get a public URL from the private bucket at compile time** — not via runtime check.

### Anti-Patterns to Avoid

- **Sharing the `S3Client` singleton via `@Global()`** — Phase 22.1 D-01 explicitly removed this. Each module imports `S3CoreModule` explicitly in its own `imports: [...]` array.
- **Passing `contentType` as upload parameter.** Violates D-12. Baked into DI binding.
- **Buffering the stream before upload to pre-compute size.** Defeats D-16 (streaming). Size enforced via inline counter (D-18).
- **Per-operation visibility flag (`upload(..., { public: true })`).** Violates D-09. Visibility encoded in module/interface choice.
- **Passing `leavePartsOnError: true` to `Upload`.** `[CITED: npm docs — @aws-sdk/lib-storage]` Default `false` ensures automatic `AbortMultipartUpload` on error — the desired behavior for size-limit breach.
- **Reading `STORAGE_ENDPOINT`/`STORAGE_PORT` to build public URL.** They are the internal endpoint (D-05). Using them for client URLs breaks dev/prod parity. Only `STORAGE_PUBLIC_URL` goes into URLs returned to clients.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Multipart upload chunking | Custom `CreateMultipartUpload`+`UploadPart`+`CompleteMultipartUpload` orchestration | `@aws-sdk/lib-storage.Upload` | Retries per chunk, concurrent uploads (queueSize 4), automatic abort on error, progress events. AWS-maintained. |
| UUID generation | `Math.random`-based pseudo-UUID, Date-based IDs, third-party `uuid` package | `node:crypto.randomUUID()` | Built-in Node 20, 122 bits entropy, RFC 4122 v4. No dep. `[CITED: nodejs.org/api/crypto]` |
| Stream size enforcement | Wrapping full stream in memory to measure, pre-request `Content-Length` header | `Transform` with byte counter + `destroy(err)` | Works for unknown-length streams. Propagates through `pipeline` to `Upload.done()` which invokes cleanup. |
| Multipart cleanup on abort | Manual `AbortMultipartUpload` calls | Default behavior of `Upload` (leavePartsOnError: false) | Library handles it. `[CITED: aws-sdk-js-v3 docs]` |
| Presigned URL generation | Custom HMAC signing, third-party S3 URL libs | **Not needed at all** — D-19 replaces presigning with anonymous-read bucket + UUID keys | Phase removes presigning entirely. |
| Anonymous bucket policy JSON (MinIO) | Hand-written IAM JSON per bucket | `mc anonymous set download ALIAS/public` | Single command. Sets the minimal well-known "download" policy (`s3:GetObject` on `*` for principal `*`). `[CITED: docs.min.io]` |
| Garage public access | Custom reverse-proxy signing middleware | `garage bucket website --allow public` | Only official mechanism. `[CITED: garagehq.deuxfleurs.fr/cookbook/exposing-websites]` |

**Key insight:** All hard pieces (multipart orchestration, UUID, abort propagation, anonymous policy) have one-liner canonical solutions. This phase is almost entirely assembly and renaming — no novel infrastructure code should appear.

## Common Pitfalls

### Pitfall 1: `lib-storage` requires `Upload.done()` — not a single `send()` call
**What goes wrong:** Developers reach for `client.send(new PutObjectCommand(...))` with a huge Readable and get the upload stuck or failing on hosts that enforce `Content-Length`.
**Why it happens:** `PutObjectCommand` with a Readable body but no `Content-Length` forces the SDK to buffer the stream in memory to compute length (on some versions) — defeating the streaming goal.
**How to avoid:** **Always use `new Upload({...}).done()`** for the new namespaced service. `PutObjectCommand` stays only for the old `PrivateStoragePort.upload` (where Buffer body is fine) or can be migrated as a cleanup. `[CITED: @aws-sdk/lib-storage npm docs]`
**Warning signs:** Memory spikes on upload, requests hanging at 100% on small files.

### Pitfall 2: `Upload.done()` does NOT always abort in-flight parts on `.abort()`
**What goes wrong:** Calling `uploader.abort()` after an upload starts doesn't cancel parts already being sent — only parts still queued. Memory/bandwidth leak on user-disconnect scenarios.
**Why it happens:** `[CITED: github.com/aws/aws-sdk-js-v3 issue #5109]` Known limitation of the library in browser and Node contexts.
**How to avoid:** For **this phase**, this doesn't matter because size-limit abort goes through **stream error propagation**, not manual `.abort()`. The Transform destroys itself, `pipeline` propagates, `Upload.done()` rejects, multipart cleanup fires. Do NOT add a manual `.abort()` path — trust the error propagation. Document this in the service comment.
**Warning signs:** If a future task adds timeout-based cancel, verify behavior.

### Pitfall 3: `Transform` without `pipeline` doesn't propagate destroy
**What goes wrong:** Chaining `body.pipe(counter)` and passing `counter` as `Body` to `Upload`. When `counter` destroys with error, the upstream `body` isn't cleaned up — resource leak.
**Why it happens:** Plain `.pipe()` has weak error propagation; `pipeline()` from `node:stream/promises` is the canonical fix.
**How to avoid:** Use `pipeline(body, counter)` OR — simpler — construct the Transform to wrap via `body.pipe(new SizeCounter())` and pass the counter as `Upload.Body`. `Upload` internally pipes **from** the Body you pass it — if the Body errors, `Upload.done()` rejects and abort fires. Test with a deliberate oversized payload in smoke.
**Warning signs:** Dangling file handles in `lsof`, memory not releasing after aborted uploads.

### Pitfall 4: Garage has no S3 bucket policy — path-style `/public/${key}` does not work
**What goes wrong:** Developer copies the MinIO-tested URL format to production (Garage) and gets 403 Forbidden on every public URL.
**Why it happens:** `[CITED: garagehq.deuxfleurs.fr issue #263]` Garage S3 API **does not support anonymous GET at all**. Only the separate web endpoint (port 3902) serves anonymous content, and it uses virtual-hosted-style (`https://<bucket>.<web-root>/<key>`) exclusively.
**How to avoid:** The `STORAGE_PUBLIC_URL` env var absorbs the difference. For MinIO envs, set it to `http://localhost:9000` (path-style works — file served at `.../public/<key>`). For Garage envs, operator fronts Garage with a reverse proxy (Traefik/Cloudflare) that rewrites `https://files.email-platform.pp.ua/public/<key>` → Garage virtual-host `public.{web-root}/<key>`. **OR** accept operator sets `STORAGE_PUBLIC_URL=https://files.email-platform.pp.ua` and the code concatenates `/public/${key}` — which Traefik rewrites at edge. Runbook must cover both backends explicitly. **See Open Questions.**
**Warning signs:** Smoke tests pass local MinIO, fail dev/prod Garage with 403 Forbidden.

### Pitfall 5: `mc anonymous set download` grants `s3:GetObject` on whole bucket
**What goes wrong:** Developer thinks anonymous-download permits only keys under `namespace/` prefix. It doesn't — bucket-wide.
**Why it happens:** MinIO's `mc anonymous set download` sets a bucket-wide IAM policy. Granular prefix policies require `mc anonymous set-json` with custom JSON. `[CITED: docs.min.io]`
**How to avoid:** Since the `public` bucket holds only public files (by design — D-01), bucket-wide anonymous is correct. No prefix policy needed. But plan tasks must **not** accidentally store secrets or private files in `public` — enforce via module boundary (D-09). Document that `public` bucket is "anything written here is public" in `public.constants.ts`.
**Warning signs:** Calling `upload` on `SharedNamespaceModule` with PII-adjacent content.

### Pitfall 6: Removing `@aws-sdk/s3-request-presigner` with lingering imports
**What goes wrong:** `pnpm install` succeeds after removal, but typecheck fails later because a test file or old branch imports from it.
**Why it happens:** Workspace dep removal is silent on TS errors until consumer builds.
**How to avoid:** Before removing from `package.json`, run `grep -r "s3-request-presigner" packages/ apps/` to confirm zero hits. Expected single hit today: `packages/foundation/src/internal/storage/s3-storage.service.ts` (the `getSignedUrl` method being deleted). Delete the method and the import in the same commit as the dep removal.
**Warning signs:** Red CI on typecheck after dep drop.

### Pitfall 7: Renaming `reports → public` bucket when `reports` contains smoke-test artifacts
**What goes wrong:** Operator destroys `reports` bucket; parallel running smoke tests error out with `NoSuchBucket`.
**Why it happens:** Rename = destroy + create in Garage (no native rename) and is safest in MinIO too. `[CITED: CONTEXT.md D-03 — explicitly destroy+recreate]`
**How to avoid:** Runbook step MUST instruct operator to stop services (or at least halt smoke-test endpoints) before rename. Verify-step curls the new `public` bucket, not the old one.
**Warning signs:** 503 DOWN on readiness after bucket rename; `HeadBucket` returns 404.

## Code Examples

### Multipart upload with size-limit enforcement and content-type binding

```ts
// packages/foundation/src/external/storage/public/namespaced-storage.service.ts
// Source: combines @aws-sdk/lib-storage docs + Node 20 stream/promises pipeline

import { Readable, Transform, type TransformCallback } from 'node:stream';
import { randomUUID } from 'node:crypto';
import type { S3Client } from '@aws-sdk/client-s3';
import { DeleteObjectCommand, HeadObjectCommand } from '@aws-sdk/client-s3';
import { Upload } from '@aws-sdk/lib-storage';
import { StorageUploadTooLargeError } from './upload-too-large.error';
import { PUBLIC_URL, UPLOAD_DEFAULTS } from './public.constants';
import type { NamespacedStoragePort } from './namespaced-storage.interface';

export class NamespacedStorageService implements NamespacedStoragePort {
  constructor(
    private readonly client: S3Client,
    private readonly bucket: string,       // 'public'
    private readonly namespace: string,    // 'reports'
    private readonly contentType: string,  // 'application/pdf'
    private readonly publicUrlBase: string,
    private readonly maxBytes: number,
  ) {}

  async upload(filename: string, body: Readable): Promise<{ url: string; key: string }> {
    const key = `${this.namespace}${PUBLIC_URL.KEY_SEPARATOR}${randomUUID()}${PUBLIC_URL.KEY_SEPARATOR}${filename}`;
    const counter = new SizeCountingTransform(this.maxBytes);

    const uploader = new Upload({
      client: this.client,
      params: {
        Bucket: this.bucket,
        Key: key,
        Body: body.pipe(counter),
        ContentType: this.contentType,
      },
      queueSize: UPLOAD_DEFAULTS.QUEUE_SIZE,
      partSize: UPLOAD_DEFAULTS.PART_SIZE_BYTES,
      // leavePartsOnError defaults to false — Upload auto-aborts multipart on error.
    });

    await uploader.done(); // throws if counter destroys with StorageUploadTooLargeError

    const url = `${this.publicUrlBase}${PUBLIC_URL.PATH_SEPARATOR}${this.bucket}${PUBLIC_URL.PATH_SEPARATOR}${key}`;
    return { url, key };
  }

  async delete(key: string): Promise<void> {
    await this.client.send(new DeleteObjectCommand({ Bucket: this.bucket, Key: key }));
  }

  async exists(key: string): Promise<boolean> {
    try {
      await this.client.send(new HeadObjectCommand({ Bucket: this.bucket, Key: key }));
      return true;
    } catch (err) {
      if (isNotFound(err)) return false;
      throw err;
    }
  }
}

// Same file or sibling — size-limit.transform.ts
class SizeCountingTransform extends Transform {
  private seen = 0;
  constructor(private readonly max: number) {
    super();
  }
  _transform(chunk: Buffer, _enc: BufferEncoding, cb: TransformCallback): void {
    this.seen += chunk.length;
    if (this.seen > this.max) {
      cb(new StorageUploadTooLargeError(this.seen, this.max));
      return;
    }
    cb(null, chunk);
  }
}
```

## Security Domain

`security_enforcement` config check: if explicitly `false` in `.planning/config.json`, omit. Otherwise required.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | Public bucket is deliberately anonymous (D-21). Authentication is handled upstream at gateway for private buckets (unchanged). |
| V3 Session Management | no | No sessions in storage layer |
| V4 Access Control | **yes** | **Compile-time separation** (D-09) — `PrivateStoragePort` and `NamespacedStoragePort` are distinct interfaces. TypeScript rejects mixing. Anonymous-read policy applies to `public` bucket **only**, never to per-service private buckets. Runbook step MUST verify this (show `mc anonymous get local/parser` returning `none`). |
| V5 Input Validation | **yes** | `filename` from caller goes into S3 key — a hostile filename like `../foo` could produce `reports/<uuid>/../foo`. S3 does not interpret `..`, so it doesn't escape — but the resulting key is ugly. Planner should decide: strip path separators from filename, or document that filename is treated as a display label only (UUID guarantees uniqueness). `content-Type` is bound at DI time (D-12) — not attacker-controllable. |
| V6 Cryptography | **yes** | UUID v4 via `crypto.randomUUID()` is CSPRNG-backed `[CITED: nodejs.org/api/crypto]`. Do NOT substitute `Math.random`. 122 bits entropy satisfies the security-by-obscurity claim in D-19. |
| V7 Error Handling | yes | `StorageUploadTooLargeError` must NOT echo request bodies or partial content in error messages — keep to `seen`/`max` numbers only. Existing `AllRpcExceptionsFilter` handles the rest. |
| V12 API / Web Service | **yes** | Anonymous-read bucket is a publicly enumerable surface if UUIDs were predictable. They are not (V6). No directory listing must be enabled (MinIO: default off; Garage website: index.html served only, no listing — verify). |

### Known Threat Patterns for `NestJS + S3 (MinIO/Garage)`

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Malicious filename injection into S3 key | Tampering | Sanitize filename or treat as label only; UUID provides uniqueness |
| Content-Type spoofing (user uploads JS pretending to be PDF) | Tampering / XSS via browser content-sniffing | D-12 binds content-type at DI — caller cannot override. Also advisable: set `X-Content-Type-Options: nosniff` at the reverse proxy for public bucket responses. |
| Directory enumeration on public bucket | Information Disclosure | Disable bucket listing (default on MinIO + Garage). Don't enable `s3:ListBucket` in anonymous policy — `mc anonymous set download` grants only `GetObject`. `[CITED: docs.min.io]` |
| Upload DoS (runaway stream) | Denial of Service | `STORAGE_MAX_UPLOAD_BYTES` hard ceiling via Transform counter (D-18) |
| Exhausting S3 multipart slots via abandoned uploads | Denial of Service | `Upload` default `leavePartsOnError=false` auto-aborts. Also advisable: configure MinIO/Garage lifecycle rule to purge incomplete multipart uploads after N days (future runbook item, not in scope). |
| URL leaked in logs / analytics | Information Disclosure | D-20 accepts this risk; mitigation is rotation (upload new key, delete old). Design note for the planner: **do not log the `url` field** from `upload()` — log only `key`. |
| Cross-service write of private-class data into public bucket | Information Disclosure | D-09 compile-time separation. Private port has no `getPublicUrl` and no access to `public` bucket — `PrivateStorageModule.forBucket` binds a specific private bucket name. |

## Open Questions (RESOLVED)

1. **Garage URL shape vs D-14 format — REQUIRES USER DECISION BEFORE PLANNING**
   - What we know: D-14 locks `${STORAGE_PUBLIC_URL}/public/${key}` (path-style). MinIO serves this natively on S3 API port 9000 after `mc anonymous set download`. Garage does NOT — its S3 API is auth-only, and its web endpoint (3902) is virtual-hosted only `[CITED: garagehq.deuxfleurs.fr issue #263 + cookbook/exposing-websites]`.
   - What's unclear: Does Traefik at the edge have (or can easily have) a rewrite rule mapping `https://files.email-platform.pp.ua/public/{key}` → `Host: public.<garage-web-root>` / `path: /{key}`?
   - Recommendation: Before /gsd-plan-phase is invoked, user confirms one of:
     - (a) Traefik rewrite is feasible; runbook D-27 includes the Traefik snippet; `STORAGE_PUBLIC_URL` has the same shape in all envs (`https://files.email-platform.pp.ua` — and code appends `/public/${key}`).
     - (b) Accept different env-value shapes per backend; in MinIO envs `STORAGE_PUBLIC_URL=http://localhost:9000`, in Garage envs `STORAGE_PUBLIC_URL=https://public.files.email-platform.pp.ua` (with the bucket as subdomain, and code **still appends `/public/${key}`** — which on Garage resolves to a nonexistent `public/` prefix, so operator sets `STORAGE_PUBLIC_URL=https://public.files.email-platform.pp.ua` meaning the `public/` path segment is redundant-but-harmless if Traefik strips it).
     - (c) Revisit D-14 to remove the `/public/` segment and derive bucket from path or virtual-host transparently — but this unlocks a locked decision.

   **RESOLVED (2026-04-14):** выбран вариант (b) с конкретизацией — public download уходит через **Garage native virtual-host web endpoint** (port 3902), bucket `public` exposed как subdomain `public.<root_domain>`. Никакого Traefik rewrite, никакого gateway proxy. D-14 amended: новая формула `${STORAGE_PUBLIC_URL}/${key}` (bucket в hostname, `/public/` сегмент из path удалён). Per-env `STORAGE_PUBLIC_URL` — см. CONTEXT.md D-28, D-29. Anonymous policy one-time per env — см. D-30.

2. **Filename sanitization in key construction**
   - What we know: D-13 format is `{namespace}/{uuid}/{filename}`. Filename comes from caller.
   - What's unclear: Should service strip path separators / control chars from filename? Or trust caller?
   - Recommendation: Strip `/` and `\0`, replace with `_`, cap length at 255. Low-risk defensive measure. Put the rule in a `sanitizeFilename` helper under `public.constants.ts` or a sibling. Planner's call.

   **RESOLVED (2026-04-14):** выбран sanitization — strip `/`, `\0` и control-chars (`\x00-\x1f\x7f`), replace с `_`, cap at 255 chars. Реализуется в `FILENAME_SANITIZE` (`public.constants.ts`) + `sanitizeFilename()` (`public-url.builder.ts`) — Plan 01 Task 2.

3. **`STORAGE_MAX_UPLOAD_BYTES` value suggestion for each env**
   - What we know: Env var is required (D-06), no default.
   - What's unclear: What value does operator put in `.env.example`?
   - Recommendation: Default example value `104857600` (100 MiB) — generous for the PDF-report use case but not unbounded. Operator can raise/lower per env. Planner adds this to runbook D-27 and to `.env.example`.

   **RESOLVED (2026-04-14):** `STORAGE_MAX_UPLOAD_BYTES=104857600` (100 MiB) в `.env.example` как example value; операторы переопределяют per env. Присутствует в `.env`, `.env.docker`, `.env.example` (Plan 02) и в runbook (Plan 03).

4. **Lifecycle rule for incomplete multipart uploads**
   - What we know: `Upload` aborts on error; good on happy path. But if process hard-crashes mid-upload, multipart parts linger.
   - What's unclear: Should runbook D-27 include a bucket lifecycle rule to purge incomplete multiparts after N days? MinIO supports this; Garage lifecycle support is partial.
   - Recommendation: Out of scope for 22.4 — note in Deferred Ideas for a future hardening phase.

   **RESOLVED (2026-04-14):** multipart lifecycle cleanup — deferred. Note добавлен в CONTEXT.md `<deferred>` блок. Happy-path abort через `leavePartsOnError=false` остаётся; hard-crash cleanup — операторская задача / будущая фаза.
