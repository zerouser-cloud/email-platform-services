## Context

### Problem statement

Email Platform — 6 NestJS микросервисов в pnpm monorepo (`apps/auth` + `apps/sender` + `apps/parser` + `apps/audience` + `apps/notifier` + `apps/gateway`) + 3 shared packages (`packages/contracts` + `packages/config` + `packages/foundation`). Current build pipeline (audit-snapshot per `999.18-AUDIT.md`):

- pnpm 11 + `injectWorkspacePackages: true` (community-flagged "foot gun" per pnpm Discussion #3938 — see RESEARCH §Sources Primary `pnpm Discussion #3938`).
- Single multi-stage `infra/docker/app.Dockerfile` reused × 6 services через `ARG APP_NAME` (per RESEARCH §3.1 baseline).
- Turbo orchestration на host; **bypassed inside Dockerfile** (per-package `pnpm --filter ... run build` invocations — F-03 per `999.18-AUDIT.md` F-03 §Evidence).
- Step 4b + Step 4d cycles `rm -rf node_modules + pnpm install --frozen-lockfile` to refresh injected dist (F-02; root cause F-01 per `999.18-AUDIT.md`).
- Multi-arch CI absent — `.github/workflows/docker-build.yml` has no `platforms:` arg (F-08 BLOCKER per `999.18-AUDIT.md`).
- Contract generation × 6 parallel CI jobs (F-12), with cache hash blind to ts-proto version (F-24 per `999.18-AUDIT.md` F-24 §Evidence).
- 5 prior infra fix commits (`132138d` / `fb8dee7` / `6fc9d3c` / `b9d1913` / `da70085`) form patch-on-patch archaeology (F-15 BLOCKER).

12 deferred BLOCKER+MAJOR findings из 999.18 audit (`F-01` / `F-02` / `F-03` / `F-04` / `F-04-d8` / `F-05` / `F-08` / `F-12` / `F-14` / `F-15` / `F-20` / `F-24`) clustered into THREE архитектурных оси per RESEARCH §1:

1. **Monorepo build orchestrator + injection model** (F-01 / F-02 / F-03 / F-14 / F-15) — кто оркестрирует TS-builds внутри Dockerfile + как избежать pnpm injection-model staleness класса.
2. **Container build pattern** (F-02 / F-20 / F-08) — multi-stage shape, image base, BuildKit cache strategy, multi-arch CI, image determinism для k8s digest-pinning.
3. **Contract generation placement + cache hash determinism** (F-12 / F-24) — где (когда) генерируется `packages/contracts/src/generated/*.ts`; как сделать чтобы cache invalidate-ся при ts-proto bump.

Plus orthogonal cleanups (F-04 / F-04-d8 / F-05) — compose healthcheck `/health/live` → `/health/ready` swap; PROTO_DIR triple-duplication kill — orchestrator-independent, могут пройти в same impl phase 999.18.2.

### What this ADR closes (single decision, four coupled choices)

Per RESEARCH §12.2 the ADR Decision section MUST close ONE orchestrator finalist + FOUR coupled cross-cutting choices в одном решении (они не independently re-decidable):

- (a) `pnpm deploy --prod` keep / drop (per RESEARCH §5.4)
- (b) `injectWorkspacePackages: true` keep-with-mitigation (`syncInjectedDepsAfterScripts: [build]`) / drop-entirely (per RESEARCH §5.5)
- (c) Image base (node:22-alpine vs distroless vs scratch+node-binary) для builder + runner stages (per RESEARCH §5.2)
- (d) Contract generation placement (Placement A pre-build CI / Placement B build-time hook × 6 services / Placement C runtime) (per RESEARCH §7)

Plus implicit FIFTH coupled choice — multi-arch initial strategy (`docker buildx` + QEMU vs native ARM runners) per CONTEXT D-11; finalised в §Decision как recommendation, with DevOps-owned timing for migration to native runners.
