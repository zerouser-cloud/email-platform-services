## Stage 0: Build args + global setup

This pseudo-stage covers the Dockerfile preamble — `# syntax`, `ARG NODE_VERSION`, `ARG APP_NAME`, base image FROM declaration semantics. It is not an OCI stage proper but is the canonical anchor for all build-args + multi-arch directives + image-base discipline.

### Section 0.1: Dockerfile syntax pragma

**Code:**
\```dockerfile

# syntax=docker/dockerfile:1

\```

- **Purpose:** Enables BuildKit features (multi-stage, `--mount=type=cache`, `--mount=type=secret`, multi-arch buildx).
- **Invariant I-S0.1:** First non-comment line MUST be `# syntax=docker/dockerfile:1` (or pinned digest per OQ-10 if image-determinism is being tightened). Without it, BuildKit features silently degrade.
- **K8s-ready:** N/A — pragma applies at build-time only.
- **Multi-arch:** N/A — pragma applies at build-time only.

### Section 0.2: Build-args declaration

**Code:**
\```dockerfile
ARG NODE_VERSION=22-alpine
ARG APP_NAME
\```

- **Purpose:** `NODE_VERSION` parameterises base image without forking Dockerfile per service. `APP_NAME` parameterises which app's `dist/` is copied into runner — single Dockerfile reused × 6 services.
- **Invariant I-S0.2:** `APP_NAME` has NO default value — build MUST fail if caller forgets `--build-arg APP_NAME=<svc>`. This is the canonical fail-loud pattern; absent it, Docker builds an "empty" image silently.
- **Invariant I-S0.3:** `NODE_VERSION` default = `22-alpine` (per CONTEXT D-12 + project_devsecops_state). Bumping to `22.12-alpine@sha256:<digest>` is RECOMMENDED for image-determinism (per RESEARCH §5.6 mechanism #4 + OQ-10) — if ADR Decision (c) image base picked digest-pinned variant, update this default.
- **K8s-ready:** Build-arg discipline (`APP_NAME` per service) supports k8s ImageMeta `imagePullPolicy: Always` with per-service tags.
- **Multi-arch:** Both `node:22-alpine` and `gcr.io/distroless/nodejs22-debian12` publish multi-arch manifests (linux/amd64 + linux/arm64). No special handling required.

### Section 0.3: PROTO_DIR triple-duplication kill (F-05 resolution)

This is a critical Stage 0 invariant per F-05.

- **Current state (pre-999.18.2):** `infra/docker/app.Dockerfile:82` declares `ENV PROTO_DIR=/app/proto`. Same value duplicated in `.env.docker:64` AND `.env.docker.example:65`. Three sources of truth → drift risk.
- **Reference shape:** Dockerfile MUST NOT declare `ENV PROTO_DIR=...`. Single source of truth = `env_file:` directive in `infra/docker-compose.yml` reading from `.env.docker`. Local-native dev reads from `.env.docker` via `dotenv-cli` wrapping `pnpm start:native`.
- **Invariant I-S0.4:** `grep -c '^ENV PROTO_DIR' infra/docker/app.Dockerfile` MUST equal `0`. If non-zero, F-05 has regressed.
- **Invariant I-S0.5:** `PROTO_DIR` value lives in `.env.docker` only; consumed by `env_file:` block. App reads via `process.env.PROTO_DIR` (NOT from Dockerfile literal).
- **K8s-ready:** k8s consumes `PROTO_DIR` via `envFrom: configMapRef: <svc>-config` — same env-discipline as compose `env_file:`. No Dockerfile change needed for k8s portability.
- **Skill cross-check:** `twelve-factor` §"Factor III — Config" — environment variables MUST come from environment, not baked into image. `env-schema` §"Required env vars" — `PROTO_DIR` is a Zod-required field in `packages/config/src/env-schema.ts`.

````markdown
## Stage 1: Builder

This stage produces compiled `dist/` artefacts + isolated dependency closure for the target app. Stage 1 output flows into Stage 2 via `COPY --from=builder ...` directives.

### Per-Step decomposition

#### Step 1.1: Pruner stage entry (orchestrator-finalist-specific)

**Code (Turborepo finalist — per RESEARCH §3.1 spike):**
\```dockerfile
FROM node:${NODE_VERSION} AS pruner
WORKDIR /app
RUN corepack enable
COPY . .
ARG APP_NAME
RUN pnpm dlx turbo prune @email-platform/${APP_NAME} --docker
\```

- **Purpose:** `turbo prune --docker` produces minimal context per service in `/app/out/json/` (manifests only) + `/app/out/full/` (manifests + source). Splits "what changed in dependency graph" from "what changed in source code" — gives Step 1.2 a stable manifest-only cache layer.
- **Invariant I-S1.1:** First COPY is `COPY . .` (entire workspace) — `turbo prune` requires full workspace to compute the dependency graph slice. This APPEARS to invalidate cache on every commit, but Step 1.2's `--from=pruner` reference uses ONLY the pruner output (json/full), which IS cache-keyed by manifests.
- **Invariant I-S1.2:** `corepack enable` MUST precede `pnpm dlx turbo prune` — pnpm 11 ships via corepack; absence breaks the prune invocation.
- **K8s-ready:** Pruner stage is build-time only; doesn't ship to k8s. Turbo prune output (`/app/out/json` + `/app/out/full`) is the k8s-relevant slice (minimal closure per service).
- **Multi-arch:** `corepack enable` and `pnpm dlx turbo prune` work on amd64 AND arm64 (no native binaries in turbo CLI per RESEARCH §6.4). No special handling.
- **Cache behaviour:** Pruner stage is NOT cache-friendly by design — every commit invalidates `COPY . .`. This is acceptable because pruner stage is fast (~5-10s) and downstream cache savings dominate.
- **Trade-off vs alternatives:** Plain-pnpm baseline (RESEARCH §3.6) skips this stage entirely — it copies manifests directly in Step 1.2 and uses `pnpm install --filter @email-platform/${APP_NAME}...` for closure isolation. Trade-off documented in ADR §Alternatives O-06 plain-pnpm.
- **F-NN coverage:** Closes F-03 (turbo invoked at Dockerfile boundary, not bypassed).

#### Step 1.2: Install layer (manifests-only cache anchor)

**Code:**
\```dockerfile
FROM node:${NODE_VERSION} AS installer
WORKDIR /app
RUN corepack enable

# Manifests-only copy — install layer cache key

COPY --from=pruner /app/out/json/ ./
RUN --mount=type=cache,id=pnpm,target=/pnpm/store \
 pnpm install --frozen-lockfile
\```

- **Purpose:** Establish the install-layer cache key. Manifests-only copy means changes to source code (Step 1.3) don't invalidate the install layer. Cache mount `id=pnpm,target=/pnpm/store` provides cross-CI-run survival of pnpm content-addressable store.
- **Invariant I-S1.3:** Step 1.2 copies ONLY package.json + lockfile from `/app/out/json/` — NEVER source code. Any source-code COPY here invalidates Step 1.3 install cache on every code change.
- **Invariant I-S1.4:** `--mount=type=cache,id=pnpm,target=/pnpm/store` survives across CI runs in BuildKit. Different `id=` values produce isolated caches per consumer (per RESEARCH §5.3).
- **Invariant I-S1.5:** Per ADR Decision (b) — if `injectWorkspacePackages: true` is dropped-entirely, this step's cache survives across all source-code commits. If kept-with-mitigation (`syncInjectedDepsAfterScripts: [build]`), cache is INVALIDATED on every dist/ change because pnpm runs sync hook post-build (per pnpm Issue #9837 known limitation cited in RESEARCH §3.1 sources).
- **K8s-ready:** Install layer ships into Stage 2 manual COPY closure (per ADR Decision (a) drop pnpm deploy). Layer is byte-deterministic given same lockfile (cache key) → image-determinism unlocked (F-20 closure mechanism).
- **Multi-arch:** `pnpm install --frozen-lockfile` runs natively on amd64 AND arm64. Native modules (e.g., `bcrypt` if added) build per-arch via `node-gyp` — extends build time +5-15s on QEMU emulation per RESEARCH §6.1 acceptance.
- **Cache behaviour:** Layer hit rate ≈ 99% on typical commits (commits that don't touch package.json or lockfile). Lockfile bump → layer rebuild → ~30-60s install (warm pnpm store via cache mount) vs ~2-5min without cache mount.

#### Step 1.3: Build layer (orchestrator-driven build)

**Code (Turborepo finalist):**
\```dockerfile
FROM installer AS builder
WORKDIR /app
COPY --from=pruner /app/out/full/ ./
ARG APP_NAME
RUN pnpm exec turbo run build --filter=@email-platform/${APP_NAME}
\```

- **Purpose:** Compile TypeScript → JavaScript via the orchestrator finalist. `--filter=@email-platform/${APP_NAME}` restricts build to target app + its dep closure (defined in turbo.json `dependsOn`).
- **Invariant I-S1.6:** Source code copy uses `/app/out/full/` (pruner output), not `COPY . .` — pruner already filtered to dep-closure. Re-COPYing full workspace would defeat pruning purpose.
- **Invariant I-S1.7:** Build invocation is `pnpm exec turbo run build` (NOT `pnpm --filter ... run build` — that bypasses turbo cache, which is the F-03 root cause). If ADR picked Nx, equivalent invocation is `pnpm exec nx build ${APP_NAME}`. Plain-pnpm finalist replaces with `pnpm --filter @email-platform/${APP_NAME}... build` (acceptable here because plain-pnpm finalist IS the no-orchestrator baseline).
- **Invariant I-S1.8:** Per ADR Decision (b) drop-entirely — NO `RUN rm -rf node_modules apps/*/node_modules packages/*/node_modules` cycle (F-02 closure). NO `RUN pnpm install --force` (F-15 archaeology root-cause closure).
- **Invariant I-S1.9 (conditional, applies if ADR Decision (d) Placement A pre-build CI):** Generated proto files arrive via `COPY --from=pruner` (i.e., they were generated in commit-time CI step BEFORE `docker build` and committed to the workspace). NO `RUN pnpm generate:contracts` invocation in this stage (F-12 closure). If ADR Decision (d) Placement B build-time hook chosen, replace this invariant with the `pnpm generate:contracts` invocation here, gated by `--mount=type=cache` for proto output.
- **K8s-ready:** `dist/` output is per-app + deterministic given same source + same lockfile → image-determinism unlocked.
- **Multi-arch:** `tsc` runs natively on amd64 AND arm64 (TypeScript is pure-JS). `pnpm exec turbo run build` works on both archs. ## Stage 2: Runner

This stage produces the runtime image that ships to k8s (or compose). Stage 2's shape determines image size, attack surface, k8s probe-target reachability, and image-determinism feasibility.

### Per-Step decomposition

#### Step 2.1: Runner stage entry + non-root user

**Code:**
\```dockerfile
FROM node:${NODE_VERSION} AS runner
RUN addgroup -g 1001 -S appgroup && adduser -S appuser -u 1001 -G appgroup
WORKDIR /app
\```

- **Purpose:** Establish a non-root runtime user (uid 1001 / gid 1001). k8s `securityContext: runAsNonRoot: true` requires non-root entry; alpine's default `node` user (uid 1000) is acceptable but explicit `appuser` matches project precedent (current `infra/docker/app.Dockerfile:53`).
- **Invariant I-S2.1:** UID/GID are explicitly numeric (`1001`) — k8s `runAsUser: 1001` matches without name-resolution. Alphabetic-only users (`USER appuser`) require name resolution at admission control time (works on alpine; fragile across base-image changes).
- **Invariant I-S2.2:** Last `USER appuser` directive precedes `CMD` (Step 2.4). All COPY directives BEFORE `USER` so they have root permissions to write into `/app/`.
- **K8s-ready:** Non-root + numeric UID = `securityContext: runAsNonRoot: true, runAsUser: 1001` in pod spec works without modification.
- **Multi-arch:** `addgroup` + `adduser` are alpine BusyBox commands — work identically on amd64 + arm64 alpine images.
- **Cache behaviour:** Layer is reused across all builds (immutable user creation).

#### Step 2.2: Manual COPY closure (per ADR Decision (a) drop pnpm deploy)

**Code:**
\```dockerfile
ARG APP_NAME
COPY --from=builder /app/apps/${APP_NAME}/dist ./dist
COPY --from=builder /app/apps/${APP_NAME}/node_modules ./node_modules
COPY --from=builder /app/packages /app/packages
COPY --from=builder /app/node_modules/.modules.yaml /app/node_modules/.modules.yaml
\```
