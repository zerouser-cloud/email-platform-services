## Gaps

### Gap 1 — Decision (b) `injectWorkspacePackages`: М2 → М3

**Текущая запись (executor's choice):** Decision (b) DROP-ENTIRELY — стандартный pnpm symlink + manual COPY runner (М2 в RESEARCH §5.5).

**Согласованное решение (user D-16 review):** **М3** — `pnpm fetch --prod` + `pnpm install --offline --frozen-lockfile`.

**Reasoning:** «Делать максимально правильно архитектурно». М3 даёт лучшую cache-mount granularity (tarball cache отделён от install layer); готовит проект к scale-out N=15-20 сервисов; supported pattern в pnpm community для production Docker builds.

**Amendments needed:**

- `999.18.1-ADR.md` §Decision (b) — переписать с М2 на М3, обновить мотивировку
- `999.18.1-DOCKERFILE-REFERENCE.md` Stage 1 — добавить под-этап `fetcher` для `pnpm fetch --prod`, изменить `installer` на `pnpm install --offline --frozen-lockfile`
- `999.18.1-MIGRATION-RUNBOOK.md` Wave 2 — отразить новый порядок stages в task list

### Gap 2 — Decision (c) Image base + healthcheck protocol: alpine + two-phase → distroless + transport-aligned

**Текущая запись (executor's choice):** Decision (c) `node:22-alpine` для builder и runner (initial), distroless DEFERRED to k8s-only deploy phase (two-phase evolution через Path X).

**Согласованное решение (user D-16 review):** **Distroless `gcr.io/distroless/nodejs22-debian12:nonroot` сразу + transport-aligned healthcheck protocol**:

- **(c.1) gateway** — HTTP `GET /health/ready` (как сейчас, естественно — это HTTP сервис)
- **(c.2) auth/sender/parser/audience** — gRPC `grpc.health.v1.Health/Check` standard protocol через `grpc-health-check` package (уже в deps); `grpc_health_probe` Go static binary копируется в runner stage; compose/k8s healthcheck использует `grpc_health_probe -addr=:50051`
- **(c.3) notifier** — gRPC Health-only server (вариант N-A — для consistency с другими non-HTTP сервисами)

**Reasoning:** «Резало глаз что gRPC сервисы держат HTTP сервер только ради `wget /health/ready`». Transport-aligned = чище архитектурно (hexagonal-friendly: транспорт-aligned, нет phantom HTTP serverов в gRPC сервисах). Distroless smaller attack surface, smaller image, industry standard. Closes pre-existing pitfall с parser /health/ready S3-timeout hang структурно (нет HTTP path = нет hang).

**Amendments needed:**

- `999.18.1-ADR.md` §Decision (c) — полностью переписать; заменить «two-phase evolution» на «distroless сразу + transport-aligned healthcheck»; добавить sub-decisions (c.1)/(c.2)/(c.3); обновить F-NN coverage table — F-04 / F-04-d8 переклассифицировать с «orthogonal-cleanup» на «coupled с Decision (c) — часть transport-aligned cleanup»
- `999.18.1-DOCKERFILE-REFERENCE.md` Stage 2 — переписать на distroless runner + COPY `grpc_health_probe` from builder stage; обновить K8s-ready callouts (k8s 1.24+ имеет native gRPC probe support); удалить «Path X distroless evolution» текст; убрать compose `wget` healthcheck-shape mention из Stage 2 invariants
- `999.18.1-MIGRATION-RUNBOOK.md` Wave 2 — расширить scope: добавить tasks «drop HTTP server в auth/sender/parser/audience/notifier», «register grpc.health.v1.Health service», «remove HTTP ports 3001-3004 from infra/docker-compose.yml»; Wave 3 healthcheck swap — вместо `wget /health/ready` использовать `grpc_health_probe -addr=:50051`
- `999.18.1-RE-EVAL-TRIGGERS.md` — добавить новый trigger `T-PROC-04 — k8s native gRPC probe migration` (когда мигрируем на k8s 1.24+, можно убрать `grpc_health_probe` binary, kubelet справится сам через `grpc:` field в probe spec)
