### Gap 2 — Decision (c) Image base + healthcheck protocol: alpine + two-phase → distroless + transport-aligned ✓ RESOLVED (Plan 04 Tasks 2/4/5/6, commits 57f4d09/814407a/77a0290/c1575c4)

**Текущая запись (executor's choice):** Decision (c) `node:22-alpine` для builder и runner (initial), distroless DEFERRED to k8s-only deploy phase (two-phase evolution через Path X).

**Согласованное решение (user D-16 review):** **Distroless `gcr.io/distroless/nodejs22-debian12:nonroot` сразу + transport-aligned healthcheck protocol**:

- **(c.1) gateway** — HTTP `GET /health/ready` (как сейчас, естественно — это HTTP сервис)
- **(c.2) auth/sender/parser/audience** — gRPC `grpc.health.v1.Health/Check` standard protocol через `grpc-health-check` package (уже в deps); `grpc_health_probe` Go static binary копируется в runner stage; compose/k8s healthcheck использует `grpc_health_probe -addr=:50051`
- **(c.3) notifier** — gRPC Health-only server (вариант N-A — для consistency с другими non-HTTP сервисами)

**Reasoning:** «Резало глаз что gRPC сервисы держат HTTP сервер только ради `wget /health/ready`». Transport-aligned = чище архитектурно (hexagonal-friendly: транспорт-aligned, нет phantom HTTP serverов в gRPC сервисах). Distroless smaller attack surface, smaller image, industry standard. Closes pre-existing pitfall с parser /health/ready S3-timeout hang структурно (нет HTTP path = нет hang).
