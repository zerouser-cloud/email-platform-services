## Re-evaluation Contract for ADR-001

When ANY trigger condition (§"Trigger Catalogue" below) fires, the following procedure activates:

1. **Author or maintainer files `/gsd:plan-phase 999.NN` (or sub-decimal)** with explicit rationale block citing the fired trigger ID (`T-NN`) + observed evidence (commit SHA, GitHub issue URL, npm version bump, `find apps -maxdepth 1 -type d | wc -l` count, etc.). Rationale block locked в the spawned phase's CONTEXT.md / DISCUSSION-LOG.md.

2. **Re-open `999.18.1-ADR.md`.** For each of the 4 cross-cutting choices the ADR locked (orchestrator finalist + (a) `pnpm deploy --prod` keep / drop + (b) `injectWorkspacePackages` keep-with-mit / drop-entirely + (c) image base + (d) contract-gen placement):
   (a) Is the choice still optimal под new context (per fired trigger evidence)? If NO → flip Status sentinel в ADR-001 к `☒ Superseded by ADR-NNN (post-trigger T-NN re-evaluation)`.
   (b) If YES → annotate ADR-001 §Status section с line `**Re-evaluated:** YYYY-MM-DD against trigger T-NN — choice retained` and proceed (no new ADR drafted; trigger entry в этом документе flipped к `☒ Fired (YYYY-MM-DD, → re-evaluation confirmed ADR-001)` per Step 5).

3. **If ANY choice flips, draft a new ADR (ADR-002, ADR-003, ...)** per MADR canonical pattern (CONTEXT D-14). Old ADR-001 retains `☒ Superseded` status; new ADR cites old via `**Supersedes:** ADR-001` line в его §References section. C-01..C-13 weighted scoring re-applied под new context (per ADR §Decision §D.1 matrix); finalist may change.

4. **Trigger 999.NN.2 implementation phase** per the new ADR's MIGRATION-RUNBOOK.md (mirror 999.18.1 → 999.18.2 sub-decimal pattern). New phase consumes new ADR + new DOCKERFILE-REFERENCE + new MIGRATION-RUNBOOK; carries-forward этот документ как RE-EVAL contract registry.

5. **Update this document:** flip the fired trigger T-NN status from `☑ Active` к `☒ Fired (YYYY-MM-DD, → triggered ADR-NNN re-eval)`. Optionally add new triggers если post-evaluation context exposed new condition surfaces (e.g., new toolchain entrant, new compliance regulation). New triggers получают next-available T-<CATEGORY>-NN ID per §"Trigger ID convention".

## Trigger ID convention

- **T-SCALE-NN** — service count, polyglot, team size triggers (project growth axis)
- **T-TOOL-NN** — toolchain landscape (pnpm, Bazel, Buck2, Pants, Nx, Turborepo) triggers (external tool ecosystem axis)
- **T-CI-NN** — CI / infrastructure (cycle wall-clock, GitLab migration, registry migration, k8s digest-pinning) triggers (deploy pipeline axis)
- **T-AUDIT-NN** — compliance (SBOM, reproducible-builds, SLSA) triggers (regulatory axis)
- **T-PROC-NN** — process / quality (patch-on-patch recurrence, finding-class recurrence, smoke gate failures, **k8s native gRPC probe migration** per T-PROC-04) triggers (project-internal quality + cluster baseline axis)
- **T-DEAD-NN** — static-detection (orphan Dockerfile stage, unreachable module export, dead-code architectural surface) triggers (canonical-shape audit axis)

Cross-reference: triggers referenced from `999.18.1-MIGRATION-RUNBOOK.md` rollback procedure («if T-PROC-01 fires post-Wave-2, rollback per §Rollback anchors per wave») и от any future ADR Status sentinel that flips via re-evaluation.
