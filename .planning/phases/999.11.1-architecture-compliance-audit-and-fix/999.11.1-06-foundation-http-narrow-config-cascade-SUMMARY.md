Making envToken an opt lets the caller pick their app's token."
  - "Generic TEnv default `Record<string, unknown>` — preserves caller ergonomics when the TEnv type parameter is omitted (not used here but important for future smoke/test clients)."
  - "Bracket index access `deps.env[VENDOR_ENV.KEY] as string` over direct field access `deps.env.TELEGRAM_BOT_TOKEN` — the plan §Task 2 offered both. Bracket form was chosen because it preserves the 'VENDOR_ENV constant is the single source of truth for env-key strings' principle established in Phase 24 — direct property access hardcodes the field name in two places (constant definition + consumer). Both forms type-check identically under TEnv extends Record<string, unknown>; the bracket+cast form stays consistent with how other foundation factories do env-key lookup (e.g. define-grpc-client.ts `config.grpcUrls[opts.service.envKeys.GRPC_URL]`)."

## Decisions Made

- **envToken as an opt (not a generic parameter)** — see key-decisions above. Runtime identity doesn't belong in a compile-time generic slot.
- **No foundation-narrow HttpClientConfig interface** — vendor field sets differ (TELEGRAM_BOT_TOKEN vs APPSTORESPY_API_KEY vs CLOUDFN_API_KEY). A fixed narrow interface would either be a union (awkward typing) or a very loose `Record` (defeats the purpose). Generic TEnv with caller-supplied narrow type is the idiomatic shape.
- **Bracket `deps.env[VENDOR_ENV.KEY] as string`** over direct `deps.env.TELEGRAM_BOT_TOKEN` — preserves VENDOR_ENV constant as single source of truth for env-key strings (Phase 24 no-magic-values canon). Both forms type-check identically; bracket form chosen for consistency with Plan 05's `config.grpcUrls[opts.service.envKeys.GRPC_URL]`.
- **Import types via `../../config` barrel** — shorter than plan's `../../../infrastructure/config` spelling; same index.ts resolution.
- **Single atomic commit** — Plan 04/05 precedent. Splitting per task would leave the build red between Task 1 and Task 2 (callback shape breaking change).
- **No generic-parameter-substituting fallback** — plan suggested omitting the TEnv type parameter at callsite would default to `Record<string, unknown>`; used explicit `<TelegramClient, NotifierEnv>` (etc.) at every callsite for typed property access inside the build callback.
