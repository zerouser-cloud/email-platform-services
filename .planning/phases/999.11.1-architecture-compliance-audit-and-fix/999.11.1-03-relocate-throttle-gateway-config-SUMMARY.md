## Decisions Made

- **Single atomic commit for 2 tasks** — plan §success_criteria specified "One atomic commit `refactor(999.11.1-03): relocate ThrottleModule + migrate to GATEWAY_CONFIG`"; both tasks must commit together so gateway.module.ts imports a file that exists at the path it references in the same commit (no intermediate broken state).
- **`import type { GatewayEnv } from '../config'`** (barrel path) rather than `'../config/gateway-env.schema'` (direct path) — barrel `apps/gateway/src/infrastructure/config/index.ts` exists and re-exports both `GatewayEnvSchema` and `GatewayEnv`; using the barrel is the canonical consumer surface.
- **THROTTLE_TIER block preserved byte-identical** — no-magic-values skill owns these string literals; relocating the module doesn't change tier semantics, so the `as const` block stays verbatim. Only the DI plumbing changed.
- **Empty `apps/gateway/src/throttle/` left on disk for Git auto-untrack** — follows Phase 999.11.1-02 + Phase 999.11 precedent. Git does not track directories; `git ls-files apps/gateway/src/throttle/` returns 0. The empty directory on local filesystem has zero impact on cloned repos (they won't get it) and will be cleaned by any future `git clean -fdx` or simply ignored. Plan explicitly forbids manual `rmdir`.
- **Rename similarity at 57%** (git's detection threshold) — the body rewrite (strip ConfigService wiring, add GATEWAY_CONFIG/GatewayEnv imports, change factory arg types, replace 4 callsite expressions) exceeds the 50% default threshold so `git log --follow` and `git blame` continue to trace history through the rename seamlessly.
