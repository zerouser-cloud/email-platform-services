## Decisions Made

- **Atomic single-commit closure.** Task 1/2/3 each leave the workspace intentionally broken (imports point at a deleted module OR `"@nestjs/config"` still declared while source is absent). Committing only after Task 4's `pnpm install && pnpm lint && pnpm build` green is the only safe granularity per plan §objective Build-failure window. A 4-commit split would ship 3 broken-build snapshots to reflog.
- **Orphan {Svc}EnvSchema imports purged in Task 1.** `{Svc}EnvSchema` was the only argument to `AppConfigModule.forRoot()`, so its import became dead code the moment `AppConfigModule.forRoot(Schema)` was removed. Left in, they would trigger `@typescript-eslint/no-unused-vars` errors in Task 4's lint — treated as blocking-issue auto-fix (Rule 3).
- **packages/config peerDeps narrowed to @nestjs/common only.** After `AppConfigModule` deletion, `packages/config/src/` contains only plain Zod validation (`config-loader.ts`) + topology/catalog helpers. Zero NestJS DI surface. `@nestjs/common` remains only because `z` utilities may be consumed in app contexts that already have it — and `@nestjs/common` is a workspace universal.
- **Stale `dist/` cleanup during Task 4 acid-grep.** An orphan `packages/config/dist/app-config.service.d.ts` (from a long-removed `AppConfigService` source file — unrelated to `AppConfigModule`) caused the D-11 inv1 grep to report `count: 1` despite all source being clean. Fixed by `rm -rf .turbo node_modules/.cache/turbo packages/*/dist apps/*/dist` + `pnpm build` — `dist/` is gitignored so no commit churn. Lesson: turbo task cache can restore stale emit after source deletion unless turbo cache is also cleared.
- **Out-of-scope unstaged files preserved.** `apps/gateway/src/infrastructure/clients/audience/audience-client.module.ts` and `packages/foundation/src/external/grpc/clients/promisify-grpc-client.ts` were already modified in the working tree before Plan 09 started (per session-start `git status`). They belong to a different owning phase and were NOT staged. Similar precedent set by Plan 08 SUMMARY.

## Deviations from Plan

**1. [Rule 3 — Blocking issue] Prettier auto-format of auth.module.ts imports array**
- **Found during:** Task 4 `pnpm lint`
- **Issue:** After removing `AppConfigModule.forRoot(AuthEnvSchema)` from auth's imports, the remaining 2 entries (`PersistenceModule.forRootAsync(), LoggingModule.forGrpcAsync('auth')`) were 3-line array. Prettier rule requires 2-item arrays on one line.
- **Fix:** Collapsed `imports: [\n    PersistenceModule.forRootAsync(),\n    LoggingModule.forGrpcAsync('auth'),\n  ]` → `imports: [PersistenceModule.forRootAsync(), LoggingModule.forGrpcAsync('auth')]`
- **Files modified:** `apps/auth/src/auth.module.ts` only (other modules have 3+ imports, no collapse triggered)
- **Commit:** `2d14d30` (included in atomic commit)

**2. [Rule 3 — Blocking issue] Turbo task cache + stale dist/ hygiene**
- **Found during:** Task 4 acid-grep (D-11 inv1 reported count=1 from stale `packages/config/dist/app-config.service.d.ts`)
- **Issue:** An ancient orphan `.d.ts` in `packages/config/dist/` held a `from '@nestjs/config'` import. File gitignored (safe) but contaminated the acid grep. First `rm -rf packages/*/dist` was silently overridden by turbo's task cache restoring outputs on next `pnpm build`.
- **Fix:** `rm -rf .turbo node_modules/.cache/turbo packages/*/dist apps/*/dist` → fresh `pnpm build` from scratch. All 10 tasks executed (cache: 0), acid grep returned 0 as expected.
- **Files modified:** None in source — `dist/` + `.turbo/` are gitignored.
- **Commit:** N/A (build hygiene, not source change)
