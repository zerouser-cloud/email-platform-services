## Decisions Made
- **Shape A (inline) vs Shape B (shared helper):** Adopted Shape A per RESEARCH.md §6 recommendation — 4 files × 3 extra lines = 12 LOC, below the DRY extraction threshold. Each config stays self-contained and readable without a new helper module. A shared helper would be premature abstraction for four build-tool configs that happen to share a single env var.
- **Import path: `@email-platform/config` vs deeper `@email-platform/config/schemas/database`:** Used the barrel re-export. The `DatabaseSchema` named export is available at the top-level barrel (via `packages/config/src/schemas/index.ts` → `./database`), matches the standard import style used throughout `apps/`, and keeps CLI configs insensitive to internal refactors of the config package.
- **No fallbacks / no defaults:** Zod `.url()` validation fires if `DATABASE_URL` is missing or malformed; matches env-schema skill's "no fallbacks in consumer code" rule. drizzle-kit will surface a Zod error at CLI startup, which is the correct failure mode.
