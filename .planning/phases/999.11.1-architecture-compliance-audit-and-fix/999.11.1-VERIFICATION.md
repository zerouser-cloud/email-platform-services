## Regression Analysis

**Single regression caught and closed within this phase:**

Plan 04 introduced `LOGGING_CONFIG_PORT` as a root-module provider. Plan 09 removed `@nestjs/config` (which had `AppConfigModule` marked `isGlobal: true`). Combined, these two changes broke nested third-party `forRootAsync({ inject: [LOGGING_CONFIG_PORT] })` consumers in foundation modules, because root-module providers are NOT automatically visible inside nested `forRootAsync` scopes.

**Discovery vector:** D-15 dual-mode smoke gate — first boot attempt threw `UnknownDependenciesException: can't resolve Symbol(LOGGING_CONFIG_PORT)`.

**Closure:** Commit `6122f43` introduces `@Global() {Svc}ConfigModule.forRoot()` per service, which preserves the global-visibility semantics that `AppConfigModule` previously provided. After the fix, both native and isolated smoke flows passed HTTP 200.

**Skill update (commit `4d93805`):** the `@Global()` requirement is now documented as MANDATORY (not optional) in `infrastructure-client-layering/SKILL.md §Config` — this prevents Phases 999.12 (Redis) / 999.13 (RMQ) / 999.14 (S3) from hitting the same regression.

**No other regressions observed.** Container log scan confirmed 0 error/warn across 6 containers in the last 2 minutes of the smoke window (recorded in Plan 10 SUMMARY metadata).
