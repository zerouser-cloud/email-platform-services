<objective>
**Commit 4 of 10** — `refactor(999.11.1-04): foundation narrow-config migration — cache + persistence + logging + storage`

Introduce narrow `*Config` interfaces + `*_CONFIG_PORT` Symbols in foundation for 5 single-instance modules (cache, persistence, logging, s3-core, shared-namespace public). Swap each module's `inject: [ConfigService]` → `inject: [*_CONFIG_PORT]`. In each consuming app, register slice providers (useFactory inject [{SVC}_CONFIG]) that project `{Svc}Env` into the narrow shape the foundation expects.

Addresses: **D-10** (foundation narrow config interfaces — Approach C at foundation↔apps boundary), **D-12** callsites IC-01/IC-02/IC-03/IC-07/IC-08 (~14 ConfigService references gone from foundation), **NMV-02** auto-resolved (env-key magic strings disappear via typed reads), **IC-03 bonus** (removes `as LogLevel`/`as LogFormat` casts).

**Why:** Foundation must be service-agnostic (Infrastructure-client-layering: Mechanism layer). Narrow interfaces enforce this — foundation receives only what it uses, apps own the slicing.

**Scope boundary:** This plan does NOT touch gRPC clients (Plan 05), HTTP clients (Plan 06), or `@nestjs/config` dep removal (Plan 09). AppConfigModule still registered — ConfigService still reachable to any NOT-YET-migrated consumer.

**Critical ordering (PT within plan):** in each app module edit, use foundation's exported `*_CONFIG_PORT` Symbols — NOT local duplicates. Barrel exports must be in place BEFORE apps edit.
</objective>
