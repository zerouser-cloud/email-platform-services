## Decisions Made

- **grpcUrls as Record lookup over discrete fields** — Unlike single-instance Plan 04 modules (cache = `{REDIS_URL}`, persistence = `{DATABASE_URL}`), gRPC clients need per-upstream URLs. Options considered: (a) discrete `AUTH_GRPC_URL?` / `SENDER_GRPC_URL?` / etc. fields with optional typing (awkward, leaky), (b) generic `grpcUrls: Record<string,string>` lookup keyed by env-var name (chosen — foundation does `config.grpcUrls[opts.service.envKeys.GRPC_URL]` in constant time, apps project typed reads from `{Svc}Env`). Option (b) matches the SERVICE catalog's per-upstream keying naturally.
- **Per-app scope — apps include only upstreams they consume** — Gateway calls all 5 domain services so it projects all 5 URLs; sender only calls audience so it projects one; same for parser→notifier and audience→parser. This is the "apps own the slice projection" principle from D-10 applied to multi-instance modules. No excess providers, no drift possibility.
- **No slice in notifier + auth** — Audit per plan Task 4 acceptance: notifier consumes no gRPC client modules (RMQ consumer only); auth is a backend service exposing gRPC but not calling any upstream. Registering GRPC_CLIENT_CONFIG_PORT there would be dead weight (foundation wouldn't ever inject it in those apps). Correct to omit.
- **5 per-upstream `*-client.module.ts` files unchanged** — They call `defineGrpcClient<TRaw>({ service, clientToken })` which is the only surface exposed to them. Internal rewire of that factory is transparent. This matches plan §objective "they don't change (they invoke `defineGrpcClient(...)`; migration is foundation-internal)."
- **PT-11 preservation verified** — The plan explicitly warned about confusing `packages/foundation/src/external/grpc/grpc-client.module.ts` (dead) with `packages/foundation/src/external/grpc/clients/define-grpc-client.ts` (live). Pre-delete grep confirmed the former has zero consumers while the latter is used by 5 per-upstream modules. Both paths handled correctly — dead one deleted, live one enhanced.
- **No `grpc/index.ts` barrel edit needed** — Task 3 §action mentioned removing a potential `export * from './grpc-client.module'` line, but `packages/foundation/src/external/grpc/` has no `index.ts` barrel (verified via `ls`); `clients/` has its own barrel (unchanged naming — only the existing re-exports plus new clients.constants + grpc-client.interfaces). Skipped that step per "only if that line exists" clause.
- **Single atomic commit** — Same rationale as Plan 04 (OQ-7): splitting per task would require intermediate broken-build states (Task 2 alone breaks build until Task 4 wires apps).
- **Pre-existing cosmetic diffs left untouched** — `apps/gateway/src/infrastructure/clients/audience/audience-client.module.ts` and `packages/foundation/src/external/grpc/clients/promisify-grpc-client.ts` have pre-session whitespace-only drift (noted in Plan 04 SUMMARY as "out-of-scope — probably future Plan 05 staging"). Not included in this commit since Plan 05 semantics do not require those edits. They'll be handled elsewhere or reverted separately.
