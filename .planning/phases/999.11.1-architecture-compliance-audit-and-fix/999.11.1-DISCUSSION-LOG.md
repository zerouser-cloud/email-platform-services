## Area 3: drizzle.config.ts fix approach (expanded to Config Access Contract)

Начинался как узкий вопрос (3 helper-варианта), но user pivot'нул на архитектурный:

> "У нас же есть механизм который даёт конфиги в приложение, или он не работает на этом уровне?"

Это раскрыло broader discussion по Canonical Config Access Contract (build-time + runtime).

**Claude explained 2-layer mechanism:**
- Layer 1 (runtime NestJS DI): `AppConfigModule` + `loadGlobalConfig()` + `ConfigService`
- Layer 2 (raw Zod schemas): `DatabaseSchema`/`RedisSchema`/etc. — pure exports
- drizzle.config.ts runs outside NestJS → Layer 1 недоступен, Layer 2 reuse работает

### Sub-decision D2: Per-service config token

Расширили обсуждение до runtime-механизма (убрать type loss в `configService.get<T>()!`).

| Option | Description | Selected |
|---|---|---|
| A1: Single generic APP_CONFIG Symbol | Один токен, тип на inject-site | |
| A2: Per-service {SVC}_CONFIG Symbol (Recommended) | По аналогии с gRPC canonical pattern | ✓ |

**User's rationale:** "A2 — per service, это будет наподобие GRPC и других клиентов, то есть каждый сервис берёт заготовки и мастерит себе клиенты, конфиги и т.д и использует уже их."

### Sub-decision D3: Foundation boundary

Claude показал через Redis worked example: foundation объявляет narrow `CacheConfig` interface, apps делают slice из `{SVC}_CONFIG` в этот shape. Foundation никогда не знает про `SenderEnv`/`AuthEnv`.

**User confirmed** через "Отлично, да" после Redis example walkthrough.

### Sub-decision D1: Layer rule

**Claude's initial proposal:** infra + module factories OK; application services ⚠️ avoid; use-cases/domain 🚫.

**User's refinement:**
> "Может конфиги прокидывать на каждый сервис с самого верха в модуль, что бы они были доступны везде в слоях nest, но глубже, в useCase уже прокидывать в конструктор?"

**Clarification:** Config технически доступен через DI во всём @Injectable, но convention:
- ✅ Infra + module factories + **application services** (seam между env и business logic)
- 🚫 Use-cases — получают env-values через **method args** (не constructor — constructor это DI seam для портов)
- 🚫 Domain (уже enforced через ESLint Override 8)

**User approved refined version:** "Давай пробовать"
