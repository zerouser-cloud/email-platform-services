### IN-01: ESLint flat config — `no-restricted-imports` в Override 4 и Override 5 семантика «last-match-wins», не «merge»

**File:** `eslint.config.cjs:171-252`
**Issue:**
В flat config ESLint v9 правила со значениями-объектами (как `no-restricted-imports`) при множественных матчах НЕ объединяются — последний матч ПЕРЕЗАПИСЫВАЕТ предыдущий. Файл `apps/auth/src/infrastructure/outbound/persistence/persistence.module.ts` совпадает с обоими Override 4 (`apps/*/src/**/*.ts`) И Override 5 (`apps/*/src/infrastructure/**/*.ts`). В таком случае `no-restricted-imports` Override 5 ПОЛНОСТЬЮ заменяет Override 4 для файлов в `infrastructure/`.

Override 5 содержит:
- ban апсов→апсов (есть)
- ban `from 'pg'` (есть)
- НЕТ ban `ioredis` (намеренно — narrow-unlock D-13)
- НЕТ ban `foundation/internal` (намеренно — Phase 22.1 разрешение)

Текущая реализация D-01 корректна: оба Override содержат `pg`-ban, поэтому эффект эквивалентен независимо от порядка матчинга. Это явная избыточность по дизайну (D-01 «stricter than ioredis pattern»). Однако комментарий «Override 5: same as Override 4 minus ioredis (...); pg banned in both per Phase 999.19 F-02 V2» (строка 216) использует фразу «same as Override 4 minus ioredis» — это вводит в заблуждение, потому что Override 5 НЕ переопределяет ВСЁ из Override 4, а ЗАМЕНЯЕТ Override 4 для матчающих файлов. Без ban-а в Override 5 правило Override 4 не применилось бы (оно бы было затёрто).

**Почему Info, а не Warning:** функционально корректно (D-01 явно требует «in BOTH overrides»), но комментарий описывает поведение через старую `extends`-метафору `.eslintrc.js`, которая не соответствует семантике flat config. Будущий редактор может подумать, что добавление правила только в Override 4 покроет infrastructure/ — это ошибка.

**Fix:** Уточнить комментарий выше Override 5 (строки 216-217), указав явно flat-config семантику:

```diff
-    // Override 5: apps/*/src/infrastructure — same as Override 4 minus ioredis (infrastructure may use Redis via narrow-unlock); pg banned in both per Phase 999.19 F-02 V2.
-    // Preserves verbatim semantics of legacy .eslintrc.js lines 108-125.
+    // Override 5: apps/*/src/infrastructure — flat-config semantics: this block REPLACES Override 4's `no-restricted-imports` for files matching `apps/*/src/infrastructure/**` (last-match-wins, not merge). Therefore Override 5 must independently re-state every ban that should still hold here. ioredis is intentionally OMITTED (narrow-unlock D-13); pg is banned in BOTH Override 4 and Override 5 (Phase 999.19 F-02 V2 D-01).
+    // Preserves verbatim semantics of legacy .eslintrc.js lines 108-125 (eslintrc cascade collapsed identically — both layers re-stated rules per `overrides[]` entry).
```

(альтернативно: можно вынести общие patterns в локальную const и спредить в оба Override, чтобы избежать drift — но это refactor, выходящий за scope V2)
