## Three-Tier Classification (proposed framework)

**Tier 1 — Domain-role abstractions (MUST be tech-agnostic):**
- Health DI tokens binding `*HealthIndicator` types
- Service DI tokens binding port interfaces
- Config port DI tokens
- Type names (`*HealthIndicator`, `*Port`, `*Service`)

**Tier 2 — Raw library instance tokens (legitimately tech-specific):**
- `S3_CLIENT`, `DRIZZLE`, `PG_POOL`, `REDIS_CLIENT` — это конкретные объекты конкретных библиотек. DI инжектит реальный `pg.Pool`, не интерфейс. Имя должно honest отражать identity.
- Phase 21 D-04 + 999.12 D-13: `REDIS_CLIENT` приватный кроме narrow consumers (throttle storage). Tech-name подчёркивает "это escape hatch".

**Tier 3 — Library-specific defaults/constants (tech-name OK):**
- `S3_DEFAULTS` (FORCE_PATH_STYLE — AWS SDK option)
- `PG_POOL_DEFAULTS` (max connections — pg-specific)
- `REDIS_DEFAULTS` (KEEP_ALIVE_MS — ioredis option)
- `*_HEALTH_CHECK` constants (`PING`, `SELECT 1` — конкретные команды)
- Tech-name = honest. Переименовать в abstract — потеряем читаемость.

## Field Naming (apps/*/src/infrastructure/bootstrap/health/health.controller.ts)

Текущее состояние per Phase 999.12 audit:
```typescript
@Inject(REDIS_HEALTH) private readonly redis: CacheHealthIndicator
@Inject(DATABASE_HEALTH) private readonly db: DatabaseHealthIndicator
@Inject(PARSER_STORAGE_HEALTH) private readonly parserStorage: StorageHealthIndicator
@Inject(PUBLIC_BUCKET_HEALTH) private readonly publicBucket: StorageHealthIndicator
```

Field naming rules per Phase 999.10.1:
- **Domain-role suffix** mirrored (Repository, Storage — ubiquitous language) ✓
- **Architectural-role suffix** (Port, Adapter, UseCase) NOT mirrored

`Cache` is architectural role (как Repository, Storage) — следовательно `cache` уместно для field. Symmetric с `db` (Database is domain), `parserStorage` (Storage is domain).

**Proposed rename:** `redis` → `cache` в 6 health.controller.ts files.
