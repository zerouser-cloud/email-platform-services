#### Audit Framework

- **D-01:** Tier 1/2/3 framework принят как audit criterion (per `999.12.1-NOTES.md`):
  - **Tier 1** = domain-role abstractions, MUST be tech-agnostic. Health DI tokens, service DI tokens, config port DI tokens, abstract type names (`*HealthIndicator`, `*Port`, `*Service`).

## Summary

Phase 999.12.1 is a **structural rename refactor** with **zero behavior change**. It applies a single architectural rule — *layer-name axis for Tier-1 abstract surface* — across 4 backing-service layers (cache, persistence, storage, messaging-stub) by:

1. Renaming 5 foundation Symbols + 1 type + 4 string keys (across 5 affected foundation files).
2. Updating 6 health.controllers + 1 reports.module + 1 health.module (notifier).
3. Promoting `RabbitMqHealthIndicator` from class-based DI to Symbol-based DI under a new `external/messaging/` folder (mirrors cache/persistence/storage skeleton).
4. Extracting `COLUMN_LENGTH` from `persistence.constants.ts` to a separate file (orthogonal to PG-pool).
5. Codifying the Tier 1/2/3 framework + layer-name axis rule in `infrastructure-client-layering/SKILL.md` using fictional names (per 999.11.4.1 D-3) + adding a CLAUDE.md cross-link + inventory matrix touch-up.

Total touched files: **~22 source files + 2 doc files**. Total commits expected: **~7-9 atomic commits** following the 999.12 D-18 per-concern precedent. Verification gate: dual-mode runtime smoke (`pnpm start:native` + `pnpm start:isolated`) + workspace-wide grep invariants showing zero residual occurrences of the old token/type/string names.

**Primary recommendation:** Adopt the wave plan in §"Wave / Ordering Analysis" — foundation Symbols rename FIRST (one wave per layer), then app sites in lock-step per layer, then HEALTH.INDICATOR keys, then COLUMN_LENGTH extraction, then skill + CLAUDE.md docs. Each layer's foundation rename + its consumers MUST be in the SAME atomic commit (semantic atomicity — DI token rename without consumer update breaks the build).

### Pattern 1: Layer-Name Axis for Tier-1 Tokens

**What:** A single uniform rule for naming Tier-1 abstract surface artefacts: the artefact's prefix MUST equal its hexagonal layer name (`cache` / `persistence` / `storage` / `messaging`), NOT the backing-service domain (database / queue / object-store), NOT the specific tech (Postgres / Redis / S3 / RabbitMQ).

**When to use:** Whenever a new Tier-1 abstraction enters the foundation surface — health DI tokens, service DI tokens, config-port DI tokens, abstract type names.

**Example (post-rename, real):**

```typescript
// packages/foundation/src/external/cache/cache.constants.ts
export const CACHE_HEALTH = Symbol('CACHE_HEALTH');         // T1 — layer-name axis ✓
export const CACHE_SERVICE = Symbol('CACHE_SERVICE');       // T1 ✓
export const CACHE_CONFIG_PORT = Symbol('CACHE_CONFIG_PORT'); // T1 ✓
export const REDIS_CLIENT = Symbol('REDIS_CLIENT');         // T2 — raw lib instance, tech-name OK
export const REDIS_DEFAULTS = { ... } as const;             // T3 — library-specific, tech-name OK
```

**Counter-example (pre-rename — what we're fixing):**

```typescript
// BEFORE: tech-named token binding abstract type — drift
export const REDIS_HEALTH = Symbol('REDIS_HEALTH');         // T1 ✗ tech-named
@Inject(REDIS_HEALTH) private readonly redis: CacheHealthIndicator;
//      ^^^^^^^^^^^^                  ^^^^^^^^^^^^^^^^^^^^^^^^^
//      tech identifier               abstract type → mismatch
```

[VERIFIED: codebase pre-rename + CONTEXT.md]

### Pattern 2: Field Naming — Domain-Role Mirror, Architectural-Role NOT Mirror (Phase 999.10.1)

**What:** Inject field names mirror the **domain-role** suffix of the type they hold (`Repository`, `Storage`, `Cache`, `Messaging` — ubiquitous-language terms) but DO NOT mirror **architectural-role** suffixes (`Port`, `Adapter`, `UseCase` — hexagonal jargon).

**When to use:** Every `constructor(...) { @Inject(TOKEN) private readonly fieldName: SomeTypeIndicator/Port/...)` site.

**Application in this phase:**

| Field name | Type | DI token | Domain or arch role? |
|------------|------|----------|----------------------|
| `cache` | `CacheHealthIndicator` | `CACHE_HEALTH` | Domain (`Cache` is hexagonal layer + ubiquitous-language) — mirror ON field |
| `persistence` | `PersistenceHealthIndicator` | `PERSISTENCE_HEALTH` | Domain — mirror ON field |
| `publicStorage` | `StorageHealthIndicator` | `PUBLIC_STORAGE_HEALTH` | Domain (`Storage` ubiquitous) — mirror ON field |
| `messaging` | `MessagingHealthIndicator` | `MESSAGING_HEALTH` | Domain — mirror ON field |
| `parserStorage` (existing) | `StorageHealthIndicator` | `PARSER_STORAGE_HEALTH` | Domain — mirror ON field |

**Suffix `Indicator` is omitted from field name** because `Indicator` is a Terminus framework artefact, not domain language. (Mirrors how `Port` / `UseCase` are also omitted from fields.)

### Anti-Patterns to Avoid

- **Tech-named Tier-1 token binding abstract type** (`REDIS_HEALTH` → `CacheHealthIndicator`). The exact drift this phase fixes. Caught by manual review of `cache.constants.ts` against `cache.interfaces.ts` — token name + bound type must share the same axis.
- **Mirror architectural-role suffix on field name** (e.g., `cachePort: CachePort` instead of just `cache: CachePort`). `Port` is hexagonal jargon, not domain. Phase 999.10.1 D-LOCKED.
- **Class-based DI for Tier-1 indicator** (`@Injectable() class RabbitMqHealthIndicator` injected without `@Inject(SYMBOL)`). The current state of `RabbitMqHealthIndicator` — D-08 fixes by promoting to Symbol DI.
- **Co-locate orthogonal generic constants with library-specific constants** (e.g., `COLUMN_LENGTH` next to `PG_POOL_DEFAULTS` in same file). D-10 fixes by extraction.
- **Mix Tier-1 + Tier-2 + Tier-3 in same `as const` object.** Always separate at the symbol/object level (current `cache.constants.ts` already does this — preserved).

## Common Pitfalls

### Pitfall 1: Foundation rename without consumer update in same commit

**What goes wrong:** Rename `REDIS_HEALTH` → `CACHE_HEALTH` in `cache.constants.ts` only, push commit. App health.controllers (which import `REDIS_HEALTH`) instantly fail to build. Per-commit `pnpm build` gate fails.

**Why it happens:** Splitting a semantically-atomic change across multiple commits (Phase 999.12 D-18 invariant violation).

**How to avoid:** Per-token atomic commit. Foundation file + ALL consumer files in single commit. Plan-phase MUST list all consumers per token from §"Site Inventory" and lock them into the same wave.

**Warning signs:** `pnpm build` fails on first commit but passes on second. Means the first commit was incomplete.

[VERIFIED: 999.12 D-18 + D-19 precedent + 999.11 6-commit per-concern pattern]

### Pitfall 2: HEALTH.INDICATOR rename desync from token rename

**What goes wrong:** `HEALTH.INDICATOR.REDIS` → `HEALTH.INDICATOR.CACHE` performed in commit N, but health.controller body still calls `this.cache.isHealthy(HEALTH.INDICATOR.REDIS)` — TypeScript catches this if old key is removed. But if old key is left as alias, drift persists silently.

**Why it happens:** Hard-removing a key from `as const` object would break all 11 read sites. Tempting to keep alias.

**How to avoid:** D-07 + 11 read-site updates in **same atomic commit**. Hard-remove old keys (no aliases). TypeScript build will catch any missed site.

**Warning signs:** Build green but `/health/ready` JSON has both `cache` AND `redis` keys (confirms alias-leak).

### Pitfall 3: `external/messaging/` folder export drift

**What goes wrong:** `packages/foundation/src/external/index.ts` line 22 currently `export * from './health/indicators/rabbitmq.health';` — D-08 deletes that file. If barrel still references it, `pnpm build` fails. If barrel adds `export * from './messaging';` BUT old line not removed, dual-export collision.

**Why it happens:** Manual barrel maintenance — easy to forget one of two edits.

**How to avoid:** Both lines in single commit. Verifier MUST grep `rabbitmq.health` in `packages/foundation/src/external/index.ts` post-commit — must return 0.

[VERIFIED: file `packages/foundation/src/external/index.ts` line 22 confirms current export]

### Pitfall 4: Notifier composition root re-wiring forgets `MessagingModule.forRootAsync()` import

**What goes wrong:** `health.module.ts` removes `providers: [RabbitMqHealthIndicator]` and `imports` add `MessagingModule.forRootAsync()` is missed → DI fails at boot with `UnknownDependenciesException: can't resolve Symbol(MESSAGING_HEALTH)`.

**Why it happens:** Class-DI removes are easy to grep; module-import additions are easy to forget.

**How to avoid:** Verifier MUST run `pnpm start:isolated` (boots full stack incl. notifier) and check container logs for `UnknownDependenciesException`. Static `pnpm build` does NOT catch this.

**Warning signs:** Build green but `pnpm start:isolated` fails on notifier boot.

[VERIFIED: NestJS DI semantics + 999.11.1 Pitfall on `@Global()` resolution]

### Pitfall 5: `dist/` cache invalidation across packages

**What goes wrong:** Foundation rebuilt cleanly but apps' `node_modules/@email-platform/foundation/dist/` cached still references old types. `pnpm build` thinks foundation is fresh and skips.

**Why it happens:** turbo cache hash includes content fingerprint — usually catches this. But if foundation's `package.json` is unchanged + only `.ts` content changed, edge cases possible.

**How to avoid:** Plan-phase MUST include in verification step: `pnpm build` from the workspace root (turbo orchestrates correctly). If suspicious, `rm -rf packages/*/dist apps/*/dist && pnpm build`. Verifier final smoke MUST be on a clean build.

[VERIFIED: 999.11 P04 pattern — cache miss + clean rebuild as verification step]
