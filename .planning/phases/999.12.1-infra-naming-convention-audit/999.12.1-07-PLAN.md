    ```markdown
    ## Tier 1/2/3 Token Framework + Layer-Name Axis

    Every infra-client surface declares tokens of three distinct natures. Place each
    according to its nature, not by reflex copy-paste:

    | Tier | What it represents | Naming axis | Example (fictional) |
    |------|--------------------|-------------|---------------------|
    | **Tier 1** | Abstract domain-role surface — DI tokens binding `*HealthIndicator` types, service tokens binding port interfaces, config-port tokens, abstract type names | **Layer-name** (hexagonal layer = `foo` / `bar` / etc.) | `FOO_HEALTH` (token), `FOO_SERVICE` (token), `FooHealthIndicator` (type), `FooPort` (type) — where `Foo` is the layer |
    | **Tier 2** | Raw library instance tokens — DI binds the literal library object | **Tech-name** (legitimately tech-specific — DI injects a real client/handle/connection) | `LIB_CLIENT` (e.g., raw library handle) |
    | **Tier 3** | Library-specific defaults / commands — `as const` objects holding library options | **Tech-name** (tech identifier honest — these are concrete library knobs) | `LIB_DEFAULTS = { KEEPALIVE_MS: ... } as const`, `LIB_HEALTH_CHECK = { COMMAND: 'PING' } as const` |

    ### The Layer-Name Axis Rule (Tier 1 only)

    The prefix of a Tier-1 artefact MUST equal its **hexagonal layer name** (the
    architectural layer in the Cockburn/Evans/Uncle Bob sense), NOT the
    **backing-service domain** (database / queue / object-store), NOT the
    **specific tech** (Postgres / Redis / S3 / RabbitMQ). The rule survives any
    change of underlying tech: swap one library for another and the Tier-1
    surface name `FOO_HEALTH` (where `Foo` is the layer) stays correct;
    `FOO_LIBNAME_HEALTH` would orphan immediately.

    **Rename test:** if the Tier-1 token contains the name of the backing library
    (or its synonym in domain language), it fails the rule. Fix by replacing
    the library identifier with the hexagonal-layer name.

    ### Worked Example

    A canonical implementation lives at the directory
    `packages/foundation/src/external/storage/` — open the directory to see the
    applied pattern: Tier-1 tokens prefixed with the layer name (layer-name axis),
    Tier-2 raw client tokens prefixed with the library name (tech-name honest),
    Tier-3 library options as `*_DEFAULTS` (tech-name honest).
    ```
