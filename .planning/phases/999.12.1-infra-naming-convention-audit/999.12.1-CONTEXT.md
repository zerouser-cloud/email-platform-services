<domain>
## Phase Boundary

Аудит и исправление naming convention поверх 4 backing-service layers (cache, persistence, storage, future messaging) с применением единой layer-name axis для Tier-1 abstract surface. Phase deliverable:

1. **Закрыть Tier-1 drift во всех 4 layers** (cache + persistence + storage + messaging-stub) — переименовать DI tokens / types / fields, привести к layer-name axis.
2. **Извлечь orthogonal misplacement** (COLUMN_LENGTH) из persistence.constants.ts в отдельный файл.
3. **Закодифицировать Tier 1/2/3 framework + layer-name axis convention** в skill `infrastructure-client-layering/SKILL.md` (principles) + cross-link/inventory update в CLAUDE.md.
4. **Lock messaging convention** для будущей Phase 999.13 (RabbitMQ adapter) до того как там пишется новый код.

Storage post-Phase 22.x используется как canonical reference baseline. Tier-2 (raw lib instances: REDIS_CLIENT, S3_CLIENT, DRIZZLE, PG_POOL, AMQP_CLIENT) и Tier-3 (library defaults: REDIS_DEFAULTS, PG_HEALTH, S3_DEFAULTS) — sealed, не трогаются.

<decisions>
## Implementation Decisions

### Audit Framework

- **D-01:** **Tier 1/2/3 framework принят как audit criterion** (per `999.12.1-NOTES.md`):
  - **Tier 1** = domain-role abstractions, MUST be tech-agnostic. Health DI tokens, service DI tokens, config port DI tokens, abstract type names (`*HealthIndicator`, `*Port`, `*Service`).
  - **Tier 2** = raw library instance tokens (legitimately tech-specific). DI инжектит реальный `pg.Pool` / `Redis` / `S3Client` — имя должно honest отражать identity.
  - **Tier 3** = library-specific defaults / commands. `REDIS_DEFAULTS.KEEP_ALIVE_MS`, `PG_HEALTH.QUERY='SELECT 1'`, `S3_DEFAULTS.FORCE_PATH_STYLE` — tech-name = honest.

- **D-02:** **Full audit scope** — все 4 backing-service layers (cache, persistence, storage, messaging-stub), не targeted only к известным findings из NOTES.md. Дискуссия выявила additional drifts не учтённые в NOTES.md (DATABASE_HEALTH, PUBLIC_BUCKET_HEALTH, HEALTH.INDICATOR keys).

- **D-03:** **Layer-name axis для Tier-1 naming** — единый принцип: имя Tier-1 артефакта = имя архитектурного слоя в hexagonal (`cache`, `persistence`, `storage`, `messaging`). NOT backing-service domain (database / queue / object-store) и NOT specific tech (Postgres / Redis / S3 / RabbitMQ). Проверочный тест: cache+storage+persistence все следуют layer-name axis после fix.

### Audit Findings & Fixes

#### Cache layer (`packages/foundation/src/external/cache/`)

- **D-04:** **`REDIS_HEALTH` → `CACHE_HEALTH`** (foundation token rename):
  - `packages/foundation/src/external/cache/cache.constants.ts` — Symbol declaration
  - `packages/foundation/src/external/cache/cache.providers.ts` — provider binding
  - `packages/foundation/src/external/cache/cache.module.ts` — module exports list
  - `packages/foundation/src/external/cache/index.ts` — barrel re-export
  - 6 health.controllers (`apps/{auth,sender,parser,audience,notifier,gateway}/src/infrastructure/bootstrap/health/health.controller.ts`) — `@Inject(REDIS_HEALTH)` → `@Inject(CACHE_HEALTH)` + field `redis: CacheHealthIndicator` → `cache: CacheHealthIndicator` (per 999.10.1 mirror rule — `Cache` = domain identity).
  - Comment updates в 6 health.modules + 6 outbound/cache modules (mention `REDIS_HEALTH` → `CACHE_HEALTH`).

#### Persistence layer (`packages/foundation/src/external/persistence/`)

- **D-05:** **`DATABASE_HEALTH` → `PERSISTENCE_HEALTH`** + **`DatabaseHealthIndicator` → `PersistenceHealthIndicator`** (token + type rename):
  - `packages/foundation/src/external/persistence/persistence.constants.ts` — Symbol declaration
  - Type definition file (TBD by plan-phase research; expected `external/persistence/persistence.interfaces.ts` or similar) — type rename
  - Foundation barrel export
  - 6 health.controllers — `@Inject(DATABASE_HEALTH)` → `@Inject(PERSISTENCE_HEALTH)` + field `db: DatabaseHealthIndicator` → `persistence: PersistenceHealthIndicator`.
  - **Repository fields НЕ трогаем:** `private readonly db: NodePgDatabase` в 4 pg-*.repository.ts остаются — это Tier-2 raw drizzle convention (`db` — стандартный Drizzle vocab для NodePgDatabase instance).

- **D-10:** **`COLUMN_LENGTH` extraction** в split-file `packages/foundation/src/external/persistence/column-length.constants.ts`:
  - Move out из `persistence.constants.ts` (текущее соседство с PG-specific `PG_POOL_DEFAULTS`/`PG_HEALTH` — semantic mismatch: `COLUMN_LENGTH` это generic SQL VARCHAR semantics, не PG/Drizzle-specific).
  - Barrel `external/persistence/index.ts` добавляет export из нового файла.
  - 4 schema imports (`apps/{auth,sender,parser,audience}/.../schema/*.schema.ts`) НЕ меняются — они импортируют `from '@email-platform/foundation'`.

#### Storage layer (`packages/foundation/src/external/storage/`)

- **D-06:** **`PUBLIC_BUCKET_HEALTH` → `PUBLIC_STORAGE_HEALTH`** (token rename + field rename):
  - `packages/foundation/src/external/storage/public/public.constants.ts` — Symbol declaration
  - Foundation storage barrel
  - `apps/notifier/src/infrastructure/outbound/storage/reports/reports.module.ts` — provider config
  - `apps/notifier/src/infrastructure/bootstrap/health/health.controller.ts` — `@Inject(PUBLIC_BUCKET_HEALTH)` → `@Inject(PUBLIC_STORAGE_HEALTH)` + field `publicBucket: StorageHealthIndicator` → `publicStorage: StorageHealthIndicator`.
  - Comment в `external/storage/public/shared-namespace.module.ts` (mention `PUBLIC_BUCKET_HEALTH`).

- **D-13:** **`PUBLIC_BUCKET = 'public'` literal → defer к Phase 999.14 (s3-canonical-audit).** Это config-as-data (literal bucket name в S3), отдельная concern от Tier-1 token naming.

#### Health indicator keys (`packages/foundation/src/external/health/health-constants.ts`)

- **D-07:** **`HEALTH.INDICATOR` keys rename** (Tier-1 abstract surface — попадают в JSON-ответ `/health/ready`):
  - `REDIS: 'redis'` → `CACHE: 'cache'`
  - `RABBITMQ: 'rabbitmq'` → `MESSAGING: 'messaging'`
  - `POSTGRESQL: 'postgresql'` → `PERSISTENCE: 'persistence'`
  - `MEMORY_HEAP: 'memory_heap'` остаётся — generic, не tech-specific.
  - Эффект: меняет shape JSON `/health/ready` (pre-prod, безопасно).
  - Internal indicator implementations (`packages/foundation/src/external/cache/redis.health.ts`, аналогичные для storage/persistence/messaging) обновляют использования.
  - Notifier health.controller вызовы — `this.cache.isHealthy(HEALTH.INDICATOR.CACHE)` и т.д.

#### Messaging layer (RMQ-stub) — currently scattered

- **D-08:** **`RabbitMqHealthIndicator` → `MessagingHealthIndicator`** + class-based DI → Symbol-based DI (immediate, не deferred):
  - Создать `packages/foundation/src/external/messaging/messaging.constants.ts` с `MESSAGING_HEALTH = Symbol('MESSAGING_HEALTH')`, `MESSAGING_CONFIG_PORT = Symbol('MESSAGING_CONFIG_PORT')`.
  - Создать `packages/foundation/src/external/messaging/` folder structure (parallel with `external/cache/`, `external/persistence/`, `external/storage/`).
  - Migrate `RabbitMqHealthIndicator` class → `MessagingHealthIndicator` (renamed, в новом folder).
  - Foundation barrel re-exports.
  - `apps/notifier/src/infrastructure/bootstrap/health/health.controller.ts` — replace `private readonly rabbitmq: RabbitMqHealthIndicator` (class-DI) на `@Inject(MESSAGING_HEALTH) private readonly messaging: MessagingHealthIndicator`.
  - Notifier composition root — register provider for new Symbol DI.
  - **Deferred к 999.13:** real AMQP/RabbitMQ adapter implementation (текущий health-indicator stub продолжает существовать; rename + Symbol-DI promotion = pure structural cleanup).

- **D-09:** **999.13 messaging convention locked в audit + skill** (zero-drift entry для следующей phase):
  - Folder: `packages/foundation/src/external/messaging/` (per layer-name axis — НЕ `external/rmq/`, НЕ `external/amqp/`).
  - Tier-1 tokens: `MESSAGING_HEALTH`, `MESSAGING_CONFIG_PORT`.
  - Tier-1 type: `MessagingHealthIndicator`.
  - Tier-2 raw lib instance: `AMQP_CLIENT` (или эквивалент per amqplib API — finalized в 999.13 plan-phase).
  - Tier-3 library defaults: `AMQP_DEFAULTS`, `RMQ_HEALTH_CHECK` (PING-equivalent commands).
  - Field naming в 999.13 inbound/RMQ adapters — per 999.10.1 architectural-role NOT mirrored, domain-role mirrored (`messaging` для health field, ports на usual rules).

### Tier-2 / Tier-3 Sealed (no changes)

- **D-11:** **Tier-2 raw library instance tokens** sealed — НЕ переименовываются:
  - `REDIS_CLIENT` (Phase 21 D-04 invariant + 999.12 D-13 narrow unlock)

  - `DRIZZLE`, `PG_POOL` (Phase 999.3-999.4 canonical)

  - `S3_DEFAULTS`, `S3_HEALTH_CHECK`, `S3_TIME`, `S3_ERROR_NAME`
  - Tech-name на Tier-3 = honest (это конкретные команды/опции конкретных библиотек).
