- Assertion: "The authoritative list of `pnpm` scripts that orchestrate these modes lives in `package.json`." — survives rename or content-change of every script in `package.json`. Rationale: refers to `package.json` by role (the runtime-contract file); workspace root file per D-8.
- Assertion: "The authoritative list of ports and hostnames lives in the tracked env templates at the repository root." — survives rename of `.env.example` → `.env.sample`, addition of new env templates, migration from `GATEWAY_PORT` → `GATEWAY_HTTP_PORT`. Rationale: refers to env templates by role ("tracked env templates") not by filename; grep recipe below picks up any `*_PORT=` matching the regex.
- Assertion (discovery recipe): ``node -e 'const p = JSON.parse(require("fs").readFileSync("package.json","utf8")); console.log(Object.keys(p.scripts).sort().join("\n"));'`` — survives any change to `package.json` contents. Rationale: reads the file at runtime; no cached knowledge.
- Assertion (classification rule): "any script whose name contains a role keyword (`start`, `stop`, `reset`, `build`, `lint`, `infra`, `test`) maps to the corresponding workflow step." — survives addition of new scripts following the role-keyword convention. Rationale: uses keyword predicates, not a closed enumeration.
- Assertion (discovery recipe): `ls .env* 2>/dev/null` and `grep -hE '^(GATEWAY|GATEWAY_HTTP)_PORT=' .env* 2>/dev/null | head -5` — survives rename of `.env.example` → any `.env*` name; survives `GATEWAY_PORT` → `GATEWAY_HTTP_PORT` migration (regex matches both). Rationale: `.env*` glob + regex alternation anticipate plausible future renames.
- Assertion (health-controller discovery): `find apps/gateway -name '*.controller.ts' -exec grep -l -i 'health' {} \;` — survives rename of the health controller file and change of readiness path. Rationale: `find` discovers the file by content-keyword (`health`) rather than by name.
- Assertion (workflow template): `pnpm stop:<flow>` / `pnpm start:<flow>` / `pnpm reset:<flow>` / `curl "http://localhost:${GATEWAY_PORT}/health/ready"` — survives rename of every flow-specific script and of the gateway port variable. Rationale: `<flow>` is a literal placeholder; `${GATEWAY_PORT}` is a variable reference with source cited inline. The reader binds both from discovery output.
- Assertion: "When in doubt about which flows the project currently supports, which ports the gateway currently binds, or which readiness path it exposes, run the discovery commands above." — survives every rename. Rationale: defers to the discovery recipes already established.
