# Phase 999.7.3: gRPC client promisify proxy — replace per-method wrappers - Research

**Researched:** 2026-04-18
**Domain:** TypeScript mapped types + JavaScript Proxy + NestJS @nestjs/microservices client-grpc internals + ts-proto generated client interfaces
**Confidence:** HIGH

## Summary

This is a tightly-scoped architectural cleanup: replace 8 hand-written per-method wrapper classes (~58 method wrappers) and the standalone `GrpcCaller` helper class with a single typed `Promisified<T>` Proxy in `packages/foundation`. All 21 design decisions (D-01..D-21) are locked in CONTEXT.md — no architectural alternatives to investigate. The research target is the **mechanics**: TypeScript mapped-type edge cases, JavaScript Proxy behavior on ts-proto-generated grpc-js client objects, `lastValueFrom` semantics for unary RPC, the `getService()` lifecycle, metadata propagation through the Observable wrapping, foundation barrel export ripple, migration interim-state behavior, and validation architecture for the refactor.

Key verified facts:
- `@nestjs/microservices@11.1.16` is installed; `client-grpc.js` `getService(name)` enumerates ONLY `Object.keys(clientRef[name].prototype)` — prototype-own RPC method names — and returns a plain object with one function-typed property per RPC. No symbols, no extra props beyond proto methods. **Channel binding happens at first `getService()` call** (creates `new clientRef[name](url, credentials, options)` and caches it in `this.clients`).
- `createUnaryServiceMethod` returns `(...args) => new Observable(observer => { const call = client[methodName](...args, callback); ...; return () => call.cancel(); })`. Args are spread positionally — `raw.method(req, metadata)` → `client[methodName](req, metadata, callback)`, the canonical grpc-js unary signature with metadata in middle position.
- `lastValueFrom` for unary RPC is correct semantics: unary returns one value then completes, `lastValueFrom` resolves with that single value. `firstValueFrom` would also work for unary, but `lastValueFrom` is the established pattern in `GrpcCaller` and matches NestJS canon. `EmptyError` reject only fires if Observable completes without emitting — impossible for a successful unary call.
- All 5 proto contracts (`auth`, `audience`, `parser`, `notifier`, `sender`, `common`) have **zero streaming methods** (`grep -c "responseStream: true|requestStream: true" = 0`). All RPCs are unary. Streaming-readiness is structural (mapped type + Proxy support it trivially via D-13 future migration), but no concrete streaming work needed now.
- Kamil Myśliwiec (NestJS creator) endorsed the JavaScript Proxy + `.toPromise()` (modern: `lastValueFrom`) pattern in [nestjs/nest#3710](https://github.com/nestjs/nest/issues/3710) as **"the only supported way"** to get Promise ergonomics from `nestJs=true` ts-proto clients. No native Promise mode exists in NestJS 11.1.16 (verified by reading `client-grpc.js:38-50` and `:159-210`).

**Primary recommendation:** Implement exactly as CONTEXT.md prescribes. Add the mapped-type edge-case handling (`void`/`never` returns, optional `metadata` arg, `unknown` for unrecognized callable shapes). The Proxy `get` trap must guard non-function results (Object.prototype's `toString`, `hasOwnProperty`, etc. ARE functions inherited via prototype chain — must filter by **whether the property name appears in the proto methods**, not just by `typeof`). Most reliable filter: enumerate proto methods at construction time via `Object.keys(raw)` (since `getService` returns a plain object with exactly the RPC names as own keys), then `if (!ownMethods.has(prop)) return orig` in the trap.

### Pattern 1: Promisified<T> mapped type

**What:** TypeScript mapped type that converts every `(...args) => Observable<R>` method on `T` into `(...args) => Promise<R>`. Non-function properties and intentional Observable returns pass through unchanged (future-proofs for streaming RPC by D-13).

**When to use:** Any T whose methods uniformly return `Observable<R>` and the consumer wants Promise ergonomics. Today: ts-proto-generated `XxxServiceClient` interfaces (`nestJs=true` mode).

**Example:**

```typescript
// Source: NOTES.md sketch + standard TypeScript mapped-type pattern
import type { Observable } from 'rxjs';

export type Promisified<T> = {
  [K in keyof T]: T[K] extends (...args: infer A) => Observable<infer R>
    ? (...args: A) => Promise<R>
    : T[K];
};

// Verification:
// type X = Promisified<AuthProto.AuthServiceClient>
// X['login']  →  (request: LoginRequest, metadata?: Metadata) => Promise<TokenPair>
// X['nonExistent']  →  (does not exist)
```

**Edge cases the mapped type handles correctly (verified mentally against TypeScript 5.7):**

| Input shape | Output shape | Note |
|-------------|--------------|------|
| `(req: R, meta?: Metadata) => Observable<T>` | `(req: R, meta?: Metadata) => Promise<T>` | Standard ts-proto unary — works |
| `(req: R) => Observable<T>` (no metadata arg) | `(req: R) => Promise<T>` | Works — `infer A` captures whatever args exist |
| `() => Observable<void>` | `() => Promise<void>` | Works |
| `(req: R) => Observable<never>` | `(req: R) => Promise<never>` | Works (never is valid type result) |
| `(req: R) => Observable<T> \| Observable<U>` | `(req: R) => Promise<T \| U>` | Works (`infer R` captures union) |
| `(...args: unknown[]) => unknown` (non-Observable) | passes through unchanged | Works (conditional fails the `extends`) |
| Optional method `method?: (...) => Observable<T>` | Optional preserved? | **Edge case** — `T[K]` includes `undefined` for optionals. Conditional `T[K] extends (...) => Observable<R>` evaluates `undefined extends ...` which is false → passes through. **Result: optional methods pass through as `undefined | ((...) => Observable<R>)` — Promise conversion is LOST.** Mitigation: ts-proto-generated client interfaces have NO optional methods (verified — `auth.ts:608-622` shows 7 required methods, all `(req: R, metadata?: Metadata) => Observable<T>`). If proto ever generates optional methods, mapped type would need a tweak — flag as future watch-item, not today's blocker. |
| Generic methods `<T>(req: R<T>) => Observable<T>` | Generic preserved? | **Edge case** — TypeScript distributes the conditional over the generic. Inferring `(...args: infer A) => Observable<infer R>` should preserve the type parameter via `A`/`R` capture. ts-proto does NOT generate generic methods (each RPC has concrete types). Future-watch only. |

**Recommendation:** The simple mapped type from D-07 / NOTES.md handles 100% of today's cases. Document the optional/generic edge cases in a code comment but don't pre-engineer for them.

### Pattern 2: JavaScript Proxy with method-name whitelist

**What:** A `new Proxy(raw, { get(target, prop) })` that intercepts function-typed RPC method accesses, returns an async wrapper, and passes everything else through unchanged.

**When to use:** When `T` is a typed object whose methods you want to wrap uniformly without writing one wrapper per method.

**Critical refinement vs NOTES.md sketch:** The NOTES.md sketch uses `if (typeof orig !== 'function' || typeof prop !== 'string') return orig`. This is **almost** correct but has a subtle hole: `Object.prototype.toString`, `valueOf`, `hasOwnProperty` ARE inherited functions. If consumer code (or NestJS DI machinery, or a debugger) calls `Promisified.toString()`, the trap would wrap `toString` in an async function expecting `(request, callOpts)` args — accessor returns the wrapped function, and any call to it would build Metadata for a non-RPC. Better filter:

```typescript
// Source: refinement of NOTES.md sketch
export function promisifyGrpcClient<T extends object>(
  raw: T,
  opts: PromisifyOpts,
): Promisified<T> {
  // Snapshot RPC method names at construction time.
  // ClientGrpc.getService() returns a plain object whose own keys are exactly
  // the proto method names — verified by reading client-grpc.js:38-50.
  const rpcMethods = new Set(Object.keys(raw));

  return new Proxy(raw, {
    get(target, prop, receiver): unknown {
      // Pass through symbols, prototype methods, and any non-RPC string prop.
      if (typeof prop !== 'string' || !rpcMethods.has(prop)) {
        return Reflect.get(target, prop, receiver);
      }
      const orig = Reflect.get(target, prop, receiver) as
        | ((req: unknown, meta?: Metadata) => Observable<unknown>)
        | undefined;
      if (typeof orig !== 'function') {
        return orig;
      }

      return async (request: unknown, callOpts?: CallOpts): Promise<unknown> => {
        const deadlineMs = callOpts?.deadlineMs ?? opts.defaultDeadlineMs;
        const meta = new Metadata();
        meta.set(
          GRPC_CLIENT_DEADLINE.METADATA_HEADER,
          `${deadlineMs}${GRPC_CLIENT_DEADLINE.METADATA_UNIT_MILLISECONDS}`,
        );
        return lastValueFrom(orig.call(target, request, meta));
      };
    },
  }) as Promisified<T>;
}
```

**Why `orig.call(target, ...)` not `orig(...)`:** Some object methods rely on `this` binding (the grpc-js internal client method may reference `this.client`). The NOTES.md sketch already uses `orig.call(target, request, meta)` correctly — preserve.

**Why `Reflect.get(target, prop, receiver)` not `target[prop]`:** Best-practice for Proxy traps; preserves correct `this`-binding behavior for getters (none expected on the gRPC service object, but defensive). NOTES.md sketch uses `Reflect.get(target, prop)` — passing `receiver` is the more correct form.

**Anti-Patterns to Avoid:**
- **Wrapping `toString`/`valueOf`:** Without the whitelist guard, the Proxy would intercept `Object.prototype` methods. Filter by **RPC method name set**, not by `typeof` alone.
- **Eagerly building wrapper functions at construction time:** Defeats the purpose — Proxy is more memory-efficient and handles future-added properties (irrelevant for ts-proto but cleaner).
- **Forgetting `orig.call(target, ...)`:** Could break if grpc-js internal methods rely on `this`. The 999.7.2 GrpcCaller uses callback factories so consumers always wrote `(m) => this.raw.method(req, m)` — the `.call(target, ...)` form preserves identical behavior.
- **Synchronous trap that returns Promise without `await`:** Functionally equivalent but loses stack traces; using `async` + `return lastValueFrom(...)` preserves async stack reporting. Both NOTES.md sketch and the example above use the async form.

### Pattern 3: useFactory wires Proxy directly

**What:** Modify `defineGrpcClient` so its `useFactory` builds the Promisified Proxy internally — no build callback parameter needed.

**Example:**

```typescript
// Source: D-09 specification, derived from current define-grpc-client.ts
export function defineGrpcClient<TRaw extends object>(
  opts: DefineGrpcClientOpts,
): GrpcClientBuildResult {
  const upperId = opts.service.id.toUpperCase();
  const grpcToken = Symbol.for(`${upperId}${TOKEN_SUFFIX.CLIENT_GRPC}`);
  const healthToken = Symbol.for(`${upperId}${TOKEN_SUFFIX.GRPC_HEALTH}`);

  const facadeProvider: Provider = {
    provide: opts.clientToken,
    inject: [grpcToken, ConfigService],
    useFactory: (grpc: ClientGrpc, config: ConfigService): Promisified<TRaw> => {
      const raw = grpc.getService<TRaw>(opts.service.grpc.serviceName);
```

## Common Pitfalls

### Pitfall 1: `getService()` lifecycle — when does the channel bind?

**What goes wrong:** Believing `getService()` is "lazy" and only binds the gRPC channel on first method invocation. Misunderstanding leads to fear that calling it inside `useFactory` (before HTTP server starts) might fail.

**Why it happens:** Documentation describes ts-proto runtime as "creating a Proxy"; people assume Proxy = lazy. The implementation is more precise.

**The truth (verified by reading `client-grpc.js:38-92`):**
```javascript
// client-grpc.js:38
getService(name) {
  const grpcClient = this.getClientByServiceName(name);     // ← THIS creates the channel
  // ... enumerates prototype methods, builds plain object, returns
}
// client-grpc.js:53
createClientByServiceName(name) {
  // ...
  const grpcClient = new clientRef[name](this.url, credentials, options);  // ← channel allocated HERE
  this.clients.set(name, grpcClient);
  return grpcClient;
}
```

So: `getService()` is synchronous, allocates the channel on first call, caches in `this.clients`, reuses on subsequent calls. The grpc-js internal `new Client(url, ...)` does NOT actually open a TCP connection — it lazily connects on the first RPC. So:
- `getService()` inside `useFactory` is SAFE. The channel object exists; no network I/O happens until first RPC call.
- The cached `this.clients` map means subsequent `getService(sameName)` calls are O(1) prototype-key lookup.

**How to avoid:** Don't second-guess. Call `grpc.getService<TRaw>(serviceName)` synchronously inside `useFactory` exactly as D-09 prescribes. The 999.7.x predecessor phases verified this in production runtime — current `define-grpc-client.ts:43-51` does the same pattern via `build(grpc, caller)` → `grpcClient.getService<T>(serviceName)`.

**Warning signs:** If `useFactory` throws "InvalidGrpcServiceException", it means `serviceName` doesn't match a service in the loaded proto packages — a config bug, not a lifecycle bug.

### Pitfall 2: Metadata propagation through Observable wrapping

**What goes wrong:** Worrying that the `Metadata` passed via `raw.method(req, meta)` is lost in the Observable wrapping.

**Why it happens:** The wrapping `new Observable(observer => { ... })` looks like it could swallow extra args.

**The truth (verified by reading `client-grpc.js:159-210`):**
```javascript
// client-grpc.js:159
createUnaryServiceMethod(client, methodName) {
  return (...args) => {
    // args[0] = request, args[1] = metadata (when passed)
    return new rxjs_1.Observable(observer => {
      const call = client[methodName](...args, (error, data) => {  // ← args spread INTO grpc-js call
        if (error) return observer.error(this.serializeError(error));
        observer.next(data);
        observer.complete();
      });
      return () => { if (!call.finished) call.cancel(); };
    });
  };
}
```

So `raw.method(req, meta)` becomes `client[methodName](req, meta, callback)` at the grpc-js level — exactly the canonical 3-arg unary signature `(request, metadata, callback)`. The `grpc-timeout` header in our Metadata reaches the wire. The `createDeadlineInterceptor(GRPC_DEADLINE_MS)` channel-level interceptor (`define-grpc-client.ts:78`) ALSO sets the deadline at the channel level — both layers cooperate (minimum-wins semantics; `grpc-timeout` from per-call metadata wins when smaller). Same behavior as today's `GrpcCaller`.

**How to avoid:** Don't second-guess. Pass `Metadata` as second arg to `orig.call(target, request, meta)`. Same shape as today's `(m) => this.raw.method(req, m)` callback factory.

**Warning signs:** Deadline silently not honored = check that `GRPC_CLIENT_DEADLINE.METADATA_HEADER === 'grpc-timeout'` (verified in `clients.constants.ts:8`) and `METADATA_UNIT_MILLISECONDS === 'm'` (per gRPC spec, `m` = milliseconds; valid units `n`/`u`/`m`/`S`/`M`/`H`).

### Pitfall 3: `Object.prototype` method leakage through Proxy

**What goes wrong:** Without the method-name whitelist, the Proxy intercepts `toString`, `valueOf`, `hasOwnProperty`, `Symbol.toPrimitive`, etc. — ALL functions inherited from `Object.prototype`. Calling `String(promisifiedClient)` or `console.log(promisifiedClient)` would trigger the wrapper to build Metadata for "toString" RPC, which then crashes because `target.toString.call(target, undefined, meta)` returns a string, not an Observable, and `lastValueFrom(string)` throws `TypeError: source.subscribe is not a function`.

**Why it happens:** `typeof Object.prototype.toString === 'function'` returns `true`. The NOTES.md sketch's filter `if (typeof orig !== 'function') return orig` lets these through.

**How to avoid:** Snapshot RPC method names at construction time and filter by membership:
```typescript
const rpcMethods = new Set(Object.keys(raw));  // exactly the RPC names — verified
// inside trap:
if (typeof prop !== 'string' || !rpcMethods.has(prop)) return Reflect.get(target, prop, receiver);
```

**Warning signs:** If logging/inspection of the Promisified client throws `TypeError: source.subscribe is not a function`, the trap is wrapping non-RPC inherited methods — add the whitelist.

**Why this is safe:** `client-grpc.js:38-50` enumerates `Object.keys(clientRef[name].prototype)` (proto-loader-generated class) and assigns each method-name to `grpcService[methodName]`. The returned `grpcService` is a plain object with **own** keys exactly matching proto methods. `Object.keys(grpcService)` gives those own keys deterministically.

### Pitfall 4: Symbol-keyed Proxy access (Symbol.iterator, Symbol.toPrimitive)

**What goes wrong:** NestJS or some logger might do `for (const x of promisified)` (triggers `Symbol.iterator`) or `promisified + ''` (triggers `Symbol.toPrimitive`). Without the whitelist, `Reflect.get(target, Symbol.iterator)` returns `undefined` (Object doesn't have iterator), and `typeof undefined === 'undefined'` ≠ `'function'`, so trap returns `undefined`. Safe by the NOTES.md sketch.

**Why it happens:** Symbols are the catch-all for JS metaprotocol.

**How to avoid:** The whitelist `if (typeof prop !== 'string' || !rpcMethods.has(prop))` covers symbols (typeof Symbol === 'symbol', not 'string'). Reflect.get of a non-existent symbol returns undefined → safe pass-through.

**Warning signs:** None expected — symbols pass through cleanly. This is a pre-emptive safety check.

### Pitfall 8: `lastValueFrom` vs `firstValueFrom` for unary

**What goes wrong:** Confusion about which Observable→Promise converter to use.

**The truth:** For unary RPC, the Observable from `client-grpc.js:createUnaryServiceMethod` emits ONE value via `observer.next(data)` then immediately calls `observer.complete()`. Both `lastValueFrom` and `firstValueFrom` resolve with the same single value:
- `firstValueFrom` resolves on first `next` event, then unsubscribes (cancels the call). For unary, the callback already fires `complete` synchronously after `next`, so unsubscribe is a no-op.
- `lastValueFrom` waits for `complete` event, then resolves with the most-recent `next`-emitted value. For unary, this is the SAME value.

**Difference matters only for multi-value Observables** (streaming) — irrelevant today (no streaming RPCs).

**Defensiveness:** `lastValueFrom` rejects with `EmptyError` if Observable completes without emitting. For a successful unary call, this never happens (callback always fires `next` before `complete`). For an error case, the callback fires `observer.error(err)` which causes `lastValueFrom` to reject with `err` directly (not `EmptyError`).

**How to avoid:** Use `lastValueFrom` for symmetry with current `GrpcCaller` (continuity) and matching Kamil's #3710 reference pattern. Either works for unary. **Decision: keep `lastValueFrom`.**

**Warning signs:** None. Both functions handle unary identically.

### Promisify Proxy implementation (consolidated final form)

```typescript
// File: packages/foundation/src/external/grpc/clients/promisify-grpc-client.ts
// Source: D-07 + D-08 + Pitfall 3 refinement
import { Metadata } from '@grpc/grpc-js';
import { type Observable, lastValueFrom } from 'rxjs';
import { GRPC_CLIENT_DEADLINE } from './clients.constants';
import type { CallOpts } from './grpc-client-logging.types';

/**
 * Maps every `(...args) => Observable<R>` method on T to `(...args) => Promise<R>`.
 * Non-function properties and intentional Observable returns (future streaming) pass through.
 *
 * Edge cases:
 * - Optional methods (T[K] = undefined | (...) => Observable<R>): pass through unchanged.
 *   ts-proto-generated XxxServiceClient interfaces have no optional methods; not a concern today.
 * - Generic methods (<T>(req: R<T>) => Observable<T>): TypeScript distributes the conditional
 *   over generics correctly. ts-proto does not generate generic methods; not a concern today.
 */
export type Promisified<T> = {
  [K in keyof T]: T[K] extends (...args: infer A) => Observable<infer R>
    ? (...args: A) => Promise<R>
    : T[K];
};

export interface PromisifyOpts {
  readonly defaultDeadlineMs: number;
}

/**
 * Wrap a raw `ClientGrpc.getService<T>()` return in a typed Promise-returning Proxy.
 * The Proxy:
 *   1. Filters by RPC method name (snapshotted at construction) — does NOT wrap inherited
 *      Object.prototype methods (toString, valueOf, hasOwnProperty, etc.)
 *   2. Builds Metadata with grpc-timeout deadline header per call (default + per-call override)
 *   3. Converts Observable → Promise via lastValueFrom
 *
 * No logging, no tracing, no retry — those are deliberate omissions per phase 999.7.3 D-03..D-05.
 * Future observability phase will compose an outer Proxy (`wrapWithObservability`) around this
 * inner Proxy via DI-injected logger/cls.
 *
 * Channel binding: opts/grpc.getService(name) inside useFactory creates the gRPC channel
 * synchronously and caches it. No network I/O until first RPC method call.
 */
export function promisifyGrpcClient<T extends object>(
  raw: T,
  opts: PromisifyOpts,
): Promisified<T> {
  // ClientGrpc.getService(name) returns a plain object with own keys equal to RPC method
  // names — verified in @nestjs/microservices/client/client-grpc.js:38-50.
  const rpcMethods = new Set(Object.keys(raw));

  return new Proxy(raw, {
    get(target, prop, receiver): unknown {
      if (typeof prop !== 'string' || !rpcMethods.has(prop)) {
        return Reflect.get(target, prop, receiver);
      }
      const orig = Reflect.get(target, prop, receiver) as
        | ((req: unknown, meta?: Metadata) => Observable<unknown>)
        | undefined;
      if (typeof orig !== 'function') {
        return orig;
      }

      return async (request: unknown, callOpts?: CallOpts): Promise<unknown> => {
        const deadlineMs = callOpts?.deadlineMs ?? opts.defaultDeadlineMs;
        const meta = new Metadata();
        meta.set(
          GRPC_CLIENT_DEADLINE.METADATA_HEADER,
          `${deadlineMs}${GRPC_CLIENT_DEADLINE.METADATA_UNIT_MILLISECONDS}`,
        );
        return lastValueFrom(orig.call(target, request, meta));
      };
    },
  }) as Promisified<T>;
}
```

```typescript
import { GrpcClientHealthIndicator } from './grpc-client-health.indicator';
// REMOVED: import { GrpcCaller } from './grpc-caller';
import { promisifyGrpcClient, type Promisified } from './promisify-grpc-client';

const TOKEN_SUFFIX = {
  CLIENT_GRPC: '_CLIENT_GRPC',
  GRPC_HEALTH: '_GRPC_HEALTH',
} as const;

export interface DefineGrpcClientOpts {
  readonly service: GrpcServiceDeclaration;
  readonly clientToken: symbol;
}

export interface GrpcClientBuildResult {
  readonly imports: Array<Type<unknown> | DynamicModule>;
  readonly providers: Provider[];
  readonly exports: symbol[];
  readonly grpcToken: symbol;
  readonly healthToken: symbol;
}

// CHANGED: removed `build` callback parameter; useFactory builds Promisified Proxy directly.
export function defineGrpcClient<TRaw extends object>(
  opts: DefineGrpcClientOpts,
): GrpcClientBuildResult {
  const upperId = opts.service.id.toUpperCase();
  const grpcToken = Symbol.for(`${upperId}${TOKEN_SUFFIX.CLIENT_GRPC}`);
  const healthToken = Symbol.for(`${upperId}${TOKEN_SUFFIX.GRPC_HEALTH}`);

  const facadeProvider: Provider = {
    provide: opts.clientToken,
    inject: [grpcToken, ConfigService],  // CHANGED: removed ClsService
    useFactory: (grpc: ClientGrpc, config: ConfigService): Promisified<TRaw> => {
      const raw = grpc.getService<TRaw>(opts.service.grpc.serviceName);
      return promisifyGrpcClient(raw, {
        defaultDeadlineMs: config.get<number>('GRPC_DEADLINE_MS')!,
      });
    },
  };

  const healthProvider: Provider = {
    provide: healthToken,
    inject: [HealthIndicatorService, grpcToken],
    useFactory: (his: HealthIndicatorService, grpc: ClientGrpc) =>
      new GrpcClientHealthIndicator(his, grpc),
  };

  return {
    imports: [
      TerminusModule,
      ClientsModule.registerAsync([
        {
          name: grpcToken,
          inject: [ConfigService],
          useFactory: (config: ConfigService) => ({
            transport: Transport.GRPC,
            options: {
              url: config.get<string>(opts.service.envKeys.GRPC_URL!)!,
              package: [opts.service.grpc.package, GRPC_CLIENT_HEALTH.PACKAGE],
              protoPath: [
                resolveProtoPath(opts.service.grpc.package, config.get<string>('PROTO_DIR')!),
                require.resolve('grpc-health-check/proto/health/v1/health.proto'),
              ],
              channelOptions: {
                interceptors: [createDeadlineInterceptor(config.get<number>('GRPC_DEADLINE_MS')!)],
              },
            },
          }),
        },
      ]),
    ],
    providers: [facadeProvider, healthProvider],
    exports: [opts.clientToken, healthToken],
    grpcToken,
    healthToken,
  };
}
```
