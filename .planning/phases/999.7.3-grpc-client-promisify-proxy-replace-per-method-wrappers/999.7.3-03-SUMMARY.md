## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking, atomic with each sweep commit] Inline retype of `apps/gateway/src/test/grpc-client-sanity.ts` per upstream**

- **Found during:** Each of Tasks 1–4 (immediately after deleting the corresponding `*.client.ts` file).
- **Issue:** Sanity probe imports each `{Xxx}Client` class as a TYPE for parameter annotations. After the sweep deletes the class and removes it from the barrel, this import would fail with TS2305 ("Module '...' has no exported member '{Xxx}Client'") and gateway typecheck would NOT clear — contradicting the plan's primary acceptance criterion.
- **Fix:** Per upstream, drop the class type import and switch the parameter type to `Promisified<{Xxx}Proto.{Xxx}ServiceClient>`. For audience (Task 3), `_probeNegative` also retyped — the `@ts-expect-error` directives still resolve correctly because `Promisified<T>` preserves the per-method proto signature, so `nonExistentMethod` still raises TS2339 and `listRecipients({ wrongField: 1 })` still raises TS2353.
- **Files modified:** `apps/gateway/src/test/grpc-client-sanity.ts`
- **Verification:** `pnpm --filter @email-platform/gateway typecheck` after each commit shows the cumulative TS error count drop monotonically: 8 → 6 → 4 → 2 → 0.
- **Committed in:** `8297d04`, `eec1619`, `8ad2fee`, `517d30f` (one per sweep, atomic with the deletion that triggered the fix).
- **Why this is the right call:** Mirrors Plan 02 precedent verbatim. Rule 3 scope-boundary satisfied — each fix is directly caused by the corresponding sweep's deletion (not pre-existing).

**2. [Rule 3 — Blocking, atomic with parser + notifier sweep commits] Inline retype of `apps/gateway/src/test/storage-smoke.controller.ts`**

- **Found during:** Task 2 (parser sweep) + Task 4 (notifier sweep).
- **Issue:** storage-smoke.controller.ts imports `ParserClient` and `NotifierClient` as TYPES for `@Inject` decorator parameters. After the parser/notifier sweeps delete the classes, these imports would fail with TS2305 — gateway typecheck would NOT clear — deferred runtime smoke could not reach /health/ready.
- **Fix:** Replace `ParserClient` type import with `Promisified` import from foundation; change constructor param types to `Promisified<ParserProto.ParserServiceClient>` and `Promisified<NotifierProto.NotifierServiceClient>`. Method bodies (`this.parser.runStorageSmoke({})`, etc.) unchanged — Promisified preserves the per-method Promise return shape.
- **Files modified:** `apps/gateway/src/test/storage-smoke.controller.ts` (2 commits)
- **Verification:** Gateway typecheck stays clean; storage-smoke routes still mount successfully (verified during runtime smoke — gateway logs `Mapped {/test/parser/storage-service, GET}` and the corresponding DELETE/GET routes).
- **Committed in:** `eec1619` (parser sweep) and `517d30f` (notifier sweep).
- **Why this is the right call:** The plan's note ("do NOT touch storage-smoke.controller.ts in this plan") was overridden by the executor prompt's deviation_handling section, which explicitly grants permission to fix consumer-side type-patches inline atomically. Without this fix, the BLOCKING smoke gate that Plan 02 deferred to Plan 03 would be impossible to even attempt.
