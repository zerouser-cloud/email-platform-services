**Plain-class `GrpcCaller` helper landed in foundation (metadata build + Observable->Promise + structured logging), `defineGrpcClient` build callback evolved to 2-arg `(grpcClient, caller) => T` with internal `new GrpcCaller(...)` inside useFactory, barrel type-only re-exports the helper — foundation half of composition-over-inheritance refactor, Plan 02 restores gateway typecheck next.**

## Accomplishments

- Created `packages/foundation/src/external/grpc/clients/grpc-caller.ts` — 99-line plain ES class with no NestJS decorators, no lifecycle hooks, no ClientGrpc coupling. Encapsulates three concerns: `buildMetadata` (private, deadline header construction), `call` (public, callback-factory signature with try/finally logging), `emitLog` + `getLogger` (lazy pino child resolution).
- Evolved `packages/foundation/src/external/grpc/clients/define-grpc-client.ts` — build parameter type changed from `(grpc: ClientGrpc, cls: ClsService, deadlineMs: number) => T` to `(grpcClient: ClientGrpc, caller: GrpcCaller) => T`; useFactory body expanded to instantiate `new GrpcCaller(cls, opts.service.grpc.serviceName, config.get<number>('GRPC_DEADLINE_MS')!, \`${upperId}Client\`)` before delegating to the caller-supplied `build`. Inject array unchanged (still 3 elements: `[grpcToken, ClsService, ConfigService]`). `DefineGrpcClientOpts` + `GrpcClientBuildResult` interface shapes unchanged per D-08.
- Updated `packages/foundation/src/external/grpc/clients/index.ts` barrel — added `export type { GrpcCaller } from './grpc-caller';` (type-only per D-09 + Pitfall 5 encapsulation); kept `export { AbstractGrpcClient }` line (removal reserved for Plan 04 after all 8 client classes migrate).
