## Decisions Made

1. **Strict replication from Wave 2 AuthClient template with per-upstream substitutions only.** No semantic deviations between Wave 2 pilot (7 methods), Wave 3 sweep (4 clients, 31 methods), and Wave 4 sweep (3 clients, 20 methods). Every difference was mechanical: proto namespace (`AuthProto` → `AudienceProto`/`NotifierProto`/`ParserProto`), `SERVICE.<id>` (`.auth` → `.audience`/`.notifier`/`.parser`), class name, method list. This is exactly what PATTERNS.md entry 7 prescribes and what the user confirmed in their D-13/D-14 pre-discussion.

2. **Fixed prettier nits inline in the same atomic commit.** Unlike Wave 3 — where a Wave 2 leftover required a separate `style(...)` commit to keep Task 4's scope clean — Wave 4 had no pre-existing leftover. Each per-task prettier nit (detected by `pnpm --filter=<app> lint` before commit) was fixed directly in the task's client file and committed as part of the single `refactor(...)` commit. Result: exactly 3 atomic commits from this plan, one per upstream, per D-14.

3. **Workspace-wide gates (`pnpm build && pnpm lint`) run AFTER Task 3 commits, not as a separate commit.** The final gate is a verification checkpoint — it proves Option 5c interim state (foundation changed in Plan 01, 8 modules broken, 8 modules healed over Waves 2/3/4) has fully resolved. No fourth commit needed because the verification produces no diff.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking (prettier)] Task 2 — NotifierClient cleanupStorageSmoke formatting**
- **Found during:** Task 2 `pnpm --filter=@email-platform/parser lint` (pre-commit gate)
- **Issue:** Prettier demanded the `cleanupStorageSmoke` call be inlined on one line (the 3-line broken form with trailing comma was rejected by prettier/prettier rule).
- **Fix:** Collapsed `return this.grpc.call('cleanupStorageSmoke', opts, (m) =>\n  this.raw.cleanupStorageSmoke(req, m),\n);` into a single line. Semantics identical.
- **Files modified:** `apps/parser/src/infrastructure/clients/notifier/notifier.client.ts`
- **Committed in:** `0bcaa1b` (folded into Task 2 atomic commit, not a separate style commit)

**2. [Rule 3 — Blocking (prettier)] Task 3 — ParserClient getTask signature formatting**
- **Found during:** Task 3 `pnpm --filter=@email-platform/audience lint` (pre-commit gate)
- **Issue:** Prettier demanded the `getTask(req: ..., opts?: ...)` signature be inlined on one line (mirror of AuthClient style where shorter signatures fit). The 3-line broken form was rejected by prettier/prettier rule.
- **Fix:** Collapsed `getTask(\n  req: ...,\n  opts?: ...,\n): Promise<...>` into a single line. No behavior change.
- **Files modified:** `apps/audience/src/infrastructure/clients/parser/parser.client.ts`
- **Committed in:** `a6d67d1` (folded into Task 3 atomic commit, not a separate style commit)

**Total deviations:** 2 auto-fixed prettier nits (Rule 3, both blocking the pre-commit lint gate). Zero architectural deviations. Zero scope creep.

## Issues Encountered

1. **Fresh worktree required `pnpm install`.** Node_modules was empty — ran `pnpm install` before the first typecheck. Turbo cache was warm from prior plans so most tasks were cached. Not a regression.
2. **Prettier line-wrap heuristic differs per method signature length.** Prettier collapses signatures that fit on one line and wraps ones that don't — the mechanical replication from Wave 3 (which had longer signatures that wrap) occasionally emitted a shorter signature that prettier wanted inline. Caught by per-task lint gate, fixed inline, not a real issue.

## Known Stubs

None. Pure structural refactor — 20 method bodies are 1:1 behavioral replacements of `this.call(method, this.raw.method(req, this.buildMetadata(opts)))` → `this.grpc.call(method, opts, (m) => this.raw.method(req, m))`. Transport semantics are identical (deadline header, correlationId via cls, pino logging) because `GrpcCaller` encapsulates exactly the concerns `AbstractGrpcClient` used to own.
