## Pre-discussion context

Phase 22.5 was inserted as a prerequisite to Phase 22.4 after Phase 22.4's research agent discovered a blocking divergence: **Garage does NOT support anonymous GET via S3 API** (only via website mode on a separate port). This meant that code written against MinIO local semantics would not work in dev/prod Garage. User's response: rather than patch, unify the backend. "Есть ли npm пакет garage что бы мы заменили им minio, что бы везде было одинаково?" — led to migrating local from MinIO to Garage.

Researcher and planner must both understand: this is a **deliberate infrastructure unification**, not just a MinIO replacement.

## Ports

| Option | Description | Selected |
|--------|-------------|----------|
| Native 3900/3902 | STORAGE_PORT=3900 (S3 API), стандартные порты Garage, никаких overrides | ✓ |
| Override to 9000 | Garage configured via garage.toml to bind :9000, сохранить MinIO-like URL | |
| Hybrid 9000:3900 | Внутри native 3900, published host-port 9000 | |

**User's choice:** Native Garage ports. Rationale: hosting-parity (STORAGE_PORT=3900 в prod Coolify, подтверждено user-предоставленными env vars). "Fake familiarity" через override был отвергнут — маскирует Garage под MinIO.

## Bootstrap

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-entrypoint idempotent | Docker entrypoint wrapper, автоматический layout+key+bucket при первом старте | |
| Manual + helper script | pnpm garage:bootstrap wrapper вокруг docker exec. Оператор запускает вручную | ✓ |
| Pure manual via runbook | Без helper, docker exec команды из runbook напрямую | |
| Custom pre-built image | Свой Docker image с bootstrap внутри | |

**User's clarification question (important):** "Как это делается у нас на хостинге, там ведь тоже garage? Должно быть однообразно". This shifted rec from auto-entrypoint (my initial lean) to manual via runbook (hosting parity).

Claude's verification via runbook reading: hosting bootstrap — 100% manual через Garage WebUI (Phase 22.2 "docs, not code" rationale). Package.json script checks revealed `pnpm stop:isolated` → `docker compose down` без `-v` → volumes persist. User confirmed creds в prod "созданы один раз и не меняются" → hosting Garage container stable, volume persistent.

**Decision rationale:** unified philosophy with hosting + helper script для local ergonomics (fresh clone + `pnpm garage:bootstrap` одной командой вместо копирования 6 docker exec строк).

## Credentials

**User clarification question:** "при minio этого не было, что ты имеешь ввиду?". Triggered explanation of MinIO root-creds model vs Garage key-creation model.

**User second question:** "можно ли сами ключи положить в файлы и эти файлы добавить в gitignore, или вообще они же будут в .env и т.д, может их брать оттуда?". Triggered git state check.

Claude's finding: `.env.docker` уже committed с `STORAGE_ACCESS_KEY=minioadmin`/`STORAGE_SECRET_KEY=minioadmin` — это текущий паттерн проекта. Static test creds в git — сознательно, безопасно для local-only.

| Option | Description | Selected |
|--------|-------------|----------|
| Static test keys в .env.docker | Фиксированные values commit'ятся, bootstrap использует garage key import | ✓ |
| Generated в gitignored .env.local | Bootstrap создаёт случайные keys, пишет в .env.local, docker-compose overlay | |
| Manual через runbook | Оператор сам запускает garage key create, копирует values в .env.docker локально | |

**User's choice:** Static test keys. Rationale: продолжение существующего паттерна проекта (как с MinIO сейчас), reproducible между dev-машинами, для local test Garage безопасно. Visual-distinct from prod keys (`GKTESTLOCAL...` vs `GK2e05ee8...`) mitigates copy-paste ошибки.

## Bucket scope

| Option | Description | Selected |
|--------|-------------|----------|
| parser + reports | Точная копия текущего local setup, 22.3 smoke без изменений | |
| parser + public (сливает с 22.4) | Убирает reports вообще, 22.5 поглощает DI rename из 22.4 | ✓ |
| parser + reports + public | Все три, reports остаётся до 22.4 cleanup | |

**User's choice:** parser + public directly. Implications:
- `ReportsStorageModule` и `REPORTS_STORAGE` token удаляются в 22.5 (был scope 22.4)
- Parser + notifier storage modules обновляются для использования `PUBLIC_STORAGE`
- 22.3 smoke-контроллеры обновляются в рамках 22.5
- Hosting bucket rename (Coolify Garage WebUI): dev + prod bucket `reports` → `public`
- Scope 22.5 расширяется с "только local" на "local + hosting" — но это закономерно, т.к. code changes применяются во всех окружениях

**User acknowledged expanded scope — choice stands.** Phase boundary становится функциональной: 22.5 = plumbing (backend + rename), 22.4 = feature (public URL abstraction).
