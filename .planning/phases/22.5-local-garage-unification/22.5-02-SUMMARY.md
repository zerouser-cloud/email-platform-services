# Phase 22.5 Plan 02: Foundation Reports → Public Rename Summary

One-liner: Renamed the `ReportsStorageModule` / `REPORTS_*` DI surface in the foundation package to `PublicStorageModule` / `PUBLIC_*`, creating `packages/foundation/src/external/storage/public/` as a verbatim clone of the deleted `reports/` subdir and flipping the external storage barrel atomically.

## Scope

Pure foundation-package refactor implementing CONTEXT.md decisions D-19, D-20, D-23. Zero app-level files touched — Plan 22.5-03 in Wave 2 updates the app consumers (apps/parser, apps/notifier, apps/gateway smoke controllers). Deliberately file-disjoint from Plan 22.5-01 (which swaps MinIO → Garage in infra/ + env files) to enable Wave 1 parallelism.

The type-only `export type { StorageHealthIndicator } from '../../internal/storage'` line is preserved verbatim per Phase 22.1 carry-forward.

### Deleted: reports/ subdirectory

Three files removed: `reports/reports.constants.ts`, `reports/reports-storage.module.ts`, `reports/index.ts`. The `REPORTS_STORAGE`, `REPORTS_STORAGE_HEALTH`, `REPORTS_BUCKET`, `REPORTS_HEALTH_KEY`, `ReportsStorageModule` surface no longer exists anywhere under `packages/foundation/src/`.

## Decisions Made

- **Symbol description format**: Chose `Symbol('PUBLIC_STORAGE')` (UPPER_SNAKE matching the const name) over the RESEARCH "Code Examples" snippet's `Symbol('PublicStorage')` (PascalCase) because the existing in-tree convention in `reports.constants.ts` uses UPPER_SNAKE. Consistency with surrounding code wins over the RESEARCH example.
- **Relative import path preserved**: `../../../internal/storage` (not `@email-platform/foundation/internal`). Per Phase 22.1-04 convention, the `@subpath` form is reserved for app consumers — intra-package files use relative imports.
- **Type-only re-export of `StorageHealthIndicator`**: Kept verbatim so health controllers (which this plan does NOT touch) retain their type annotation target. Carried forward from Phase 22.1 Plan 02.
