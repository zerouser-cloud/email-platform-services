## Issues found and fixed during verification (gap-closure)

Three bootstrap-blocking bugs surfaced during user's first manual attempt; orchestrator-fixed before completing acceptance:

### Bug 1 (CRITICAL): Invalid Garage access key format
**Symptom:** `garage key import` returned `InvalidRequest (400): Bad request: Invalid key format: The specified key ID is not a valid Garage key ID (starts with GK, followed by 12 hex-encoded bytes)`

**Root cause:** `STORAGE_ACCESS_KEY=GKTESTLOCAL0123456789ab` violated Garage's strict format constraint. Garage requires exactly `GK` + 24 hex characters (12 bytes hex-encoded). The original value (a) was 21 chars after `GK` (not 24) and (b) contained non-hex letters `T`, `L`. Original CONTEXT.md D-11 picked the value for "visual distinctness from prod" without verifying Garage's validation rules.

**Fix:** Replaced with `GKdeadbeef0000000000000000` (24 hex chars, visually distinct via `deadbeef` test marker, all valid hex). Updated in `.env.docker`, `.env.example`. Future runbook reads will match.

### Bug 2: GARAGE_ADMIN_TOKEN compose-time warning
**Symptom:** `WARN[0000] The "GARAGE_ADMIN_TOKEN" variable is not set. Defaulting to a blank string.` from `pnpm docker:up`.

**Root cause:** Docker Compose only auto-loads `.env`, not `.env.docker`. The compose YAML references `${GARAGE_ADMIN_TOKEN}` for both `garage` and `garage-webui` services, and at parse time those came up empty — silently breaking the WebUI's admin API auth (and any other env-substituted reference).

**Fix:** Added `--env-file .env.docker` to all four pnpm scripts: `infra:up`, `infra:down`, `docker:up`, `docker:down`. Compose now loads `.env.docker` for variable interpolation in all start/stop commands.

### Bug 3: `test` binary missing in near-scratch Garage image
**Symptom:** `OCI runtime exec failed: exec failed: unable to start container process: exec: "test": executable file not found in $PATH` from idempotence check.

**Root cause:** `dxflrs/garage` is a near-scratch image — only `/garage` binary exists. No `test`, no `ls`, no `cat`, no busybox. The bootstrap script's idempotence check used `docker exec "$CONTAINER" test -f /var/lib/garage/meta/.bootstrapped` which needed a missing binary.

**Fix:** Replaced marker-file approach with `garage bucket list` output check — uses only the `/garage` binary that's guaranteed present. Bootstrap is "done" if both `parser` and `public` buckets exist. Each bootstrap step also gets `|| echo "(already exists — continuing)"` for graceful idempotence on partial-failure recovery scenarios.
