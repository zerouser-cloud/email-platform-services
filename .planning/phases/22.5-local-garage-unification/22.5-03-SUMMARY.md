# Phase 22.5 Plan 03: Apps REPORTS_* → PUBLIC_* Rename Summary

One-liner: Updated all six app-level consumers in apps/parser and apps/notifier (storage modules, smoke controllers, health controllers) to import `PublicStorageModule` / `PUBLIC_STORAGE` / `PUBLIC_STORAGE_HEALTH` / `PUBLIC_BUCKET` / `PUBLIC_HEALTH_KEY` from `@email-platform/foundation`, closing the Wave 1 → Wave 2 atomic handoff opened by Plan 02 and restoring workspace-wide green `pnpm build` and `pnpm typecheck`.

## Scope

Pure mechanical symbol substitution across six files. No logic changes, no behavioral changes, no proto changes, no gateway changes. The smoke step lifecycle (upload → exists → download → getSignedUrl), the SmokeBucketEntry shape, the bucket iteration order, and the health-probe count are byte-stable aside from the renamed identifiers. Implements CONTEXT.md decisions D-21, D-22, D-23.

### Gateway verified untouched

`apps/gateway/src/test/storage-smoke.controller.ts` and `apps/gateway/src/test/smoke-test.module.ts` were read but **not modified**. They proxy via gRPC (`parserService.runStorageSmoke()` / `notifierService.runStorageSmoke()`) and have no import dependency on the foundation storage symbols. Verified clean: `grep -E "REPORTS_STORAGE|PublicStorageModule"` against both files returns zero matches. The renamed bucket name appears in the JSON RESPONSE returned by parser/notifier RPCs over the wire, not in the gateway source.

### No straggler files

A workspace-wide `grep -rE "REPORTS_STORAGE|REPORTS_BUCKET|REPORTS_HEALTH_KEY|REPORTS_STORAGE_HEALTH|ReportsStorageModule" apps/ packages/ --include="*.ts"` against source (excluding `dist/`) returns zero results. The only matches were stale `packages/foundation/dist/external/storage/reports/*.d.ts` build artifacts left over from the pre-22.5-02 compile; they were removed before the build step (see Deviations) and regenerated correctly by `pnpm build` (no `reports/` subdir emitted now).

## Decisions Made

- **Substitution scope kept mechanical**: applied the table from PLAN `<interfaces>` verbatim. Did not rename any other identifiers (e.g., the `bucket` field on `SmokeBucketEntry`, the proto field names, the `RunStorageSmoke` gRPC method name) — all stay the same.
- **Buckets array order preserved**: parser smoke controller still iterates `[PARSER_STORAGE, PUBLIC_STORAGE]` (was `[PARSER_*, REPORTS_*]`) — gateway proxy parses by bucket-name field in the response, so the rename flows transparently.
- **No SUMMARY changes to gateway**: explicitly DOES NOT touch the gateway smoke controller per D-22 design (gateway is decoupled by gRPC proxy boundary, never imported REPORTS_*).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] Removed stale `packages/foundation/dist/external/storage/reports/` directory before build verification**

- **Found during:** Task 2 final verification step, when the workspace-wide grep `grep -rE "REPORTS_*" apps/ packages/ --include="*.ts"` returned 6 hits — all in `packages/foundation/dist/external/storage/reports/*.d.ts`.
- **Issue:** Stale TypeScript declaration files emitted by a pre-Plan-22.5-02 build of foundation. The source `reports/` subdir was deleted in commit `f446648` (Plan 02), but the `dist/` artifacts were never re-emitted before this plan started, so they lingered as orphans.
- **Impact:** No runtime impact (no source consumes them; no app TS file references them). Pure cleanliness — the acceptance criterion `! grep -rqE "REPORTS_*" apps/ packages/ --include="*.ts"` would otherwise trip on these `.d.ts` artifacts.
- **Fix:** `rm -rf packages/foundation/dist/external/storage/reports`. Then ran `pnpm typecheck` and `pnpm build` — both regenerated `packages/foundation/dist/external/storage/public/` and confirmed no `reports/` subdir is re-emitted.
- **Files touched:** `packages/foundation/dist/external/storage/reports/` (deleted; dist is gitignored, no commit needed).
- **Commit:** n/a (gitignored artifact cleanup).
