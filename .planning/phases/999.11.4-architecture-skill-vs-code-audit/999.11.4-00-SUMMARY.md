## Decisions Made

- **Format: MD over JSON.** D-05 (Claude's Discretion). Chose MD because: project's prevailing markdown convention; codebase maps (`.planning/codebase/*.md`) and STATE.md use MD; downstream Plan 02/03 sub-agents read MD natively; no JSON tooling exists in pipeline.
- **Topic-area inference: keyword-based, priority-ordered.** 14 regex patterns, each assigned priority 1–4. First match wins; unmatched decisions bucket into `uncategorized`. Table locked in Plan 00 Task 1 Step 4 and documented in index Methodology footer.
- **Orphan severity heuristic: 3-tier.** `high` = last-5-phases (999.10+) AND topic-area has existing skill (active drift); `medium` = any phase AND topic-area has existing skill (stale); `low` = `uncategorized` OR deprecated phase. Locked in Plan 00 Task 2 Step 4.
- **Compact orphan section layout.** High-severity = full per-decision table (43 rows); medium-severity = full per-decision table with truncated 90-char summaries (137 rows); uncategorized = full per-decision table with suggested-new-skill column (47 rows). Additional orphan-stats-by-topic summary table at end. Total orphan section ≈ 280 lines — avoids duplicating 227 rows already visible in By Topic Area §* tables above.
- **Orphan rule (conservative matching).** A decision is orphan if its D-XX ID is not cited **anywhere** in any of the candidate skills' SKILL.md + references/*.md body (phase-independent D-ID matching). Two skills currently cite phase D-XXs: `nestjs-hexagonal-mapping` (20 D-XXs: D-01..D-12, D-16..D-23, D-11a) and `infrastructure-client-layering` (3 D-XXs: D-09, D-10, D-11a). All other 9 skills cite zero phase D-XXs — expected for AUTHORITATIVE skills (they describe universal rules, not phase-specific decisions).

- **Issue:** Plan's inference table mentioned "config (env-schema, twelve-factor, no-magic-values applied to env vars)" as a single topic, but `env-schema`-specific decisions (Zod, .optional, z.coerce, composeSchemas) are semantically distinct from general `config` (DI via ConfigService, loadConfig). **2. [Rule 2 — Missing critical functionality] Added `## Letter-Suffix Decision References` subsection**

- **Found during:** Task 1 verify step (acceptance criterion: "Letter-suffix variants captured (verify: `grep -E 'D-[0-9]+[a-z]\\b'` returns at least 1 match)")
- **Issue:** Letter-suffix D-XX variants (D-11a, D-11b, D-12a, D-12b) appear as **references** in CONTEXT/SUMMARY text, not as self-contained `- **D-11a:** ...` bullet-format decisions. The main extraction regex `^- \*\*(D-\d+[a-z]?)[:.]?\*\*` does not capture them. Without handling, the letter-suffix acceptance criterion would fail.
- **Fix:** Added second-pass scan (`letter_suffix.py`) that greps for letter-suffixed `D-XX` ID mentions anywhere in CONTEXT/SUMMARY files, deduplicates by (phase, d_id, source_file) tuple, and lists them in a separate `## Letter-Suffix Decision References` subsection below `## By Topic Area`. 14 references captured from 999.11.2, 999.11.3, 999.7.1.
- **Files modified:** Added new subsection to index; added `letter_suffix.py` to build pipeline (build artifacts under `/tmp/999.11.4-build/` not committed).
- **Impact:** Task 1 acceptance criterion satisfied — `grep -cE 'D-[0-9]+[a-z]\\b'` returns 15 (the table rows + the one header mention of "D-11a" in commentary).
