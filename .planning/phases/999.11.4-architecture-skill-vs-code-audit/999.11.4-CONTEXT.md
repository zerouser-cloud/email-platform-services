<decisions>
## Implementation Decisions

### Execution Model

- **D-01:** Orchestrator + parallel sub-agents grouped by direction class. NOT single sequential auditor (context exhaustion risk on 10 × Heavy depth) and NOT fully parallel 10 sub-agents (consistency risk).
- **D-02:** Three direction-class batches, executed sequentially, each batch spawns N parallel sub-agents with identical methodology instructions:
  - **AUTH batch** (6 parallel sub-agents): `no-magic-values`, `twelve-factor`, `env-schema`, `infrastructure-guard`, `gsd-flow-guard`, `branching-patterns`. Methodology: grep-against-rules — auditor greps codebase for skill-defined violations.
  - **DESC batch** (2 parallel sub-agents): `nestjs-hexagonal-mapping`, `infrastructure-client-layering`. Methodology: skill-vs-phase-decisions — auditor compares skill text against sanctioned phase decisions from phase-decision index.
  - **HYBRID batch** (3 parallel sub-agents): `runtime-smoke-verification`, `composition-over-inheritance`, `clean-ddd-hexagonal`. Methodology: combo — per-section classification (which part AUTH, which part DESC) then apply corresponding methodology per section.
- **D-03:** Orchestrator role — aggregates per-skill sub-agent findings into `999.11.4-AUDIT.md`, enforces 4 mandatory field completeness (direction tag, evidence, phase-decision xref, remediation type), runs cross-skill consistency checks.

### Phase-Decision Evidence Lookup Methodology

- **D-04:** Pre-build phase-decision index in Plan-0 (preparation plan, no audit work). Parser reads all `D-XX` patterns from `.planning/phases/*/{phase}-CONTEXT.md` and `.planning/phases/*/{phase}-SUMMARY.md` across all ~40 phases. Output: `999.11.4-PHASE-DECISIONS-INDEX.md` or `.json` (format TBD in Plan-0) — machine-readable lookup table.
- **D-05:** Index grouped by skill/topic area (e.g., "config", "grpc", "architecture", "persistence", "storage", "hexagonal-layers", "composition"). Sub-agents in DESC/HYBRID batches query the index by skill-area for fast cross-ref, avoiding per-finding ad-hoc greps.
- **D-06:** Bonus deliverable — "orphan" phase-decisions (sanctioned in CONTEXT/SUMMARY but not reflected in any skill) are flagged in AUDIT.md as separate `## Orphan Phase-Decisions` section. Not a Requirement, but comes free from the index build and informs future skill-creation candidates.

### Sequencing & Plan Structure

- **D-07:** 5 plans total, sequential execution order enforced by dependencies:
  - **Plan 0** — Phase-decision index build (output: `999.11.4-PHASE-DECISIONS-INDEX.{md|json}`)
  - **Plan 1** — AUTH batch (6 parallel sub-agents; output: 6 per-skill sections in AUDIT.md)
  - **Plan 2** — DESC batch (2 parallel sub-agents; requires Plan 0; output: 2 per-skill sections)
  - **Plan 3** — HYBRID batch (3 parallel sub-agents; requires Plan 0; output: 3 per-skill sections)
  - **Plan 4** — SOLUTIONS.md synthesis + reclassification consolidation + AUDIT.md finalization (Summary table + orphan section + reclassification proposals section + error-handling skip note)
- **D-08:** Rationale — batch-by-direction-class keeps methodology homogeneous within a plan. Auditor sub-agents in AUTH all do grep-against-rules; DESC all do skill-vs-phase-decisions; HYBRID all do per-section combo. No cognitive mode-switching inside a single sub-agent.

### Finding Conventions

- **D-11:** AUDIT.md per-finding fields (MANDATORY per SPEC Requirement 2-5): `id`, `direction` (AUTHORITATIVE/DESCRIPTIVE/HYBRID), `claim` (what the finding asserts), `evidence` (grep output excerpt or `file:line` ref), `phase_decision_xref` (D-XX ref for DESC/HYBRID; OR `ad-hoc drift` flag for DESC/HYBRID without sanctioned decision; N/A for pure AUTH), `recommended_remediation` (refresh-skill / fix-code / leave-as-is). `severity` (blocker/major/minor) is **optional** per Round-2 decision.

### Reclassification Mechanism

- **D-12:** If a sub-agent wants to propose reclassification of a skill direction (e.g., "no-magic-values should be HYBRID because `0/1/-1 idiom` exemption blurs the rule"), the proposal goes into a **separate `## Reclassification Proposals` section** at the end of AUDIT.md — NOT inline in the skill section, NOT in SOLUTIONS.md. Rationale: keeps current audit findings (what exists now) separate from meta-proposals about future SPEC pre-classification changes.
- **D-13:** Each reclassification proposal must include: `skill_id`, `current_direction` (from SPEC pre-classification), `proposed_direction`, `rationale` (concrete evidence why current classification is wrong), `affected_findings` (list of finding IDs that would change interpretation). Reclassification approvals happen in user-driven post-phase review, same as SOLUTIONS approvals.

### Commit Cadence

- **D-14:** Commit cadence — per-plan atomic commits with skill-section granularity within Plan-1/2/3:
  - Plan 0 → 1 commit (`docs(999.11.4-00): phase-decision index build`)
  - Plan 1 (AUTH batch) → 6 per-skill commits after parallel sub-agents return (`docs(999.11.4-01): audit {skill-abbrev} — {N} findings`) OR 1 atomic plan commit (executor decides; orchestrator preference: per-skill for `git revert` granularity). RESOLVED via D-15 below.
  - Plan 2 (DESC batch) → 2 per-skill commits
  - Plan 3 (HYBRID batch) → 3 per-skill commits
  - Plan 4 → 3 commits: SOLUTIONS.md, reclassification consolidation (if any), final phase SUMMARY.md
- **D-15:** Per-skill atomic commits preferred over per-plan atomic commits — for `git revert` granularity if a single skill's audit needs redo without invalidating sibling audits. Per-plan verify-against-reality dual-mode smoke gate (D-14 pattern from 999.11.2) **not applicable** here — audit-only phase, no runtime changes to smoke-test.

### AUDIT.md Structure Detail

- **D-16:** AUDIT.md file structure (top-to-bottom):
  1. `## Summary` table (skill | finding_count | direction_distribution | remediation_type_distribution)
  2. `## Methodology` — brief reference to SPEC pre-classification + Directional Authority Taxonomy + Heavy depth discipline
  3. `### Skill: {name}` sections — 10 sections in direction-class batch order (AUTH first, then DESC, then HYBRID). Each section: pre-classification direction, brief skill synopsis, findings list with all 4 mandatory fields populated.
  4. `## Orphan Phase-Decisions` — sanctioned D-XX not reflected in any skill (bonus from Plan 0 index)
  5. `## Reclassification Proposals` — auditor-proposed direction changes (if any)
  6. `## Skipped Skills` — `error-handling` with 1-line note per SPEC
- **D-17:** SOLUTIONS.md file structure (Phase 999.1 precedent):
  1. Per-finding entry in order of AUDIT.md findings
  2. Each entry: 1-3 ranked remediation options with `Pros`, `Cons`, `Risk`, `Effort` columns + `Recommended pick` one-liner with reasoning
  3. Grouping by skill (mirrors AUDIT.md section order)
