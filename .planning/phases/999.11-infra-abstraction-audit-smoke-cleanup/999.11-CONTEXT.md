Удалить все smoke/test endpoints из production code base. **НЕ в scope:**
- Architecture audit (отложен — появится в 999.12-14 per-resource alignment phases)

- Redis/RMQ/S3 abstractions — не трогаем
- Health endpoints / CI smoke migration (отложено — 999.15)
- Documentation updates (cautionary tale, canonical pattern docs) — отложено

Фаза максимально тонкая: delete smoke code + runtime verify. Всё связанное с архитектурой и документацией делается в следующих phases когда для этого будет естественный context.

<decisions>
## Implementation Decisions

### Delete scope

- **D-01:** **Gateway production code удаляется полностью:**
  - `apps/gateway/src/test/smoke-test.module.ts` (delete)
  - `apps/gateway/src/test/storage-smoke.controller.ts` (delete)
  - `apps/gateway/src/test/http-smoke/` (delete directory)
  - `apps/gateway/src/test/grpc-client-sanity.ts` (delete)
  - `apps/gateway/src/test/` (empty dir remove)
  - `apps/gateway/src/gateway.module.ts` — remove `SmokeTestModule` import from `imports: [...]`

- **D-02:** **Backend gRPC smoke infrastructure удаляется полностью:**
  - parser service: `RunStorageSmokeService` + `CleanupStorageSmokeService` (application/services + ports + use-cases + controller methods)
  - notifier service: аналогичный storage smoke endpoint (полный структурный аналог parser'а)
  - proto contracts: удалить RPC method definitions `RunStorageSmoke` / `CleanupStorageSmoke` из `packages/contracts/proto/parser.proto` + аналог из `notifier.proto`
  - regenerate contracts: `pnpm generate:contracts` (turbo pipeline)

- **D-03:** **Границы не расширяются к audit.** Любые obvious architectural issues обнаруженные во время delete (например dangling reference в каких-то docs) → фиксируются отдельно в 999.12-15 или в backlog note, **не расширяют scope 999.11**.

### Commit granularity

- **D-04:** **Atomic commits per feature** — 3 отдельных commit'а:
  - Commit 1: delete storage-smoke (SmokeTestModule + storage-smoke.controller.ts + gateway.module.ts import)
  - Commit 2: delete http-smoke/ directory
  - Commit 3: delete grpc-client-sanity.ts
  - Commit 4: delete backend parser storage-smoke (proto + application + infrastructure)
  - Commit 5: delete backend notifier storage-smoke
  - Commit 6: regenerate contracts + runtime verification (metadata close)

  Порядок: gateway сначала (потому что consumer), потом parser backend, потом notifier backend. Consumer-first чтобы unused backend методы удалялись после того как nothing calls them.

- **D-05:** **НЕ mega-commit "rip out all test endpoints"** — clean bisect boundaries важнее скорости.

### Verification

- **D-06:** **После каждого delete commit'а — `pnpm lint` + `pnpm build`** (quick static gate, <30s).

- **D-07:** **После финального commit'а (полный smoke cleanup completed) — full dual-mode runtime smoke gate** per `runtime-smoke-verification` skill:
  - `pnpm stop:native && pnpm stop:isolated` (clean state)
  - `pnpm build` + `pnpm lint` (fresh)
  - `pnpm start:native` + `curl http://localhost:3000/health/ready` → 200, 5/5 upstreams up
  - `pnpm stop:native`
  - `pnpm start:isolated` + `curl http://localhost:4000/health/ready` → 200, 5/5 upstreams up
  - `pnpm stop:isolated`
  - Этот gate — verification что removal не сломал DI resolution или routing в production /health/ready (который живёт в отдельном controller и не должен быть затронут)

### Claude's Discretion

- Точный порядок file deletions внутри каждого commit'а
- Подход к proto regeneration (ручной vs через turbo generate:contracts)
- Commit message wording (соблюсти convention `refactor(999.11-NN): ...`)
- Handling empty directories после delete (Git автоматически не tracks, но могут остаться `.gitkeep` stubs)

</decisions>
