**CRITICAL compile constraint — proto-generated interface:**

`parser.controller.ts` declares `implements ParserProto.ParserServiceController`. The proto-generated interface (still present in `packages/contracts/src/generated/parser.ts` — Plan 04 regenerates) REQUIRES controllers to provide `runStorageSmoke` + `cleanupStorageSmoke` method signatures. If we delete the method bodies without stub-replacing, tsc errors with TS2420 "Class ParserController incorrectly implements ParserProto.ParserServiceController".

**Resolution per RESEARCH.md Pitfall 1 (consumer-first invariant):** Keep the method signatures as minimal stubs that throw `NotImplementedException` — proto interface is satisfied structurally, runtime would throw if called (nothing calls them after Plan 01's gateway deletion). Plan 04 regenerates proto → stubs disappear along with the interface requirement. See ACTION STEP 3 for exact stub code.

Alternative considered (rejected): remove `implements` clause entirely. Rejected because `@ParserProto.ParserServiceControllerMethods()` bulk decorator (line 30) applies `@GrpcMethod` to all proto-declared methods — without the implementation signatures the controller stops answering 8 gRPC methods instead of 6. Stub pattern is cleaner.
