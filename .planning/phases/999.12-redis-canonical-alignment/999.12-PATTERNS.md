**Two integration options for gateway (planner picks; both type-compatible per RESEARCH §7 line 446 — `GrpcClientHealthIndicator` and `RedisHealthIndicator` both implement `isHealthy(key: string): Promise<HealthIndicatorResult>`):**

- **Option A (RESEARCH §7 row 5 recommendation):** widen `upstreams` element type to a structural shape (`{key: string; indicator: { isHealthy(key: string): Promise<HealthIndicatorResult> }}`) and push `{key: HEALTH.INDICATOR.REDIS, indicator: redisHealth}` into the array. Planner decides per code-quality bias (Option A preserves uniform allSettled fan-out; Option B keeps `upstreams` array semantic narrow to "upstream gRPC services").
