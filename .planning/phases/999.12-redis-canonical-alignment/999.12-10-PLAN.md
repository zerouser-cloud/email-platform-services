<objective>
Migrate gateway's `@nestjs/throttler` storage from default in-memory to Redis-backed via `@nest-lab/throttler-storage-redis@^1.2.0` (per RESEARCH §1 — verified npm registry 2026-04-27, MIT, NestJS 11 compatible, ioredis-based, maintained by Jay McDoniel who is also `@nestjs/throttler` core team). This is the **single business binding** in scope for Phase 999.12 (per CONTEXT.md D-13 — "concrete consumer" paired with structural rollout in Plans 04-09).

Per RESEARCH §2 Path A1 (recommended): share the existing Redis TCP connection (already managed by AppCacheModule's foundation `CacheModule.forRootAsync` — Plan 09 wired the wrapper into gateway.module.ts root). The throttle module imports `AppCacheModule` so `REDIS_CLIENT` is in DI scope, then injects it into the `ThrottlerModule.forRootAsync` useFactory which constructs `new ThrottlerStorageRedisService(redis)`. One TCP connection, one health check, one shutdown lifecycle.

This plan depends on:
- **Plan 02** (foundation REDIS_CLIENT exposed in DynamicModule.exports + public barrel — both edits are required per RESEARCH §S-3 and Plan 02 ships them in one atomic commit)
- **Plan 09** (gateway has AppCacheModule wired into root + outbound/cache/ exists)

The plan also closes D-16 (Phase 21 D-02 partial unlock for rate-limiting). Documentation propagation to Phase 21 CONTEXT.md is Plan 11's responsibility (cross-phase doc edit grouping); this plan only ships the code change + dependency manifest.

**Known limitation (RESEARCH §S-1):** `ThrottlerStorageRedisService` writes its own ZSET keys via raw ioredis commands; these keys do NOT receive the foundation `RedisCacheService` namespace prefix (`gateway:`). At single-gateway-cluster scale this is acceptable. Future remediation (logical-DB separation `redis://host:6379/2` or wrapper class with key-prefix injection) is **deferred** — Plan 10 only documents the limitation in SUMMARY.md, does not fix it.

**Local verification:** Per RESEARCH §10, distributed-rate-limit-with-2-replicas assertion is NOT feasible locally (single-process gateway in both `pnpm start:native` and `pnpm start:isolated`); deferred to production verification (Phase 999.15 territory). What IS feasible: single-replica burst test (11 rapid `curl` requests within 1s → 429 on the 11th). Plan 10 documents the burst test and runs it as part of D-20 validation.

Output: 1 dep added (apps/gateway/package.json + pnpm-lock.yaml regenerated) + 1 file rewritten (throttle.module.ts). 3-file atomic commit.
</objective>
