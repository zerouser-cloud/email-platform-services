# Phase 999.12 Plan 03: Env Schema Redis Composition Summary

Five service env schemas (auth, audience, parser, notifier, gateway) now compose `RedisSchema.shape` so each validates `REDIS_URL` at boot via Zod. Sender already had the spread per RESEARCH §S-7 — left untouched. No `.env*` files modified.

## What Was Done

**Single atomic commit** `39dbd03` — `refactor(999.12-03): compose RedisSchema.shape into 5 env schemas (D-15)` — covering all 5 schema files with the same conceptual change.

### Per-service insertion ordering (matches sender canonical convention)

| Service | Order chosen | Position |
|---------|--------------|----------|
| `auth/env.schema.ts` | `AuthTopology → Database → **Redis** → Logging → Grpc` | After Database, before Logging |
| `audience/env.schema.ts` | `AudienceTopology → ParserTopology → Database → Rabbit → **Redis** → Logging → Grpc` | After Rabbit, before Logging |
| `parser/env.schema.ts` | `ParserTopology → NotifierTopology → Database → Storage → **Redis** → Logging → Grpc → AppStoreSpy` | After Storage, before Logging |
| `notifier/env.schema.ts` | `NotifierTopology → Rabbit → Storage → **Redis** → Logging → Grpc → Telegram` | After Storage, before Logging |
| `gateway/env.schema.ts` | `BaseGateway: ... → CorsSchema → RateLimitSchema → **Redis**` | Last spread inside BaseGatewayEnvSchema (gateway-specific pragmatic choice — gateway groups infra blocks differently than gRPC services and the spread must be inside Base for `.refine()` to see the field) |

The gRPC-services rule of thumb — **"Redis follows the heaviest infra block (Database for stateful svcs, Storage for parser/notifier, Rabbit for audience), and precedes Logging"** — replicates the sender precedent (`packages/config/src/apps/sender/env.schema.ts` lines 17–25, RESEARCH §S-7). Gateway's exception is documented inline in the file (D-15 nuance).

### Gateway BaseGatewayEnvSchema / .refine() preservation

Gateway has a two-step shape: `BaseGatewayEnvSchema = z.object({...})` followed by `GatewayEnvSchema = BaseGatewayEnvSchema.refine(({ CORS_STRICT, CORS_ORIGINS }) => ...)`. The `.refine()` is invoked on the parsed object, so the additional shape MUST be added inside the base — adding it after `.refine()` would not work because `.refine()` returns a `ZodEffects` whose subsequent extension is non-trivial. The plan's PATTERNS §P-5 lines 633–651 prescribed the inside-Base placement; followed verbatim.

The CORS strict-vs-wildcard refinement remains operationally identical: predicate, error message, and field path are unchanged. RedisSchema.shape introduces `REDIS_URL: z.string().min(1)` — a sibling field that the refinement does not reference.
