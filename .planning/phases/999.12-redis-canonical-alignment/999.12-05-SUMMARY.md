## Decisions Made

- **Auth root module untouched.** RESEARCH §8 row 2 confirms NestJS module-graph transitive providers chain: `AppCacheModule.exports = [CacheModule]` → `HealthModule.imports = [AppCacheModule]` → root `auth.module.ts` imports `HealthModule`. `REDIS_HEALTH` is visible to `HealthController` (declared inside `HealthModule`) without a root-level explicit import. Adding it to root would be duplication.
- **Env schema untouched.** Plan 03 had already added `...RedisSchema.shape` to `AuthEnvSchema`. Re-editing here would conflict with Plan 03's contract and risk drift; verified via `git diff packages/config/src/apps/auth/env.schema.ts` empty.
- **Namespace via catalog.** `SERVICE.auth.id` (resolves at runtime to `'auth'`) used in `CacheModule.forRootAsync({ namespace: ... })`. No-magic-values skill: would have failed `grep -E "namespace: '[a-z]+'"` audit. Sender's pre-Plan-04 state still has `namespace: 'sender'` literal — Plan 04 will harmonise.
- **Slice ordering.** `CACHE_CONFIG_PORT` slice appended as third narrowPorts entry (PERSISTENCE → LOGGING → CACHE), matching `sender-config.module.ts` ordering convention. Alphabetical/role grouping not used; insertion order matches sender precedent.
