### 4 edits

1. **`apps/gateway/src/infrastructure/bootstrap/config/gateway-config.module.ts`** — added `CACHE_CONFIG_PORT` + `type CacheConfig` to the foundation import block; inserted `{ port: CACHE_CONFIG_PORT, slice: (c): CacheConfig => ({ REDIS_URL: c.REDIS_URL }) }` as the 2nd entry in `narrowPorts[]` (after LOGGING, before GRPC_CLIENT — sender canonical ordering per RESEARCH §13). Closes the trust boundary: foundation `CacheModule` factory consumes `CACHE_CONFIG_PORT` at boot via `inject:[CACHE_CONFIG_PORT]` per `cache.providers.ts`.

2. **`apps/gateway/src/infrastructure/bootstrap/health/health.module.ts`** — imported `AppCacheModule` from `../../outbound/cache` and appended it to the imports array alongside the existing `TerminusModule` + `GrpcClientsModule`. JSDoc updated to cite Phase 999.12 D-05 (cross-ring D-05 wiring). PersistenceModule deliberately NOT added (RESEARCH §7 row 5 — gateway is a REST facade with no DB).

3. **`apps/gateway/src/infrastructure/bootstrap/health/health.controller.ts`** — Option B implementation:
   - Added `REDIS_HEALTH` to the value-import from `@email-platform/foundation` and `CacheHealthIndicator` to the type-only import.
   - Appended `@Inject(REDIS_HEALTH) private readonly redis: CacheHealthIndicator` as the LAST constructor argument (after `notifierHealth`). The `upstreams[]` array TYPE remained `ReadonlyArray<{ key: string; indicator: GrpcClientHealthIndicator }>` — no widening, no 6th push.
   - In `readiness()`: after the existing `Promise.allSettled(...)` fan-out and its post-processing into the first `this.health.check([...])` call (`upstreamsResult`), added a second sequential `redisResult = await this.health.check([() => this.redis.isHealthy(HEALTH.INDICATOR.REDIS)])`. Merged via spread on `info` + `details` so the response shape is identical to a single uniform `health.check([...])` call (`info.redis` slot populated alongside the 5 upstreams).
   - JSDoc on `readiness()` documents Option B locking and the rationale for rejecting Option A.

4. **`apps/gateway/src/gateway.module.ts`** — imported `AppCacheModule` from `./infrastructure/outbound/cache` and inserted it into the `imports[]` array between `HealthModule` and `ThrottleModule`. Inline comment block (5 lines) documents the load-bearing ordering rule (NestJS resolves modules in declaration order; foundation modules are NOT `@Global()` per PATTERNS §S-G; Plan 10's ThrottleModule.forRootAsync uses `inject:[..., REDIS_CLIENT]`, which AppCacheModule provides transitively).
