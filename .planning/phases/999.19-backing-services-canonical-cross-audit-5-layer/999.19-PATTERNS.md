## Anti-patterns to avoid in PATTERNS.md consumers

The following missteps were observed in 999.1 work or pre-emptively flagged in 999.19 RESEARCH.md §6 — executors of plans 01-04 must avoid them.

| Anti-pattern | Why wrong | Correct approach |
|--------------|-----------|------------------|
| Re-discussing methodology in DESIGN/AUDIT/SOLUTIONS | D-01..D-19 are carry-forward, NOT decision points (CONTEXT.md `<decisions>` Carry-forward block) | Cite the D-NN by ID; do NOT re-derive |
| Treating L5 invariants as locked | RMQ has NO canonical reference (RESEARCH §6) | DESIGN MUST mark all I-5.N as `proposed`; AUDIT MUST NOT cite "violation of I-5.X" as if locked |
| Pre-absorbing 999.13 / 999.14 backlog | Phase independence (CONTEXT.md `<deferred>` + D-15 carry-forward) | Use Backlog Impact promotion-flag, NOT pre-absorption — only user `/gsd:review-backlog` mutates ROADMAP |
| Counting `dist/` artifacts in evidence | Inflates counts 200% (RESEARCH §6) | Always `-not -path '*/dist/*'` filter in grep evidence |
| Trying to lock L5 implementation choices | That is 999.13's job | DESIGN.md describes shape from skeleton; does NOT pick amqplib / amqp-connection-manager / @golevelup |
| Mixing audit findings with code-change tasks | AUDIT phase is docs-only | Code happens in 999.19.1..N AFTER user approves SOLUTIONS.md |
| Using `---` outside frontmatter fences | Memory anchor `reference_gsd_sdk_extractfrontmatter_bug` — body `---` HRs corrupt SDK wave/autonomous parsing | Use `<hr />` for HRs in plan bodies; `---` only between frontmatter `---` … `---` open/close |
| Using ASCII brackets `[ ] / [x]` for approval marks | D-08 specifies Unicode glyphs `☐ / ☑ / ☒` | Use Unicode glyphs verbatim |
| Editor auto-stripping pipe-escapes in trade-off tables | Markdown table cells silently truncate at unescaped `\|` | Always escape pipes `\|` inside cell content (regex, type unions) |
