- **D-A1: L0 master invariant — Strict 3-zone + narrow-unlock formalized.**

  > Контракты исключительно в `packages/contracts/` (proto-generated types, no business types, no DI tokens). Механизмы абстракции в `packages/foundation/src/external/<layer>/` (factory, abstract base, proxy, builder, port-interface, HealthIndicator shape, ShutdownService shape — domain-agnostic shapes без знания о конкретных бизнес-сценариях). Любой Tier 2 raw lib instance (`pg.Pool`, `ioredis Redis`, `S3Client`, `ClientGrpc`) экспортируемый из foundation MUST иметь documented narrow-unlock комментарий symmetric к Phase 999.12 D-13 (REDIS_CLIENT для gateway throttle storage). ### F-A/F-B seed-finding treatment (Area 4)

- **D-A4: Hybrid pre-staged + fresh.**

  Audit регистрирует F-A (CacheService.get<T>() quality) и F-B (PG_POOL Tier 2 leak) как F-01 и F-02 в AUDIT.md с inline evidence (равноправно с другими findings). В SOLUTIONS.md per finding 3 variants pre-staged из previous session gray areas + 1 fresh slot если research surface'ит non-obvious option.

  **F-01 (CacheService.get<T>()) pre-staged variant axes** (3 ортогональные оси):

  - **Return-shape axis (3 значения):**
    1. Discriminated union — `get<T>(key, schema?: ZodType<T>): Promise<{status: 'absent' | 'corrupt' | 'value', value?: T}>`. Caller обязан различать.
    2. Throw `CacheParseError` — `get<T>(key, schema?: ZodType<T>): Promise<T | null>` (null=absent), throw на corrupt. Caller через try/catch.
    3. Result type — `get<T>(key, schema?: ZodType<T>): Promise<Result<T | null, CacheParseError>>`. Общий с другими foundation utilities.

  - **Schema-placement axis (3 значения):**
    1. Optional param на текущем методе — `get<T>(key, schema?)`.
    2. Separate method — `getValidated<T>(key, schema)` рядом с `get<T>(key)`.
    3. Caller-side validation вне CachePort.

  - **Corruption side-effect axis (3 значения):**
    1. Log error + treat as cache-miss (старая запись доживёт до TTL).
    2. Log error + `del(key)` self-healing (следующий get идёт в источник).
    3. Severity-aware: log warn на schema-mismatch, log error на JSON.parse, `del(key)` в обоих случаях.

  Cartesian этих 3 axes даёт 3×3×3 = 27 combinations. SOLUTIONS author selects 3-4 наиболее релевантные комбинации в trade-off table, остальные документируются inline («не выбраны по причине X») для audit-trail. Recommended комбинация по принципам user'ской framing — discriminated union + optional param + severity-aware del — но это не lock, SOLUTIONS author может recommend другую.

  **F-02 (PG_POOL leak) pre-staged variants (3):**

  1. **ESLint Override 4-style guard** — добавить ESLint rule блокирующий `@Inject(PG_POOL)` и `from 'pg'` в `apps/*/src/**` symmetric к D-08 (ioredis ban). Surface enforcement.
  2. **Kept private + comment** — убрать `PG_POOL` из foundation `index.ts` exports + `PersistenceModule.exports[]`, оставить как private symbol. Добавить комментарий «PG_POOL kept private — no narrow-unlock approved» symmetric к 999.12 D-13. Convention enforcement (минимальные 2-3 строки правок).
  3. **Tier 1 abstraction wrapper** — заменить `PG_POOL` exposure на Tier 1 abstraction (`QueryRunner` port в foundation), скрыть `pg.Pool` полностью. Architectural refactor — крупнее, но complete L0 alignment.

  **F-01/F-02 severity** — Audit может re-classify (currently F-A/F-B без severity). Ожидание: F-02 PG_POOL leak = blocker (прямой violation L0); F-01 CacheService.get<T>() quality = major (drift от Tier 1 abstraction discipline, не runtime bug).
