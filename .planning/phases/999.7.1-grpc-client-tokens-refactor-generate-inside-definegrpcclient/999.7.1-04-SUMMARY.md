## Decisions Made

- **Atomic per-upstream commits (3 SHAs, one per upstream).** Each SHA touches exactly one of the 3 cross-service upstream directories — no cross-upstream batching. Rationale: per-upstream rollback granularity, easy bisect, mitigates Pitfall 2 (intermediate state would be TS-broken if constants file deleted before client.ts strips its import). Mirrors Plan 03's discipline exactly.
- **Type-only ClientGrpc import** (`import type { ClientGrpc } from '@nestjs/microservices'`). After @Inject removal, ClientGrpc is used only as a type annotation — type-only import is the correct disposition (Pitfall 7).
- **Build verification per-upstream (not deferred to end).** Unlike Plan 03 (where all 5 upstreams live inside one gateway app, so per-upstream builds would be redundant noise from N-1 unrefactored siblings), Plan 04 upstreams live in 3 *different* consumer apps. Each app has exactly one upstream being refactored, so per-app builds are localized and high-signal: build-after-commit confirms each upstream end-to-end immediately. All 3 builds (sender, parser, audience) ran successfully cache-miss after their respective commits, then a final combined build returned FULL TURBO confirming all stay green.
- **Comment block preserved on named re-exports.** Each module file carries the explanatory comment `// Do NOT export 'grpc' directly — that leaks imports/providers/exports and lets consumers bypass forRoot()` (Anti-Pattern 4 from infrastructure-client-layering skill).
- **Root modules invariant proactively verified.** `git diff HEAD~3 HEAD -- apps/{sender,parser,audience}/src/{sender,parser,audience}.module.ts` empty — addresses RESEARCH.md Open Question #3. Class export names ({Audience,Notifier,Parser}ClientModule) preserved by design across the refactor.
