## Decisions Made

- **TOKEN_SUFFIX as-const object instead of inline string concat in derivation:** Keeps no-magic-values compliance for the suffix segments (`'_CLIENT_GRPC'`, `'_GRPC_HEALTH'`) and provides a single edit point if naming convention ever changes. Object form chosen over two flat consts because the two suffixes form a semantic group ("derived gRPC token suffix kinds").
- **Inline derivation, no helper extraction:** Per PATTERNS.md guidance and RESEARCH.md "Discretion Recommendations" — minimal change set; introducing a `deriveGrpcTokens(serviceId)` helper would add an extraction layer for two trivial template-literal expressions. Plan 05's filename guard prevents `*-client.constants.ts` regression at the apps layer; foundation-level helper guards are out of scope for this phase.
- **`exports: [opts.clientToken, healthToken]` (not `[opts.clientToken, healthToken, grpcToken]`):** Preserved current behavior. The public DI surface is the typed facade + the health indicator. `grpcToken` is the internal `ClientGrpc` channel token — consumers should never inject it directly (they get the typed facade via `clientToken`); leaving it out of the module's `exports` array keeps the encapsulation boundary intact.
- **Build-failure delegation to Plans 03/04:** Did NOT attempt to fix the 8 downstream module files in this plan — that's wave-ordered work explicitly assigned to Plans 03/04. Foundation builds green in isolation; full-workspace red is the intentional intermediate state.
