## Decisions Made

See frontmatter `key-decisions`. Most notable:

1. **D-AUDIENCE-01** — Sub-modules own their foundation `PersistenceModule.forRootAsync()` imports (HealthModule for `DATABASE_HEALTH`, RecipientModule for `DRIZZLE`, GroupModule for `DRIZZLE`) instead of the root composition root. This replicates Plan 01's D-AUTH-01 but validates the pattern across TWO aggregates simultaneously — proves the DI story scales with aggregate count. Plan 10 dual-mode smoke (future plan in this phase) will catch any duplicate-pool regression.

2. **OQ-3 cross-aggregate schema import deferred** — The plan anticipated `pg-group.repository.ts` importing schema from `../recipient/schema/...` (cross-aggregate usage documented in RESEARCH §Composer Edge Cases, Pitfall 8). Inspection during execution revealed `pg-group.repository.ts` has NO schema import whatsoever — it's a pure stub repository with all four methods throwing `'not yet implemented'`. The cross-aggregate concern is forward-looking only: when the business-logic phase implements real group persistence, the decision between (a) dedicated `outbound/persistence/group/schema/` or (b) cross-aggregate import from `../recipient/schema/...` must be made based on whether groups have distinct columns from the recipients table.

3. **App-level composer naming** — `AppPersistenceModule` chosen over `PersistenceModule` (identical to Plan 01's decision) to avoid name collision with foundation's module inside `audience.module.ts` imports. Propagates to Plans 03-06.

4. **@Global() config module preservation with 4 slice tokens** — Audience's `AudienceConfigModule` exports `AUDIENCE_CONFIG` + 3 narrow slices (`PERSISTENCE_CONFIG_PORT`, `LOGGING_CONFIG_PORT`, `GRPC_CLIENT_CONFIG_PORT`) — one more than auth (which has no gRPC clients). The `GRPC_CLIENT_CONFIG_PORT` narrow slice is consumed inside `defineGrpcClient` → `ClientsModule.registerAsync` call chain within `ParserClientModule.forRoot()`.

5. **Single-sub composer justification recorded** — `GrpcClientsModule` is one-liner (wraps only `ParserClientModule.forRoot()`), yet the composer layer is kept per D-06 verbatim. Rationale: Plans 03-06 add additional clients (sender has audience+parser, parser has audience, gateway has all 5) by editing the composer's imports/exports arrays without restructuring the root.
