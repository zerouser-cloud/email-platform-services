## Decisions Made

See frontmatter `key-decisions`. Most notable:

1. **D-AUTH-01** — Sub-modules own their foundation `PersistenceModule.forRootAsync()` imports (`HealthModule` for `DATABASE_HEALTH`, `UserModule` for `DRIZZLE`) instead of the root composition root. This preserves NestJS DI correctness because foundation's `PersistenceModule` is NOT `@Global()` and sibling module exports do NOT propagate across the composition root without explicit re-import. Plan 10 dual-mode smoke (future plan in this phase) will catch any duplicate-pool regression.

2. **App-level composer naming** — `AppPersistenceModule` chosen over `PersistenceModule` to avoid name collision with foundation's module inside `auth.module.ts` imports. Naming propagates to Plans 02-06.

3. **@Global() config module preservation** — The Rule 3 fix from Phase 999.11.1 Plan 10 (making `AuthConfigModule` `@Global()` so nested `forRootAsync({inject: [CONFIG_PORT]})` calls inside foundation can resolve the token) is preserved: `@Global()` decorator moves with the class into the new `auth-config.module.ts` sibling file.
