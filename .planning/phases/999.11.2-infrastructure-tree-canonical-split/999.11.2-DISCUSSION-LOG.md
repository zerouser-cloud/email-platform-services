## Area 1: Composer modules pattern

**Question:** В outbound/grpc-clients/ оставляем composer (grpc-clients.module.ts импортирует 5 client sub-modules) или растворяем? Тот же pattern применится к outbound/persistence/ и outbound/http-clients/ в будущем.

| Option | Description | Selected |
|--------|-------------|----------|
| Keep composer везде (Recommended) | Root {svc}.module.ts импортирует один GrpcClientsModule/PersistenceModule/HttpClientsModule — каждый с внутренними sub-modules per feature | ✓ |
| Dissolve composers | Root импортирует каждый sub-module напрямую (5 grpc + N persistence + M http). Flat, но root больше | |
| Hybrid — composer только для multi-file | Composer появляется только при ≥2 sub-modules в категории | |

**User's choice:** Keep composer везде (Recommended).

**Locked decision:** **D-06** — GrpcClientsModule / PersistenceModule / HttpClientsModule composers at category level, каждый импортирует per-feature sub-modules. Root `{svc}.module.ts` импортирует composers, не individual sub-modules.

**Notes:** Consistent с foundation.PersistenceModule convention; scalable (6-й upstream — add sub-module, root не трогаем).

## Area 2: Cross-folder DI tokens placement

### Sub-question 2.1: gRPC client tokens location

**Question:** gRPC client tokens (AUTH_SERVICE, SENDER_SERVICE, PARSER_SERVICE, AUDIENCE_SERVICE, NOTIFIER_SERVICE) сейчас в root {svc}.constants.ts. Research v2 hint 'tokens live near consumers'. Куда переносим?

| Option | Description | Selected |
|--------|-------------|----------|
| В outbound/grpc-clients/clients.constants.ts (Recommended) | Tokens рядом со своим composer и client sub-modules. Feature-local cohesion. Root {svc}.constants.ts остаётся только с {SVC}_CONFIG (или удаляется per D-11) | ✓ |
| Per-sub-module: outbound/grpc-clients/auth/auth-client.constants.ts | Каждый client sub-module держит свой token. Maximum co-location, но 5 files × 1-2 lines — fragmentation | |
| Оставить в root {svc}.constants.ts | Все cross-folder tokens в одном месте | |

**User's choice:** В outbound/grpc-clients/clients.constants.ts (Recommended).

**Locked decision:** **D-09** — grpc client tokens переезжают в `outbound/grpc-clients/clients.constants.ts`.

### Sub-question 2.2: {SVC}_CONFIG token placement

**Question:** {SVC}_CONFIG token и {Svc}ConfigModule — где живут? {SVC}_CONFIG cross-folder (inject'ится в bootstrap provider factory + outbound slice factories). {Svc}ConfigModule есть @Global() wrapper per 999.11.1 Rule 3 fix.

| Option | Description | Selected |
|--------|-------------|----------|
| Переехать в bootstrap/config/ (Recommended) | {SVC}_CONFIG в bootstrap/config/{svc}-config.constants.ts + {Svc}ConfigModule в bootstrap/config/{svc}-config.module.ts. Bootstrap владеет полной identity конфига: schema + provider + token + module | ✓ |
| Оставить в root {svc}.constants.ts | {SVC}_CONFIG в root, {Svc}ConfigModule в bootstrap/config/. Asymmetry но root остаётся каноническим | |

**User's choice:** Переехать в bootstrap/config/ (Recommended).

**Locked decisions:**
- **D-10** — `{SVC}_CONFIG` + `{Svc}ConfigModule` + env schema + config provider — все в `bootstrap/config/`
- **D-11** — Root `{svc}.constants.ts` удаляется если становится пустым после D-09 + D-10

## Area 3: Barrel files per feature

**Question:** index.ts barrel файлы — где создаём? Это определит import ergonomics: `import { GrpcClientsModule } from './outbound/grpc-clients'` vs `'./outbound/grpc-clients/grpc-clients.module'`.

| Option | Description | Selected |
|--------|-------------|----------|
| Всюду где есть ≥ 2 exports (Recommended) | Feature folders + composer level + direction level если root импортирует 2+ items. Consistent с packages/foundation convention | ✓ |
| Только feature-level barrels | index.ts только в leaf feature folders. Composer и direction — без barrel. Меньше файлов, но длиннее paths | |
| Barrel только на composer level | Composer-level index.ts, но не на leaf folders | |

**User's choice:** Всюду где есть ≥ 2 exports (Recommended).

**Locked decision:** **D-12** — `index.ts` barrel везде где ≥2 exports. Feature folders, composer level, direction level если нужно.

| Option | Description | Selected |
|--------|-------------|----------|

- **D-08** — Создать HealthModule во всех 6 сервисах
