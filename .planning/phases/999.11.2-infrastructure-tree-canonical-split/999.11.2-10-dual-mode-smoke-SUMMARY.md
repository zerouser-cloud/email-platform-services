**One-liner:** D-14 dual-mode runtime smoke gate caught a NestJS DI scope regression (ports in root not visible to submodule controllers), diagnosed architecturally, fixed via Option A inbound-adapter-owned DI scope across 5 services, gate re-run both modes green first try, `nyquist_compliant: true` flipped, phase aggregate recorded.

## Plan 10 Execution Narrative

Plan 10 was originally drafted as a single evidence-only commit (`test(999.11.2-10): D-14 dual-mode smoke gate evidence + phase SUMMARY`) — no code changes expected. The first executor run started the smoke, gateway returned HTTP 503, and the service startup logs surfaced 5 `Cannot resolve dependencies of ...Controller` / `...UseCase` errors (one per service):

```
auth     → AuthController can't resolve LOGIN_PORT (+ 5 sibling ports)  at index [0]
sender   → SenderController can't resolve LIST_CAMPAIGNS_PORT (+ 9)     at index [0]
parser   → ParserController can't resolve CREATE_TASK_PORT (+ 4)        at index [0]
audience → AudienceController can't resolve LIST_GROUPS_PORT (+ 7)      at index [0]
notifier → HandleEventUseCase can't resolve NOTIFICATION_SENDER_PORT    at index [0]
```

Root cause (diagnosed in checkpoint return): Plans 01–05 introduced `GrpcModule` / `RmqModule` submodules that declared `controllers: [...]` but left the port → service bindings in the root `{Svc}Module.providers[]`. Without `@Global()` on the root module or explicit `exports: [...PORT_SYMBOL...]` from the root, NestJS's module scope isolation prevented the submodule-hosted controllers from seeing the root providers. Static build and lint passed clean (TypeScript only sees decorator metadata); only NestJS's `NestFactory.createMicroservice()` at startup resolves the DI graph and catches it — which is exactly why runtime-smoke-verification skill ANTI-PATTERN 5 exists and why D-14 is mandatory.

User selected **Option A** (relocate bindings into the inbound adapter module) per hexagonal D-02 cohesion — the inbound adapter module owns the port surface it drives. Execution resumed with a three-commit sequence:
